# Lowering the DOM to Document Structs Implementation Plan

## Overview

Build the second arrow of the parser pipeline: generic DOM tree in
(`Statifier.Parser.DOM.Element`), typed `%Statifier.Document{}` tree out. One
builder function per element, reached through a dispatch map, so that adding an
element touches one builder rather than the (child element x parent element)
clause matrix that made v1's `state_stack.ex` 903 lines and 73 clauses long.

Beads issue: `st-l5k.4`. Source research:
`docs/research/260807-st-l5k.4-lowers-dom-to-document.md`.

Both input layers are landed and complete. The work that is genuinely undecided
is not "how do I read an attribute" - it is where the module may live given two
guard tests that rule out both obvious namespaces, and what mechanism reports
several unsupported elements from one pass when no error accumulation exists
anywhere in `lib/`. This plan settles those and the research doc's five other
open questions, then sequences the build into six phases that each end on a
green gate.

## Current State Analysis

### What exists

- **The DOM** (`lib/statifier/parser/dom.ex` plus `dom/element.ex`,
  `dom/attribute.ex`, `dom/text.ex`) is landed, unvalidated and namespace-dumb.
  It offers exactly three accessors - `DOM.elements/1`, `DOM.attribute/2`,
  `DOM.text/1` - and gives every node a six-field
  `Statifier.Parser.Location`. Attributes carry two spans: `location`
  (`name="value"`) and `value_location` (inside the quotes), both nilable.
  Attribute duplicates are preserved and `DOM.attribute/2` returns the first.
- **The Document layer** (`lib/statifier/document.ex` plus eight structs under
  `lib/statifier/document/`) is landed and data-only: `@enforce_keys`,
  `defstruct`, `@type t`, no functions. Every struct enforces `:location`.
  `Transition.event`/`target` are already-split `[String.t()]`;
  `Transition.type` defaults to `:external`, `Document.binding` to `:early`,
  `State.history_type` is `:shallow | :deep | nil`.
- **`attribute_locations`** (`lib/statifier/document.ex:22-44`) is the contract
  most likely to be got wrong: a `%{atom() => Location.t()}` holding **value
  spans only**, with an entry **only for an attribute the author actually
  wrote**. It is what keeps "the default applied" distinguishable from "the
  author wrote the default's value" after lowering applies `:external` /
  `:early` / `:shallow`.
- **`Statifier.Parser.ParseError`** (`lib/statifier/parser/parse_error.ex`) is
  the only error type in `lib/`. It is single-error, a `defexception`, and
  carries a pattern-matchable `reason`, a rendered `message`, and a nilable
  `Location`.

### What is missing

- No lowering module of any kind. `Statifier.Lowering` does not exist; the only
  mentions of the word in the repo are prose in `docs/architecture.md:45` and
  two Document moduledocs.
- **No error accumulation machinery anywhere in `lib/`.** The bead's criterion
  "multiple unsupported elements reported in one pass" cannot be inherited; it
  has to be designed here.
- No namespace resolution. Four SCION corpus documents
  (`test/scion_tests/atom3_basic_tests/m0..m3_test.exs`) write every element as
  `<ns0:state>` with `xmlns:ns0` bound to the SCXML namespace, and reach the
  DOM as the literal names `"ns0:state"`.

### Constraints discovered

- **Two guard tests rule out both obvious namespaces.**
  `test/statifier/parser/generic_handler_test.exs:55` fails if any file matching
  `lib/statifier/parser/**/*.ex` contains a string literal equal to any of 26
  SCXML element names - a per-element dispatch map is nothing but those
  literals. `test/statifier/document/layer_test.exs:76` fails if any file
  matching `lib/statifier/document/*.ex` is not a struct module enforcing
  `:location`. Amending either would be a gate-weakening decision and therefore
  a human's call under ADR-0011; this plan does not assume it.
- **Lowering must not reject malformed shapes.** `docs/architecture.md:33-36`
  principle 4 and `lib/statifier/document/state.ex:43-62` assign all eight
  semantic checks to st-l5k.5. Lowering builds what is written and errors only
  when the Document type has **no slot** to put a thing in.
- **Locations can only be retained, never recovered** (ADR-0012 item 3,
  `docs/observability.md` Constraint 3). ADR-0014 is why
  `attribute_locations` stores the *value* span specifically:
  `value_location.start_offset + span.start` is the arithmetic that turns a
  within-expression span into a document position.
- **`Predicator` may not be referenced** from the Document layer (ADR-0004,
  `docs/datamodel.md`); lowering stores `cond` / `expr` as raw source strings.
- Coverage floor is 90% over `lib/` only (`docs/testing.md`), and
  `test/passing_tests.json` globs `test/statifier/**/*_test.exs`, so every new
  unit test joins the regression ratchet the moment it is written.

## Desired End State

`Statifier.Lowering.lower/1` takes a `%Statifier.Parser.DOM.Element{}` and
returns `{:ok, %Statifier.Document{}}` or `{:error, [%Statifier.Lowering.Error{}]}`
with every error carrying a reason naming the offending element and a
`Location`, sorted in document order.

Verification that the end state holds:

- `mix quality` green, including the 90% coverage floor.
- A guard test asserting that no SCXML element name appears more than once as a
  string literal anywhere under `lib/statifier/lowering/` - the mechanical
  defense of "one builder per element, no clause matrix".
- A guard test asserting that the 26 known SCXML element names partition
  cleanly into "in the dispatch map" and "produces an unsupported error", with
  no name in neither and none in both.
- A per-element happy-path fixture and a per-element unsupported fixture.
- An order-preservation test and a `Location.slice/2` property sweep proving
  copied spans still point at the element they came from.

### Key Discoveries:

- `lib/statifier/parser/dom.ex:29-55` - the three accessors are the whole read
  surface. `DOM.elements/1` filters text out; the stray-text rule therefore
  needs the **unfiltered** `children` list, checking each `%Text{}` for
  `String.trim/1 == ""`.
- `lib/statifier/document.ex:22-44` - the "written, not defaulted" rule for
  `attribute_locations`.
- `lib/statifier/document/raise.ex:7-13` - `<raise>`'s `event` is deliberately
  **not** whitespace-split, unlike `<transition>`'s.
- `lib/statifier/document/content.ex:12-15` - lowering is expected to error on
  an element child inside `<content>`, not drop it.
- `lib/statifier/document/initial.ex` - `<initial>` is a slot
  (`State.initial_element`), never a `kind`; its `transitions` is a list so the
  zero and two-or-more cases survive to be reported by st-l5k.5.
- `test/statifier/parser/generic_handler_test.exs:8-63` and
  `test/statifier/document/layer_test.exs:74-110` - the two namespace guards,
  and the template for writing this bead's own guards.
- `test/statifier/parser/location_accuracy_test.exs:13-37` - the
  `Location.slice/2` property-assertion style this plan reuses.

## What We're NOT Doing

- **No semantic validation.** All eight st-l5k.5 checks stay out: conflicting
  `initial` forms, `donedata` on a non-final, state children under a `:final`,
  a `:history` child of a `:final`, target resolution, unique ids. A state with
  both an `initial` attribute and an `<initial>` element is built as written.
- **No Phase 3 elements.** `datamodel`, `data`, `assign`, `script`, `send`,
  `cancel`, `invoke`, `if`, `elseif`, `else`, `foreach`, `param` are rejected,
  not partially built. This includes `<param>` inside `<donedata>`, whose
  parent element *is* Phase 1.
- **No expression compilation, interning, indexing, or `document_order`.**
  Those are st-wju.1's (ADR-0005). `cond` and `expr` stay raw strings.
- **No second-level dot split** of a transition's event descriptors -
  st-wju.1's job at match time
  (`lib/statifier/document/transition.ex:14-18`).
- **No `Statifier.parse/1` wiring.** The public entry point that chains parse ->
  lower -> validate is st-wju.7. This bead ships `Statifier.Lowering.lower/1`
  only, and `test/support/case.ex` still flunks.
- **No amendment of any existing guard test**, `.quality.exs`, `.credo.exs`, or
  `coveralls.json` (ADR-0011).
- **No `<content>` markup subtree.** Element children inside `<content>` are an
  error, not a preserved subtree - the l5k.2 plan's Residual Note 2.

## Implementation Approach

### Decision 1: the module lives at `lib/statifier/lowering/`, namespace `Statifier.Lowering`

Both obvious homes are ruled out by existing guard tests pointing in opposite
directions (see Constraints above). A third namespace needs no guard amendment,
which keeps this bead clear of ADR-0011 entirely.

Layout:

| Path | Module | Role |
|---|---|---|
| `lib/statifier/lowering.ex` | `Statifier.Lowering` | public `lower/1`, the dispatch map, the walk |
| `lib/statifier/lowering/error.ex` | `Statifier.Lowering.Error` | the error struct and its constructors |
| `lib/statifier/lowering/builders.ex` | `Statifier.Lowering.Builders` | one `build_*` function per element |
| `lib/statifier/lowering/attributes.ex` | `Statifier.Lowering.Attributes` | attribute reading, tokenization, defaults, `attribute_locations` |
| `lib/statifier/lowering/namespace.ex` | `Statifier.Lowering.Namespace` | prefix scope resolution (Phase 5) |

*Assumption*: the name `Statifier.Lowering` is not fixed by any doc; the
architecture diagram calls the stage "Lowering" and nothing else claims the
namespace. *Alternative considered*: `Statifier.Parser.Lowering`, rejected
because it falls inside the `lib/statifier/parser/**` guard's wildcard.

### Decision 2: errors accumulate through the walk; builders return `{result, errors}`

Every builder has the shape

```elixir
@spec build_state(element :: Element.t(), ctx :: Context.t()) ::
        {{slot :: atom(), struct()} | nil, [Error.t()]}
```

- Children are lowered first; each child's error list is appended to the
  parent's in document order.
- A builder that fails on its own account still returns the best partial struct
  it can (or `nil` when it cannot build one), so the walk continues and later
  errors are still found. The **partial tree is never returned** - `lower/1`
  returns `{:ok, doc}` only when the accumulated list is empty.
- `lower/1` sorts the accumulated list by `location.start_offset` before
  returning, so a report reads in document order regardless of the order a
  parent emits its own error relative to its children's.

*Why not the alternative* (fail-fast build plus a separate collecting sweep for
unsupported elements): it walks the tree twice, needs the sweep to re-derive
which elements are legal where - the exact per-parent knowledge the builders
already hold - and only accumulates *unsupported-element* errors, leaving stray
text and misplaced elements single-error. One traversal with one accumulator
handles all three uniformly.

*Assumption*: `{:error, [Error.t()]}` (a list, not a single struct) is the right
public shape. It is also what st-l5k.5's "all errors collected in one pass" will
want, so the two layers can share the shape later.

### Decision 3: children are placed by tag, not by parent-plus-name

Each builder returns its result tagged with the slot it belongs in -
`{:state, %State{}}`, `{:transition, %Transition{}}`, `{:onentry, %Block{}}`,
`{:onexit, %Block{}}`, `{:initial, %Initial{}}`, `{:donedata, %Donedata{}}`,
`{:content, %Content{}}`, `{:content_node, %Raise{} | %Log{}}`. Each container
builder has a private `place/2` with one clause per slot **it** owns and a
catch-all producing `{:misplaced_element, name, parent_name}`.

This is what keeps the dispatch context-free: `build_transition/2` does not know
or care whether its parent is a `<state>`, a `<history>`, or an `<initial>`. The
matrix v1 grew came from builders that had to know their parent; here the parent
knows its own slots, which is knowledge the Document type already encodes.

A `place/2` catch-all firing is not a semantic judgement - it is the statement
that the Document type has no field to hold the thing. `<transition>` under
`<scxml>` and `<state>` under `<log>` are both that.

### Decision 4: unsupported means "not a key in the dispatch map"

There is no rejection list driving dispatch. The map's keys are exactly the
supported elements; every other name misses and produces
`{:unsupported_element, name}` with the element's own `location`. `<param>`
inside `<donedata>`, `<script>` inside `<state>`, `<datamodel>` inside
`<scxml>`, and a typo'd `<stat>` all take the same path.

A module attribute `@phase_3_elements` lists the twelve deferred names and is
used **only to word the message** ("not supported until Phase 3" versus "unknown
element"). The `reason` term is `{:unsupported_element, name}` in both cases so
consumers have one shape to match.

*Alternative considered*: distinct `{:unknown_element, name}` and
`{:unsupported_element, name}` reasons. Rejected because the distinction is
advisory - a caller does the same thing with both - and two reasons invite a
consumer to handle only one.

### Decision 5: `<content expr="...">` is in Phase 1 scope

Accepted, not deferred. Three reasons: `Statifier.Document.Content` already
holds `expr` and the field would otherwise be dead; the spec's mutual exclusion
between `expr` and child content is explicitly a validator concern
(`lib/statifier/document/content.ex:26-31`), so accepting costs lowering
nothing; and two corpus donedata cases use it
(`test/scxml_tests/mandatory/content/test527_test.exs:30`, `test528_test.exs:31`).

`expr` is stored raw and uncompiled with its value span at
`attribute_locations[:expr]`. Accepting the attribute is not the same as
supporting donedata *evaluation* - the harness `FeatureDetector` still flunks
those corpus tests until the interpreter lands, so no test can go falsely green
off this decision.

### Decision 6: empty-string attribute values are distinguished from absent ones

`label=""` lowers to `label: ""` with `:label` present in
`attribute_locations`. Only an **absent** attribute becomes `nil` (or `[]` for a
tokenized one). The bead's "never empty-string sentinels" governs the absent
case, which is the one v1 got wrong by collapsing both to `nil`
(`../statifier/lib/statifier/parser/scxml/element_builder.ex:515-520`), and
`Statifier.Document.Log`'s moduledoc argues the two are different facts.

For tokenized attributes the *value* cannot distinguish them - `target=""`
splits to `[]`, same as absent - but `attribute_locations[:target]` still does,
which is exactly what that map exists for.

### Decision 7: duplicate attributes pass through untouched

Lowering reads through `DOM.attribute/2` (first wins) and reports nothing. The
DOM preserves duplicates deliberately "so the validator gets to report" them
(`lib/statifier/parser/dom/element.ex:12-14`); noticing them here would put a
semantic check one layer too low. `attribute_locations` stores the **first**
occurrence's value span, consistent with `DOM.attribute/2`.

*Recorded for st-l5k.5*: no listed check names duplicate attributes today. See
Residual Notes.

### Decision 8: namespace prefixes are resolved, leniently

Dispatch is on the **local** name, after resolving the element's prefix against
the `xmlns` / `xmlns:*` declarations in scope. An element resolving to the SCXML
namespace (`http://www.w3.org/2005/07/scxml`) **or to no namespace at all**
dispatches; anything else is `{:foreign_element, qualified_name, uri}` with a
location.

The lenient nil case matters for two reasons: heredoc unit-test fixtures should
not have to declare `xmlns` on every root, and a document that declares nothing
is far more likely to be a mistake the validator should name than something
lowering should refuse to read. All 278 corpus documents with an unprefixed
`<scxml>` declare `xmlns=`, and the four prefixed ones declare `xmlns:ns0`, so
the lenient branch is fixture-only in practice.

*Assumption*: erroring on a foreign-namespace element is preferable to ignoring
it. Spec 3.2 permits an implementation to ignore foreign-namespace children;
this bead's governing rule is "never silence", and a loud error is reversible
where a silent drop is not. *Alternative considered*: defer the whole question
and let `<ns0:state>` fall out as `{:unsupported_element, "ns0:state"}`. That
was rejected because four SCION corpus documents
(`test/scion_tests/atom3_basic_tests/m0..m3_test.exs`) are legal SCXML that
would then be permanently unloadable, and because l5k.3's bead text hands
foreign-namespace handling to "lowering time, not here" explicitly.

`Document.xmlns` is lowered verbatim from the root's `xmlns` attribute with no
check that it is the SCXML namespace - that check is st-l5k.5's.

### Decision 9: the FeatureDetector agreement gets a mechanical guard, on names not features

A guard test asserts a **partition**: each of the 26 known SCXML element names
is either a key in the dispatch map or produces an
`{:unsupported_element, _}` error when lowered, and no name is in neither or
both. That is the transferable half of "the library-side mirror of the
FeatureDetector contract" - fail loudly, name the thing, never skip.

The guard does **not** compare feature atoms. `FeatureDetector`'s vocabulary is
feature-shaped, not element-shaped: it has no atom for `<elseif>` or `<else>`,
and maps `<param>` to `:send_param_elements` regardless of whether it sits under
`<send>`, `<invoke>`, or `<donedata>`. Lining the two vocabularies up would mean
changing harness code to serve a library test. `lib/` may not reference
`test/support/` either way (`test/support/feature_detector.ex:6`, ADR-0006); the
guard lives entirely on the test side and reads only its own name list.

### Decision 10: the anti-matrix property is a string-literal uniqueness guard

The bead's whole reason for existing is structural, so it gets a mechanical
defense rather than a review note. The guard AST-walks every file under
`lib/statifier/lowering/**/*.ex`, drops doc attributes (the same technique as
`generic_handler_test.exs`), and asserts that **no SCXML element name appears
more than once as a whole string literal across the layer**.

A (child, parent) clause matrix cannot satisfy that property: every such clause
names both a child and a parent, so names repeat immediately. The design in
Decision 3 satisfies it by construction - each name appears exactly once as a
dispatch-map key, placement is by atom tag, and the deferred names appear once
each in `@phase_3_elements`.

### Decision 11: no changelog fragment

Per `changelog.d/README.md`'s "while v2 is unreleased" rule, a fragment is
warranted only when v2 differs from v1 in a way a user of the public API could
notice. Lowering is an internal stage with no public entry point wired yet
(`Statifier.parse/1` is st-wju.7), and re-implementing document parsing that v1
already did is invisible to a user. No `changelog.d/st-l5k.4.md`.

## Phase 1: The lowering skeleton and the `<scxml>` root

### Overview

Establish the namespace, the error type, the accumulator contract, and the root
builder. At the end of this phase a document whose `<scxml>` has attributes and
no children lowers correctly, and one with several unknown children reports
several errors in one pass - so the multi-error mechanism is exercised from the
first commit rather than bolted on later.

### Changes Required:

#### 1. The error type
**File**: `lib/statifier/lowering/error.ex` (new)
**Changes**: A plain struct, not a `defexception` - lowering never raises, and
errors travel in lists. Mirrors `ParseError`'s shape precedent: a
pattern-matchable `reason`, a rendered `message`, a `Location`.

```elixir
@type reason ::
        {:unsupported_element, name :: binary()}
        | {:misplaced_element, name :: binary(), parent :: binary()}
        | {:stray_text, text :: binary()}
        | {:unexpected_root, name :: binary()}
        | {:missing_attribute, element :: binary(), attribute :: binary()}
        | {:foreign_element, name :: binary(), uri :: binary()}

@enforce_keys [:reason, :message, :location]
defstruct [:reason, :message, :location]
```

Constructors: `unsupported/2`, `misplaced/3`, `stray_text/2`,
`unexpected_root/2`. `missing_attribute/3` arrives in Phase 3 (the only
required attribute in the Phase 1 set is `<raise>`'s `event`, which
`@enforce_keys` makes unbuildable without) and `foreign_element/3` in Phase 5;
the `reason` union above is the finished set, declared once here so later phases
add a constructor rather than reopen the type.

`{:stray_text, text}` carries the trimmed run truncated to a readable prefix,
so the message is useful without embedding a paragraph.

#### 2. The walk and the dispatch map
**File**: `lib/statifier/lowering.ex` (new)
**Changes**: `lower/1`, the dispatch map (one key per supported element, empty
but for `"scxml"` in this phase), the accumulator helpers, the stray-text check,
and the final sort.

```elixir
@spec lower(root :: Element.t()) :: {:ok, Document.t()} | {:error, [Error.t()]}
```

The stray-text check reads the **unfiltered** `children` list and errors on any
`%Text{}` whose `String.trim/1` is not `""`, naming the text node's own
`location`. Whitespace-only runs are ignored everywhere.

A root whose resolved name is not `scxml` returns
`{:error, [%Error{reason: {:unexpected_root, name}}]}`.

#### 3. Attribute reading
**File**: `lib/statifier/lowering/attributes.ex` (new)
**Changes**: The four operations every builder needs - fetch a raw value, split
a whitespace-separated value into a list, map a value to an atom with a default,
and record the value span into `attribute_locations`.

The span rule in one place: a key is added **only** when the attribute was
written **and** its `value_location` is non-nil. A nil `value_location` (the
handler's short-scan tolerance) means the field is still lowered but the span is
absent; the value is never lost, only the location.

#### 4. The `<scxml>` builder
**File**: `lib/statifier/lowering/builders.ex` (new)
**Changes**: `build_scxml/2` reading `initial` (split), `name`, `datamodel`,
`binding` (atom, default `:early`), `version`, `xmlns`, with the root's
`location` and its `attribute_locations`. State children are placed in Phase 2;
in this phase every element child misses the dispatch map.

#### 5. Tests
**File**: `test/statifier/lowering/lowering_test.exs`,
`test/statifier/lowering/error_test.exs` (new)

Happy path with all six root attributes; happy path with none (defaults
applied, `attribute_locations` empty); `binding="late"` and `binding="early"`
both present in `attribute_locations`; three unknown children producing three
errors in document order; a stray-text error with its location; a
whitespace-only run producing none; a non-`scxml` root.

### Success Criteria:

#### Automated Verification:
- [x] Full quality gate passes: `mix quality`
- [x] `mix gate.verify` confirms the run was unprofiled and unscoped
- [x] `mix test.regression` green (new tests are globbed into the ratchet automatically)

#### Manual Verification:
- [ ] `lower/1`'s moduledoc states the accumulator contract and why the partial tree is never returned
- [ ] Reading `lowering.ex`, no function takes a parent element name as an argument

## Phase 2: The state family and transitions

### Overview

`<state>`, `<parallel>`, `<final>`, `<history>`, `<initial>`, `<transition>` -
the structural spine, with tokenization, defaults, nesting, and order
preservation.

### Changes Required:

#### 1. Builders
**File**: `lib/statifier/lowering/builders.ex`
**Changes**: Six new builders and six new dispatch entries.

- `build_state/2`, `build_parallel/2`, `build_final/2`, `build_history/2` each
  produce a `%State{}` with the matching `kind`, delegating to one shared
  private `state_like/3`. One builder per element is preserved: the dispatch map
  has four distinct entries, and the kind is the builder's own contribution.
- `build_history/2` additionally reads `type`, mapping to
  `:shallow | :deep` with `:shallow` as the default.
- `build_initial/2` produces `%Initial{}` with a `transitions` list - however
  many `<transition>` children there are, including zero and two.
- `build_transition/2` reads `event` (split), `target` (split), `cond` (raw
  string), `type` (atom, default `:external`).

#### 2. Placement
**File**: `lib/statifier/lowering/builders.ex`
**Changes**: `place/2` clauses for `%State{}`'s slots (`states`, `transitions`,
`initial_element`) and for `%Document{}`'s (`states`). Every list slot is built
with `Enum.reverse/1` at the end of the child fold, never appended per child.

An unknown `type` value on `<transition>` or `<history>` - `type="sideways"` -
lowers to the **default** and keeps the `attribute_locations` entry, rather than
erroring. Rationale: an out-of-range enumerated value is a semantic check with a
stable error code, which is st-l5k.5's shape, and the span is retained so the
check can point at it. Recorded in Residual Notes.

#### 3. Tests
**File**: `test/statifier/lowering/state_test.exs`,
`test/statifier/lowering/transition_test.exs` (new)

Per-element happy path; nesting three deep; `initial="a b c"` splitting;
`target="a b"` and `event="e1 e2"` splitting; `event=""` yielding `[]` with the
key present; the `:external` / `:shallow` defaults applied with **no**
`attribute_locations` key; `type="external"` written explicitly **with** the
key; a `<state>` holding both an `initial` attribute and an `<initial>` element
built as written; an `<initial>` with zero and with two transitions; a
`<transition>` directly under `<scxml>` producing `{:misplaced_element, ...}`.

The **order-preservation test**: one `<state>` with interleaved
`<transition>`/`<state>`/`<transition>`/`<state>` children, asserting each list
is in document order and that the two lists interleave correctly by
`location.start_offset`.

### Success Criteria:

#### Automated Verification:
- [x] Full quality gate passes: `mix quality`
- [x] `mix test.regression` green

#### Manual Verification:
- [ ] No builder inspects its parent; `state_like/3` takes a kind atom, not a parent name
- [ ] A hand-lowered SCION document inspected in `iex` has the tree shape a reader would draw

**Implementation Note**: Same gate discipline as Phase 1.

## Phase 3: Executable content

### Overview

`<onentry>`, `<onexit>`, `<raise>`, `<log>`, and a transition's own content -
with the block boundary the spec requires and v1 lost.

### Changes Required:

#### 1. Builders
**File**: `lib/statifier/lowering/builders.ex`
**Changes**: Four new builders and four new dispatch entries.

- `build_onentry/2` and `build_onexit/2` each produce a `%Block{}` with the
  element's own `location`, tagged `{:onentry, block}` / `{:onexit, block}`.
  Each `<onentry>` element becomes **one** `Block`; three of them become three
  entries in `State.onentry`, never one flattened list (spec 3.8/3.9, and
  section 4's error-isolation rule).
- `build_raise/2` reads `event` as a **single unsplit string**

  adds one reason to `Error`.
- `build_log/2` reads `label` and `expr`, both nilable, both raw.

**File**: `lib/statifier/lowering/builders.ex`
**Changes**: `place/2` clauses putting `{:content_node, _}` into `Block.content`
and into `Transition.content` (unwrapped - a transition has no block element in
the source to give a block a location, per `Statifier.Document.Block`'s
moduledoc).

## Phase 4: `<donedata>` and `<content>`

### Overview

The last two Phase 1 elements, and the boundary where `<param>` is refused.

### Changes Required:

#### 1. Builders
**File**: `lib/statifier/lowering/builders.ex`

## Phase 5: Namespace resolution

### Overview

Dispatch on the local name after resolving prefixes, so the four prefixed SCION
documents lower and a genuinely foreign element errors loudly (Decision 8).

### Changes Required:

#### 1. Prefix scope
**File**: `lib/statifier/lowering/namespace.ex` (new)
**Changes**: A scope map threaded down the walk. `Namespace.push/2` folds an
element's `xmlns` and `xmlns:*` attributes into the inherited scope;
`Namespace.resolve/2` turns a qualified name into `{uri_or_nil, local_name}`.

Declarations are scoped to the subtree they appear on, which falls out of
threading the map through the recursion rather than storing it globally.

#### 2. Dispatch
**File**: `lib/statifier/lowering.ex`
**Changes**: Resolve before dispatching. `nil` or the SCXML namespace URI
dispatches on the local name; any other URI produces
`{:foreign_element, qualified_name, uri}` at the element's location. The
`{:unexpected_root, _}` check moves onto the resolved local name too, so
`<ns0:scxml>` is a valid root.

The SCXML namespace URI is a module attribute in `namespace.ex` - a URI string,
not an element name, so the Decision 10 guard is unaffected.

#### 3. Tests
**File**: `test/statifier/lowering/namespace_test.exs` (new)

The `m0_test.exs` shape (every element `ns0:`-prefixed) lowering to the same
tree as its unprefixed twin; a fixture with no `xmlns` at all lowering
(leniency); an element in a genuinely foreign namespace erroring with the URI
named; a declaration on a nested element applying only to its subtree; a prefix
declared but bound to a non-SCXML URI erroring rather than dispatching.

## Phase 6: Guards and property sweeps

### Overview

The mechanical defenses. This phase adds no `lib/` code; its entire value is
that a future edit which reintroduces the clause matrix, or silently drops an
element, reddens.

### Changes Required:

#### 1. The anti-matrix guard
**File**: `test/statifier/lowering/layer_test.exs` (new)
**Changes**: Per Decision 10 - AST-walk every file under
`lib/statifier/lowering/**/*.ex`, drop `@moduledoc`/`@doc`/`@typedoc`, and
assert that no SCXML element name appears more than once as a whole string
literal across the layer. Reuses `generic_handler_test.exs`'s
`string_literals/1` technique and its 26-name list.

A companion fixture-loader test asserts the wildcard still matches the lowering
modules, so the guard cannot pass vacuously by matching nothing.

#### 2. The element-partition guard
**File**: `test/statifier/lowering/coverage_test.exs` (new)
**Changes**: Per Decision 9 - for each of the 26 known element names, lower a
minimal document containing it and assert it either builds or produces an
`{:unsupported_element, _}` naming it. Assert the two sets partition: union is
all 26, intersection is empty.

#### 3. The location property sweep
**File**: `test/statifier/lowering/location_test.exs` (new)
**Changes**: In the style of
`test/statifier/parser/location_accuracy_test.exs:13-37` - lower a document
exercising every Phase 1 element, then walk the produced tree and assert for
every node that `Location.slice(source, node.location)` starts with that node's
start tag, and for every `attribute_locations` entry that the slice equals the
field's stored value (allowing for entity expansion, which no fixture uses).

#### 4. Per-element unsupported fixtures
**File**: `test/statifier/lowering/unsupported_test.exs` (new)
**Changes**: One fixture per deferred element placing it where the spec allows
it - `<script>` under `<scxml>` and under `<state>`, `<param>` under
`<donedata>`, `<if>`/`<elseif>`/`<else>` under `<onentry>`, `<assign>` under a
`<transition>`, and so on - each asserting one error naming the element and its
own location.

#### 5. Sabotage
**File**: all of the above
**Changes**: Every test asserting `lib/` behavior gets its one-line note per
`docs/testing.md`. The mutations this phase's guards are built around:

- drop `"final"` from the dispatch map -> it lands in neither partition -> red
- give `build_transition/2` a parent-name argument and a second clause -> a
  duplicated element-name literal -> red
- flatten the three `<onentry>` blocks into one -> the block-count assertion -> red
- skip the `Enum.reverse/1` on a child fold -> the order-preservation test -> red
- copy `attribute.location` instead of `attribute.value_location` -> the slice
  equality in the location sweep -> red
- add an `attribute_locations` key unconditionally rather than only when written
  -> the "default applied, no key" assertion -> red
- filter stray text with `DOM.elements/1` instead of erroring on it -> red

## Testing Strategy

### Unit Tests:

All under `test/statifier/lowering/`, `use ExUnit.Case, async: true` (not
`Statifier.Case`, which is corpus-only). XML fixtures are triple-quoted heredocs
at 4-space base indentation, fed to a locally-defined `lower!/1` helper per
module, matching `test/statifier/parser_test.exs:9-12`. Single-line fixtures use
`~s(...)`.

Error assertions pattern-match the whole tuple and rebind for follow-ups, in the
style of `test/statifier/parser_test.exs:265-275`:

```elixir
assert {:error, [%Error{reason: {:unsupported_element, "send"}} = error]} =
         Lowering.lower(root)

assert %Location{start_line: 4} = error.location
```

Coverage per element: one happy-path fixture and one unsupported/misplaced
fixture each, plus the cross-cutting order-preservation, multi-error,
stray-text, and location-slice tests.

Every test asserting `lib/` behavior carries a one-line sabotage note above the
`test` line and above any `@tag`, per `docs/testing.md`. The two structural
guard tests state their exemption explicitly where they assert file structure
rather than behavior (`# sabotage: n/a - ...`).

### Conformance Tests:

None ratchet in from this bead. `test/support/case.ex:118` still flunks on
`Statifier.parse/1`, which st-wju.7 wires; no SCION or W3C test can pass until
the interpreter exists. `test/passing_tests.json`'s `scion_tests` and
`w3c_tests` lists are untouched, so `mix gate.check` has nothing to flag.

`test/passing_tests.json`'s `internal_tests` list globs
`test/statifier/**/*_test.exs`, so every new test here joins the regression
ratchet automatically - no manual ratcheting, and no shrinking of the file.

### Manual Testing Steps:

1. Lower one SCION and one W3C document by hand in `iex` and read the tree: the
   state hierarchy, transition targets, and block boundaries should match what a
   reader would draw from the source.
2. Lower `test/scion_tests/atom3_basic_tests/m0_test.exs`'s prefixed XML and
   confirm it produces the same tree as the same document with prefixes removed.
3. Lower a document with a `<send>`, a `<param>`, and a stray sentence of text
   and confirm all three errors come back from **one** call, in document order.
4. Pick a `cond` attribute and confirm
   `Location.slice(source, doc |> ... |> attribute_locations[:cond])` returns
   exactly the expression text, quotes excluded - the ADR-0014 arithmetic base.

## Residual Notes for Later Beads

Recorded, not blocking; none needs an answer before this bead ships.

1. **Duplicate attributes are reported by nothing.** The DOM preserves them
   deliberately and lowering passes them through (Decision 7), but no listed
   st-l5k.5 check names them. Either an existing check widens or a new one
   appears; lowering is unaffected either way, since `element.attributes` still
   holds the whole list.
2. **An out-of-range enumerated attribute value** (`type="sideways"`,
   `binding="whenever"`) lowers to the default with its span retained
   (Phase 2). No st-l5k.5 check is listed for it. The span is deliberately kept
   so the check, when written, can point at the offending text.
3. **A nil `value_location`** means no `attribute_locations` key even though the
   author wrote the attribute, which weakens `Map.has_key?/2` as the "was it
   written" question in exactly one corner. It arises only from the handler's
   short-scan tolerance (`lib/statifier/parser/handler.ex:162-175`) and no
   corpus document triggers it. If one ever does, the fix belongs in the scanner,
   not here.
4. **`<content>` text is stored untrimmed** (Decision 5 / Phase 4). A donedata
   payload written across several lines carries its surrounding whitespace into
   `Content.text`. Whether the interpreter compares it trimmed is st-wju.1's
   call; the raw text is what the source said and normalizing it here would be a
   semantic decision in the wrong layer.
5. **Foreign-namespace elements error rather than being ignored** (Decision 8),
   which is stricter than spec 3.2's "MAY ignore". If a real document ever needs
   the lenient reading, the change is one clause in `Lowering`'s dispatch plus a
   policy decision about what "ignore" means for the validator downstream.

# `<send>` / `<cancel>` content nodes producing the send effects - Implementation Plan

## Overview

Make `<send>` and `<cancel>` first-class lowered, compiled, executable content
nodes so the pure core produces `{:send, %Effect.Send{}}`,
`{:send_delayed, %Effect.SendDelayed{}}`, and `{:cancel, %Effect.Cancel{}}`.
Every consumer already exists: `Statifier.Session.Effects.plan/1` has had
clauses for all three since st-cmq.4, and the three effect structs have been
sitting producer-less since st-wju.2. This bead builds the producer half only -
delivery, `error.communication`, and corpus feature-atom flips stay out.

Bead: st-cmq.3. Absorbs st-rsl (delay parsing delegates to
`Predicator.Duration`), per st-rsl's own standing instruction.

## Current State Analysis

`<send>` and `<cancel>` are the last two elements in the lowering coverage
test's `@phase_3_elements` deferred set
(`test/statifier/lowering/coverage_test.exs:38-40`); every other SCXML element
name is supported. Today a `<send>` anywhere in a document is a hard
`{:unsupported_element, "send"}` lowering error
(`test/statifier/lowering/unsupported_test.exs:41-56`).

What already exists and is not built here:

- **The three effect structs.** `Effect.Send`
  (`lib/statifier/effect/send.ex:19-40`), `Effect.SendDelayed`
  (`lib/statifier/effect/send_delayed.ex:14-37`), `Effect.Cancel`
  (`lib/statifier/effect/cancel.ex:13-21`). All carry the spec's own attribute
  names. `Effect.Send`'s moduledoc says "Extend fields, never rename". None
  carries `owner` yet.
- **The session-side planner.** `lib/statifier/session/effects.ex:50-69`
  already routes all three. It "copies the already-resolved fields off the
  effect and evaluates nothing", so every field must be fully resolved by the
  core before the effect leaves `execute/2`.
- **The protocol and block runner** (st-wju.5).
  `Statifier.ExecutableContent.execute/2`
  (`lib/statifier/executable_content.ex:69-73`) is the contract;
  `Statifier.Interpreter.Content.execute_block/3`
  (`lib/statifier/interpreter/content.ex:127-159`) is the only site that turns
  a node's opaque `{:error, reason}` into `error.execution`
  (`raise_execution_error/4`, `:226-236`). Neither file changes for a new
  element.
- **`Statifier.EventData.coerce/1`** (`lib/statifier/event_data.ex:52-55`), the
  single payload-coercion function, whose moduledoc already names `<send>` as
  an expected caller.
- **`Statifier.Interpreter.Datamodel.write_location/4`**
  (`lib/statifier/interpreter/datamodel.ex:115-138`), extracted from
  `Content.Assign`'s `defimpl` explicitly "so `idlocation` (6.4.1) ... can call
  the same mechanics".
- **`<invoke>`** (st-cmq.6, landed) with a near-identical attribute surface.
  `invoke_one/6` (`lib/statifier/interpreter.ex:1278-1313`) is the runtime
  shape to mirror: a `with` over `resolve_expr/2`, `resolve_params/2`,
  `resolve_content/2`, then id generation, then `maybe_write_idlocation/4`,
  then the effect.
- **`Predicator.Duration.parse/1` + `to_milliseconds/1`**, available since the
  `~> 8.0` pin landed (`mix.exs:41`, st-59d) and called from nowhere in `lib/`.

What is missing: `Statifier.Document.Send` / `.Cancel`, the two lowering
builders and their dispatch/place/reverse wiring, `Checks.Send` / `Checks.Cancel`,
the compiler clauses, `Machine.Content.Send` / `.Cancel` with their `defimpl`s,
a send-id sequence on `%MachineState{}`, and `owner` on the three effects.

## Desired End State

A document containing `<send>` and `<cancel>` parses, lowers, validates,
compiles, and executes, and executing it yields the three effect tuples fully
resolved, carrying `owner`, with `send_id` written through `idlocation` when
present. Verified by:

- `mix quality` green, including coverage and Doctor's 100% doc thresholds.
- `Statifier.Lowering.lower/1` builds `%Document.Send{}` / `%Document.Cancel{}`;
  `test/statifier/lowering/coverage_test.exs`'s `@phase_3_elements` list is
  empty and both names are in `@supported`.
- New tests in `test/statifier/machine/content/` assert the produced effects
  field-by-field for every attribute variant, including `delay`, `delayexpr`,
  `idlocation`, `namelist`, `<param>`, and `<content>`.
- An end-to-end test drives a real `<send delay>` / `<cancel>` document through
  `Statifier.Session` and observes the timer scheduled and cancelled - the
  suites ADR-0029's consequences said would migrate onto real documents once
  this landed.

### Key Discoveries:

- The send id **cannot** be a UXID. ADR-0008 as amended 2026-08-15
  (`docs/adr/0008-uxid-for-identifiers.md:112-117`) names `<send idlocation>`
  explicitly and leaves only the concrete format to this record. The invoke
  precedent is `machine_state.invoke_counter`
  (`lib/statifier/interpreter.ex:1384-1405`,
  `lib/statifier/machine_state.ex:128-167`).
- Spec 6.2.2's element-level MUST - "If the evaluation of `<send>`'s arguments
  produces an error, the Processor MUST discard the message without attempting
  to deliver it" - is the controlling clause for every argument failure,
  including `<param>` (5.7) and `<content expr>` (5.6.2). 5.6.2 itself defers:
  "The use of the `<content>` element depends on the context in which it
  occurs. See 5.5 `<donedata>`, 6.2 `<send>` and 6.4 `<invoke>` for details."
- `<send>`'s node is a **leaf**, so its `execute/2` returns the two-element
  error form (`lib/statifier/executable_content.ex:40-45`).
- Adding `owner` to the three effects and `send_counter` to `%MachineState{}`
  requires **no** change in `lib/statifier/session/recording.ex` or
  `lib/statifier/replay.ex`: the recorder stores each batch opaquely as
  `{:interpret, effects}` (`recording.ex:143-145`) with no serialization
  whitelist anywhere in `lib/`; `%Recording{}` is
  `defstruct [:machine, :opts, entries: []]` (`recording.ex:73`) and holds no
  `%MachineState{}` at all; and `Replay.run/1` builds a fresh one through
  `Interpreter.initialize/2` from the recorded machine and opts
  (`lib/statifier/replay.ex:145-151`), so a new struct field is picked up
  automatically. Every effect pattern match in `session/effects.ex:50-70` is
  partial (`%Send{target: nil}`, `%Send{}`, `%Cancel{send_id: id}` - never a
  full-shape match), so extra fields cannot break planning.
- `Predicator.Duration.parse(".5s")` is `:error` while `parse("1.5s")` is
  `{:ok, %{seconds: 1, milliseconds: 500}}`, so the leading-dot
  pre-normalization st-rsl describes is genuinely owed.
- ADR-0033 (`docs/adr/0033-validator-warning-tier.md:112-122`) reserved the
  6.5.2 `<send>`-in-`<finalize>` warning for this bead as "one additional
  clause in `forbidden/1`, no new reason tag"
  (`lib/statifier/validator/checks/invoke.ex:145-148`;
  `Warning.finalize_forbidden_content/2` already takes the element name as
  data, `lib/statifier/validator/warning.ex:53-55`).

## What We're NOT Doing

- **Delivery.** Routing, timers, and the external queue are `Statifier.Session`'s.
  The core describes; it does not perform (ADR-0003).
- **`error.communication` for unreachable targets.** Spec 3.12.2 puts
  communication failure on the session's side. Only 6.2.4's `error.execution`
  arm (unsupported or invalid target/type detected at execute time) could
  belong here, and see the next bullet.
- **Rejecting unsupported `target` / `type` values.** 6.2.4 and 6.2.5 make an
  unsupported target or Event I/O Processor type an `error.execution`, but
  "which types this processor supports" is a session-side fact (st-cmq.5 /
  st-cmq.7 own external targets and child sessions). The core resolves both
  attributes to their string values and hands them on; the check lands with the
  code that knows the answer. This is a deliberate deferral, not an oversight.
- **Flipping corpus feature atoms.** `send_elements`,
  `send_delay_expressions`, `send_param_elements`, `send_content_elements`,
  `send_idlocation`, `event_expressions`, `target_expressions`, and
  `cancel_elements` are the Phase 4 corpus bead's to flip.
- **The `_event.data` present-and-null collapse.** Filed as **st-xw7a** and
  linked below; see Decision 3.
- **`<invoke>`.** Landed under st-cmq.6; untouched here.

## Implementation Approach

Mirror `<invoke>` file-for-file. Six phases, ordered so no intermediate commit
leaves a crashing path: the two records first (docs only), then the runtime
substrate the nodes need (counter, `owner`, duration), then each element
end-to-end (document -> lowering -> compiler -> machine node -> `defimpl` in
one phase per element), then the validator, then integration.

**Why the per-element phases are not split further.** Splitting "document +
lowering" from "compiler + machine node" would create a window in which
`Lowering.lower/1` happily builds a `%Document.Send{}` that
`Compiler.build_content_node/2` has no clause for - a `FunctionClauseError`
rather than an error return, on a path that previously produced a clean
`{:unsupported_element, "send"}`. Per this skill's sizing rule, the smallest
independently gate-verifiable unit here is the whole element, so the two halves
stay in one phase.

**The Appendix D rule.** No Appendix D procedure is edited by this plan.
`<send>` and `<cancel>` are executable content: they enter through the existing
`Statifier.Interpreter.Content.execute_block/3` dispatch, which is itself
already the ported `executeContent`. There is therefore **no deviation from the
pseudocode to declare** - the plan adds protocol implementations below that
line, and any change to `interpreter/content.ex` or `executable_content.ex`
would be a signal the design went wrong.

### The three decisions this plan resolves

**Decision 1 - the send id is `send_<n>` off a new `machine_state.send_counter`.**

The bead's wording, "a `send_` UXID generated at execute time", **loses to
ADR-0008 as amended**, which forbids a UXID for any id minted inside the pure
core and names `<send idlocation>` as governed by that rule. The divergence is
recorded here rather than silently: a UXID reads the wall clock and a CSPRNG,
which would make `execute/2` a function of `(state, event, clock, entropy)`
instead of ADR-0003's `(state, event) -> {state, [effect]}`, and observably so,
because `idlocation` writes the id into the datamodel where replay would then
diverge. The bead keeps the `send_` *prefix*; only "UXID" is superseded.

Core-minting is forced, and this closes the secondary reading the research
raised: the session cannot mint the id, because `Effects.plan/1` "evaluates
nothing" and needs a resolved `send_id` on the effect, and because `idlocation`
must write that id into the datamodel from inside `execute/2`.

Between reusing `invoke_counter` and adding a sibling `send_counter`, this plan
picks **a sibling `send_counter`**:

- The two sequences have different governing clauses. `<invoke>`'s format is
  pinned by 6.4.1 (`stateid.platformid`); `<send>`'s is free - 3.14 says "The
  SCXML processor MAY generate all other ids in any format, as long as they are
  unique". Coupling a free-format sequence to a pinned one buys nothing.
- Sharing would let an `<invoke>` advance the send-id sequence, so a document's
  `send_` ids would depend on how many invocations happened first. Still
  deterministic and still replayable, but the ids stop being locally readable,
  and readable ids are exactly what `idlocation` puts in front of an author.
- The cost is one struct field, one typespec line, one key in
  `MachineState.new/2`, and one moduledoc section - the pattern
  `invoke_counter` already established (`lib/statifier/machine_state.ex:304`,
  `:397`, `:128-167`).

Format: `"send_" <> Integer.to_string(counter + 1)`, so the first generated id
is `send_1`. No state-id prefix (that is 6.4.1's requirement for `<invoke>`
alone). An author-written `id` is used verbatim and never advances the counter,
exactly as `generate_invoke_id/3` does. A new id is generated on **every**
execution of the element, never memoized on it (3.14: "not at load time but
each time the element is executed").

This gets its own short ADR (**ADR-0035**), the way the invoke format did,
because ADR-0008 explicitly left the format "to the record that implements it".

**Decision 2 - a failed `<send>` argument, `<content expr>` included, discards
the message; no effect is produced.**

Spec 5.6.2, quoted from the local cache:

> If the evaluation of 'expr' produces an error, the Processor MUST place
> error.execution in the internal event queue and use the empty string as the
> value of the `<content>` element.

Spec 6.2.2, from the same cache:

> The Processor MUST evaluate all arguments to `<send>` when the `<send>`
> element is evaluated, and not when the message is actually dispatched. If the
> evaluation of `<send>`'s arguments produces an error, the Processor MUST
> discard the message without attempting to deliver it.

These collide, and 6.2.2 wins, for a reason 5.6.2 supplies itself two sentences
earlier:

> The use of the `<content>` element depends on the context in which it occurs.
> See 5.5 `<donedata>`, 6.2 `<send>` and 6.4 `<invoke>` for details.

5.6.2's empty-string rung is the generic default for a context that has no rule
of its own. `<send>` has one, and 5.6.2 points at it by name. The same argument
resolves the 5.7-versus-6.2 question below it: 5.7's "MUST ignore the name and
value" is per-`<param>` and is what `<donedata>` implements
(`lib/statifier/interpreter/exit_entry.ex:1074`), but 6.2.2's discard is
element-level and specific to this context. `<invoke>` resolved the identical
collision the identical way under ADR-0031, and its `resolve_params/2` halts on
first failure (`lib/statifier/interpreter.ex:1329-1342`) for exactly this
reason.

So: the first failing argument returns `{:error, reason}` from `execute/2`, the
block runner converts it to `error.execution` (its sole such site), and **no**
`Effect.Send` / `Effect.SendDelayed` is emitted. The empty-string value is
therefore never constructible under `<send>`, which is the outcome, not an
omission.

Because the plan chooses something other than 5.6's empty string, **this is an
amendment to ADR-0021's scope limit**, exactly as that record's consequences
require ("If they conclude those contexts should also yield no data, that is an
amendment to this record's scope limit, not a silent extension of it"). It is
written as **ADR-0036** with a pointer added into ADR-0021, not as a quiet
extension. ADR-0036 covers `<send>` only; `<invoke>` already has ADR-0031, and
neither record claims `<content>` under any future element.

**Decision 3 - the `_event.data` present-and-null collapse is out of scope, and
is filed as st-xw7a.**

The bead's inherited note is answered in two halves. `EventData.coerce/1` is
correct and preserves it -
`coerce({:text, ~s({"foo": null, "bar": 1})})` is `%{"bar" => 1, "foo" => nil}`
- so `Effect.Send.data` carries `nil` faithfully and B.2.1 is satisfied at the
coercion boundary. That half is this bead's, and it gets a test (Phase 3).

The other half is not. `Statifier.Evaluator.undefine_nils/1`
(`lib/statifier/evaluator.ex:220-228`) rewrites `nil` to `:undefined`
recursively, and `bind/3` (`:254-258`) applies it to **every** root bound into a
`Predicator.Context`, `_event` included - so `_event.data.foo === undefined` is
true for a field that was present and null. That is the datamodel's global
bind-time convention, written for `<data>` with no `expr`
(`lib/statifier/evaluator.ex:200-219`), not anything `<send>` does; changing it
touches every bound root and is an ADR-shaped call. No corpus file is currently
known to depend on the distinction. Filed as **st-xw7a**
("Present-and-null vs absent collapses at bind time (undefine_nils)"), to be
re-checked when the send/cancel corpus atoms flip.

### The smaller calls, also settled here

- **st-rsl is absorbed.** Its own description says "if st-cmq.3 is implemented
  after this is read, fold it in there and close this bead against it", and its
  blocker (st-59d, the `~> 8.0` pin) has landed. Its full scope - delegate to
  `Predicator.Duration.parse/1` + `to_milliseconds/1`, accept a native
  predicator duration value from `delayexpr` as well as a string, document the
  `{y,mo,w,d,h,m,s,ms}` superset without re-restricting it, pre-normalize a
  leading `.` to `0.`, and test both `.5s` and `1.5s` - is implemented in Phase
  2. **st-rsl should be closed as subsumed once this branch merges** (closing is
  the orchestrator's call after the merge is verified against the remote, per
  CLAUDE.md's authority table, not something this plan performs).
- **`delay` with `target="_internal"` is a validator error.** 6.2.2 lists it
  among `delay`'s own attribute constraints ("Must not occur with 'delayexpr'
  or when the attribute 'target' has the value `_internal`"), and the house
  pattern reports 6.x.1 attribute constraints as errors (`Checks.Invoke`'s
  five). It is detectable only when `target` is a literal attribute; with
  `targetexpr` the value is not known until execute time, and the check stays
  silent there rather than guessing. This is deliberately *not* an ADR-0033
  warning: ADR-0033's tier is for rules the engine has a defined behavior for,
  and here the document is simply nonconformant.
- **`<cancel>` gets its own validator check file.** The house pattern is one
  file per element (`Checks.Invoke`, `Checks.Assign`, `Checks.Param`), and
  folding 6.3.1's single constraint into `Checks.Send` would put `<cancel>`'s
  only rule somewhere nobody looking for `<cancel>` would find it. One
  constraint is enough to justify one file at this repo's granularity.
- **A `<cancel>` whose `sendid` matches nothing is a no-op, and the core does
  nothing about it.** 6.3 says the Processor "SHOULD make its best attempt";
  the session already treats an unknown `send_id` as a no-op
  (`lib/statifier/session.ex:550`). The core emits `{:cancel, %Effect.Cancel{}}`
  unconditionally and lets the session decide there is nothing to cancel.
- **Adding `owner` needs nothing in the replay recorder.** Verified above; the
  hand-waving noted in the st-dtm research is about which *events* the recorder
  captures, not about effect struct shape.
- **A changelog fragment at `changelog.d/st-cmq.3.md` is owed, narrowly.** v1
  already had `<send>` with delay, delayexpr, namelist, `<param>`, and
  `<content>` (`../statifier/lib/statifier/actions/send_action.ex`), and
  `changelog.d/README.md`'s v2 rule is "write a fragment when v2 differs from
  v1 ... Re-implementing something v1 already did is invisible to a user and
  gets no fragment". So `<send>`/`<cancel>` support itself gets **no** line.
  What does differ is the delay surface: v2's `delayexpr` accepts a native
  predicator duration value (`timeout::duration`, a computed `2s + backoff`) in
  addition to a string, and the whole unit set `{y,mo,w,d,h,m,s,ms}` is
  accepted where v1 parsed the SCXML subset only. That is one `### Added` line,
  written in Phase 6.

## Phase 2: Runtime substrate - `send_counter`, `owner`, `Statifier.Duration`

### Overview

The three pieces both element phases need, each independently testable, landed
before either node exists. This is also where st-rsl's entire scope is
discharged.

### Changes Required:

#### 1. `send_counter` on `%MachineState{}`
**File**: `lib/statifier/machine_state.ex`
**Changes**: A `send_counter: 0` sibling to `invoke_counter` in the `defstruct`
(`:293-313`), `send_counter: non_neg_integer()` in the `t()` map (`:344-361`),
an explicit `send_counter: 0` in the `new/2` literal (`:389-406`), and a
moduledoc section beside the `invoke_counter` one (`:128-167`) saying what it
counts, who writes it, why it is a counter and not a UXID (ADR-0003, ADR-0035),
and why it is not shared with `invoke_counter` (ADR-0035). No setter function -
`invoke_counter`'s own precedent is a direct write at its one call site.

#### 2. `owner` on the three effects
**Files**: `lib/statifier/effect/send.ex`, `lib/statifier/effect/send_delayed.ex`,
`lib/statifier/effect/cancel.ex`
**Changes**: Copy `Effect.Log`'s exact shape (`lib/statifier/effect/log.ex:18-33`):
an `alias Statifier.Machine.Content`, a local
`@typedoc` + `@type owner :: Content.owner()`, `:owner` added to `defstruct`
(never to `@enforce_keys` - it is nilable), and `owner: owner() | nil` in
`t()`. Field order additive; no renames (`lib/statifier/effect/send.ex:5-11`).

#### 3. `Statifier.Duration`
**File**: `lib/statifier/duration.ex` (new)
**Changes**: The one place this engine turns an SCXML duration designation into
milliseconds, wrapping predicator rather than reimplementing CSS2 parsing
(st-rsl). Public `to_ms/1` taking either a binary or a predicator duration
value:

```
@spec to_ms(value :: binary() | map()) :: {:ok, non_neg_integer()} | {:error, term()}
def to_ms(value) when is_binary(value) do
  case value |> normalize_leading_dot() |> Predicator.Duration.parse() do
    {:ok, duration} -> {:ok, Predicator.Duration.to_milliseconds(duration)}
    :error -> {:error, {:invalid_delay, value}}
  end
end
# a predicator duration value straight off `delayexpr` needs no parse
def to_ms(%{} = duration), do: ...
```

`normalize_leading_dot/1` rewrites a leading `.` to `0.` (`".5s"` -> `"0.5s"`),
the one-line concession the SCXML schema pattern `\d*(\.\d+)?(ms|s|m|h|d)`
requires and predicator 8.0 deliberately does not make. The moduledoc documents
that predicator's `{y, mo, w, d, h, m, s, ms}` unit set is a strict superset of
the SCXML schema's `{ms, s, m, h, d}` with identical meanings (`m` is minutes in
both), and that the superset is delegated as-is rather than re-restricted.

#### 4. Tests
**Files**: `test/statifier/duration_test.exs` (new),
`test/statifier/machine_state_acceptance_test.exs`, `test/statifier/effect_test.exs`
**Changes**: `Duration` tests for `"2s"`, `"1.5s"` -> `1500`, `".5s"` -> `500`
(the schema spelling), `"0.5ms"` -> error (predicator rejects a sub-millisecond
remainder), junk -> `{:error, _}`, a native duration value, and one
superset-unit case (`"1h"`). `send_counter` defaults to `0` from
`MachineState.new/2`. The three effect structs accept and default `owner`.
Every one of these carries a sabotage note per `docs/testing.md`.

#### 4. The compiled node
**File**: `lib/statifier/machine/content/send.ex` (new)
**Changes**: Struct + `defimpl Statifier.ExecutableContent` in one file
(st-wju.5), modeled on `lib/statifier/machine/content/log.ex` for shape and on
`invoke_one/6` (`lib/statifier/interpreter.ex:1278-1313`) for the body. A leaf,
so the two-element error form; `execute/2` never raises; the block runner owns
the `error.execution` conversion and this file never names that event (the
structural check in `test/statifier/interpreter/content_acceptance_test.exs`
enforces it).

The `with`, in order:

```
with {:ok, event}  <- resolve_expr(ctx, node.event),
     {:ok, target} <- resolve_expr(ctx, node.target),
     {:ok, type}   <- resolve_expr(ctx, node.type),
     {:ok, delay}  <- resolve_delay(ctx, node.delay),
     {:ok, raw}    <- resolve_params(ctx, node.namelist ++ node.params),
     {:ok, content} <- resolve_content(ctx, node.content) do
  {send_id, machine_state} = generate_send_id(machine_state, node)
  case maybe_write_idlocation(machine_state, dm_ctx, node.idlocation, send_id) do
    ...emit one effect...
    {:error, reason} -> {:error, reason}
  end
else
  {:error, reason} -> {:error, reason}
end
```

- `resolve_params/2` **halts on first failure** (Decision 2 / ADR-0036), unlike
  `<donedata>`'s per-param drop.
- `resolve_content/2` mirrors `<invoke>`'s: `{:static, text}` ->
  `EventData.coerce({:text, text})`; `{:compiled, _, _}` -> evaluate then
  `EventData.coerce({:value, v})`; a failure propagates (Decision 2), never the
  empty string.
- `data` is `EventData.coerce({:params, raw})` when there is no `<content>`,
  and the coerced content otherwise. The 6.2.2 constraint that `namelist` /
  `<param>` must not co-occur with `<content>` is the validator's to report;
  execution follows document order and does not re-litigate it.
- `generate_send_id/2`: `node.id` verbatim when the author wrote one (counter
  untouched), else `"send_" <> Integer.to_string(counter + 1)` with
  `send_counter` incremented (ADR-0035). Generated fresh per execution.
- `maybe_write_idlocation/4` delegates to
  `Interpreter.Datamodel.write_location/4`; a write failure is an argument
  failure - no effect, `{:error, reason}` (5.9.2).
- `resolve_delay/2` evaluates `delayexpr` or takes the static `delay`, then
  `Statifier.Duration.to_ms/1`. `nil` (neither attribute) -> `{:ok, nil}`. A
  parse failure is an argument failure, same discard.
- `nil` delay -> `{:send, %Effect.Send{}}`; a delay -> `{:send_delayed,
  %Effect.SendDelayed{delay_ms: ms}}`. Both carry `c_index`, `owner` from
  `context.owner`, and `machine_state.macrostep` / `.microstep`.

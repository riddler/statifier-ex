# Document Validator Implementation Plan

## Overview

Stands up `Statifier.Validator`, the single semantic gate between lowering and
the Machine compiler: a `%Statifier.Document{}` in, ten numbered checks run in
one collect-all pass, `{:ok, document} | {:error, [error]}` out. Every error
carries a stable tagged reason, a human message, and a source span.

Beads issue: st-l5k.5. Research: `docs/research/260808-st-l5k.5-document-validator.md`.

The research left nine open questions and no human was available to answer them.
Every one is decided below under "Decisions", each marked as an assumption a
reviewer may overturn. Six representable-but-invalid shapes that no numbered
check names were filed as discovered beads rather than growing this one.

## Current State Analysis

`lib/statifier/` has `parser/`, `lowering/`, and `document/`. There is no
`Statifier.Validator` module and no `lib/statifier/validator/` directory - the
layer is empty. `docs/architecture.md:38-58` places it between Document and
Compiler, and principle 4 (`:33-36`) makes it the *only* gate: the interpreter
accepts a compiled Machine and nothing else, so no "validate if not already
validated" branch exists downstream to catch what this pass misses.

The substrate was built for this bead and says so:

- `lib/statifier/document/state.ex:42-62` is a per-field table naming, for each
  representable misuse, the st-l5k.5 check that catches it. It also names two
  rows nothing catches.
- `lib/statifier/document/initial.ex:16-29` makes `transitions` a list
  *precisely* so check 4 can report the zero and two-or-more cases.
- `lib/statifier/document/donedata.ex:12-14` states that donedata on a
  non-final state "is a shape the validator (st-l5k.5 check 8) exists to
  report, not one this layer refuses to build".
- `lib/statifier/lowering/namespace.ex:43-44` hands the absent-or-wrong `xmlns`
  report to this bead by name.
- `lib/statifier/parser.ex:33-49` says rejecting a boilerplate-free fragment is
  this bead's job.

Two things the validator needs are missing from the input, and both are
information lowering discards rather than tree shape:

1. **The raw text of an out-of-range enumerated value.**
   `Statifier.Lowering.Attributes.atom/4` (`lib/statifier/lowering/attributes.ex:67-73`)
   maps any unrecognised value to the default, so `type="sideways"` and
   `type="shallow"` both arrive as `history_type: :shallow`. The
   `attribute_locations[:type]` span survives; the offending string does not.
   Check 5's "type is shallow or deep" is unimplementable from a `%Document{}`
   alone.
2. **The root element's resolved namespace URI.** `Document.xmlns` is the
   literal `xmlns` attribute (`lib/statifier/lowering/builders.ex:65`), so a
   spec-conformant `<s:scxml xmlns:s="http://www.w3.org/2005/07/scxml">` lowers
   to `xmlns: nil`. `Statifier.Lowering.lower/1` computes the resolved URI at
   `lib/statifier/lowering.ex:72` and then throws it away.

The error vocabulary the validator will be read against is
`Statifier.Lowering.Error` (`lib/statifier/lowering/error.ex`): a
`{reason, message, location}` struct, all `@enforce_keys`'d, never raised, with
a closed tagged-tuple `reason` union declared once up front and one named
constructor per reason. `Statifier.Lowering.lower/1` sorts by
`location.start_offset` before returning (`lib/statifier/lowering.ex:140`) and
never hands back a partial document (`:20-24`).

The v1 reference (`../statifier`, read-only) implements five of the ten checks,
gets check 3 wrong (direct-child membership, not descendancy, at
`../statifier/lib/statifier/validator/initial_state_validator.ex:154-155`), has
no `<final>`-children, `donedata`, `xmlns`, or `version` check, and actively
*defeats* checks 9 and 10 by rewriting the source string to insert both
(`../statifier/lib/statifier/parser/scxml.ex:76-103`). Its errors are bare
strings with no codes and, outside the history validator, no locations.

## Desired End State

`Statifier.Validator.validate/2` exists, takes the document and the source
binary it was parsed from, and returns `{:ok, document}` when all ten checks
pass or `{:error, [%Statifier.Validator.Error{}]}` sorted by
`location.start_offset` otherwise. All checks run on every call; nothing
short-circuits on the first failure.

Verification:

- `test/statifier/validator_test.exs` and the per-check test files under
  `test/statifier/validator/` are green, with one invalid fixture per error
  code asserting both the reason tag and the location's `start_line`.
- A corpus-shaped valid document (compound + parallel + history + final with
  donedata, plus a prefixed-namespace variant) returns `{:ok, document}` with
  the document unchanged.
- A single malformed document that trips several distinct checks returns all of
  their errors in one list, in document order.
- Full `mix quality` is green.

### Key Discoveries

- `%Document{}` can already express eight of the ten checks' inputs directly;
  the two gaps are C1 (raw enum text) and C2 (resolved namespace) above, both
  named in the research at `docs/research/260808-st-l5k.5-document-validator.md:540-577`.
- The `attribute_locations` "was it written" oracle is narrower than it looks:
  `put_location/4` also skips the key when a written attribute's
  `value_location` is `nil` (`lib/statifier/lowering/attributes.ex:92-93`). So
  `Map.has_key?/2` means "written **and** spanned". Checks 4 and 5 need it for
  `event`, because `Attributes.list/2` returns `[]` for both absent and
  `event=""`.
- Descendancy has no interned ranges to lean on. There is no `document_order`
  integer, no parent pointers, no index - all belong to the compiler (st-wju.1).
  The validator builds a throwaway index and explicitly must not share it
  (`docs/research/260807-st-l5k.2-typed-document-structs.md:460`).
- ADR-0002 puts Appendix D's predicates (`is_compound_state?`,
  `is_atomic_state?`) on the Machine, and `lib/statifier/document/` defines
  none. Checks 5 and 7 need a notion of "compound" and must define it locally,
  as a private helper, without exporting a predicate that duplicates the
  Machine's.
- ADR-0014 fixed `Location` as a span with 0-based exclusive-end byte offsets so
  `value_location.start_offset + expr_span.start` is arithmetic.
  `Location.slice/2` (`lib/statifier/parser/location.ex:69-72`) is what every
  location test in the repo is built on, and is what Decision 1 leans on.
- ADR-0012 item 3 is why every Document node carries a `location` at all, which
  is why every check has a span to point at.
- There is no XML fixture-file corpus in `test/`. Every parser and lowering test
  embeds its XML inline as a heredoc or `~s()` literal.
- `test/statifier/document/layer_test.exs` and
  `test/statifier/lowering/layer_test.exs` turn an acceptance criterion into a
  mechanical AST walk over the layer's own sources. "Every reason tag has a
  constructor, and no two constructors share a tag" has precedent there.

## What We're NOT Doing

- **No expression syntax checking.** `cond`, `log`'s `expr`, and `content`'s
  `expr` stay uncompiled strings; predicator compile errors surface at the
  Machine compiler (st-wju.1). Stated non-goal on the bead.
- **No event-name / event-descriptor syntax checking.** Descriptors are matched
  structurally at runtime per spec 3.13. Stated non-goal on the bead.
- **No reachability analysis.** v1 warned about unreachable states and
  unreachable history; the spec requires neither. Out of scope entirely.
- **No `Statifier.parse/1`.** `test/support/case.ex:112` still flunks with
  "Statifier.parse/1 does not exist yet"; that is st-dtr, which this bead
  blocks. See Decision 9.
- **No warning channel.** See Decision 4.
- **No interned index, no `document_order`, no expression compilation, no
  `validated` boolean.** All are the compiler's, and the last is exactly what
  principle 4 exists to make unrepresentable.
- **None of the six unassigned shapes.** See Decision 7 and the beads filed
  there.
- **No change to `Statifier.Lowering.Error`'s reason union.** It calls itself
  finished (`lib/statifier/lowering/error.ex:11-17`) and this bead does not
  reopen it.

## Implementation Approach

One `Statifier.Validator` module owning `validate/2` and the shared index, with
one `Statifier.Validator.Check.*` module per check group holding that group's
fold. Each check is a pure function `(document, ctx) -> [Error.t()]`;
`validate/2` concatenates the lists, sorts by `location.start_offset`, and
returns. Nothing short-circuits, so a document with five distinct problems
reports five errors.

The `ctx` is built once, before any check runs, and thrown away after:

```elixir
%Statifier.Validator.Context{
  source: binary(),                       # for Location.slice/2 (Decision 1)
  states: %{optional(String.t()) => State.t()},   # id -> state, nil ids absent
  ancestors: %{optional(String.t()) => [String.t()]}, # id -> ancestor ids, root-first
  parents: %{optional(String.t()) => State.t() | Document.t()}
}
```

Descendancy is then a `MapSet.member?`-free list lookup: `b` is a descendant of
`a` when `a` appears in `ancestors[b]`. Correctness over speed, per the bead's
design note - the compiler owns speed.

### Decisions

Every decision below is an **assumption a reviewer may overturn**. No human was
available; each records the reasoning so overturning it is cheap.

#### Decision 1 (Open Question 1): `validate/2` takes the source binary

`@spec validate(Document.t(), source :: binary()) :: {:ok, Document.t()} | {:error, [Error.t()]}`.
There is no arity-1 form.

Rationale. Check 5's "type is shallow or deep" is otherwise unimplementable
(C1): `type="sideways"` and `type="shallow"` are the same `%Document{}`. The
alternatives were (b) lowering keeps the raw string alongside the atom, which
reopens a settled layer and adds a field per enum, and (c) drop the check, which
deletes an acceptance criterion. (a) is cheapest and it generalises: the same
`Location.slice/2` call lets *any* message quote the offending text, and it is
the mechanism st-i0x (filed below) will reuse for `transition type` and
`scxml binding`.

Why no arity-1 convenience: a `validate/1` defaulting `source` to `""` would
silently disable check 5 and produce a *false negative*, which is the worst
failure mode for the only gate in the system. Every real caller has the binary -
`Statifier.Parser.parse/1` takes it, and st-dtr's `Statifier.parse/1` will
thread it through. Tests parse their own heredoc, exactly as every lowering test
already does with its local `lower!/1` helper.

Precondition, stated in the moduledoc and enforced by an `is_binary(source)`
guard: `source` must be the binary the document was parsed from. Passing a
different binary produces wrong slices, not a crash. Only check 5 reads it in
this bead, so the blast radius is one check.

#### Decision 2 (Open Question 2): check 9 tests the resolved namespace URI

Lowering gains one field: `%Statifier.Document{namespace: String.t() | nil}`,
set by `Statifier.Lowering.lower/1` from the `uri` it already computes at
`lib/statifier/lowering.ex:72` and currently discards. `Document.xmlns` is
unchanged and keeps carrying the literal attribute.

Check 9 then reads `document.namespace == Statifier.Lowering.Namespace.scxml_namespace()`.

Rationale. Testing the literal `xmlns` attribute false-positives on
`<s:scxml xmlns:s="http://www.w3.org/2005/07/scxml">`, which is spec-conformant
under 3.2.1 and which lowering already dispatches correctly. Rejecting a
document the rest of the pipeline accepts is not a defensible "stated cost" the
way st-700's was - st-700's cost was *accepting too much* for a while, which is
recoverable; this would be *rejecting valid input*, which is a bug users hit.
The fix is one field on a struct and one assignment in `lower/1`.

Reporting span for check 9, in order of preference:

1. `document.attribute_locations[:xmlns]` when the bare `xmlns` attribute was
   written (the common wrong-value case).
2. `document.location` - the `<scxml>` start tag - otherwise. This covers both
   the absent case (the bead's named fallback) and the prefixed case, where the
   offending declaration is `xmlns:s=` and has no `attribute_locations` key.
   Pointing at the start tag still puts the caret on the line that declares the
   namespace, since the declaration is inside that tag.

Naming: `namespace`, not `resolved_xmlns`, because it is the resolved URI of the
root element and reads as a property of the document rather than of an
attribute.

#### Decision 3 (Open Question 3): its own error struct, same field names, `reason` wins

`Statifier.Validator.Error`, a new struct in `lib/statifier/validator/error.ex`,
with the same three `@enforce_keys`'d fields as `Statifier.Lowering.Error`:
`reason`, `message`, `location`. A closed tagged-tuple `reason` union declared
once at the top, one named constructor per reason, messages built by the
constructor and never asserted for exact text.

Rationale for a separate struct. `Statifier.Lowering.Error`'s moduledoc calls
its union "the finished set for the whole bead"; every reason in it is
lowering's vocabulary (dispatch and placement failures); and `lower/1` never
returns a document alongside a non-empty error list, so the two lists can never
be observed together. Sharing the *shape* is what st-l5k.4 Decision 2 asked for
("so the two layers can share the shape later"), and identical field names
deliver it - a future common `Statifier.Diagnostic` protocol or behaviour can
adopt both without either layer's union leaking into the other's.

Rationale for `reason` over the bead's word "code": the repo already has two
structs (`Statifier.Lowering.Error`, `Statifier.Parser.ParseError`) that call
this field `reason`. A third name for the same concept in the same pipeline is
pure friction. The bead's "stable error code" is honoured by
`Statifier.Validator.Error.code/1`, which returns the reason tuple's tag atom -
so `code(err) == :duplicate_id` is the stable contract the acceptance criteria
ask for, while `reason` carries the offending ids as data the way the rest of
the repo does.

The reason union, declared in full in Phase 1 even though later phases add the
constructors (following `Statifier.Lowering.Error`'s own precedent):

| # | Reason | Code | Span |
|---|---|---|---|
| 1 | `{:duplicate_id, id}` | `:duplicate_id` | second and later `attribute_locations[:id]` |
| 2 | `{:unresolved_target, id}` | `:unresolved_target` | `transition.attribute_locations[:target]` |
| 3 | `{:unresolved_initial, id}` | `:unresolved_initial` | `attribute_locations[:initial]` |
| 3 | `{:initial_not_descendant, id, parent_id}` | `:initial_not_descendant` | the `initial` / target span |
| 3 | `{:initial_not_top_level, id}` | `:initial_not_top_level` | `document.attribute_locations[:initial]` |
| 3 | `{:initial_on_atomic_state, id}` | `:initial_on_atomic_state` | `attribute_locations[:initial]` or `initial_element.location` |
| 4 | `{:initial_attribute_and_element, id}` | `:initial_attribute_and_element` | `initial_element.location` |
| 4/5 | `{:transition_count, owner, count}` | `:transition_count` | `initial.location` / history `state.location` |
| 4/5 | `{:transition_missing_target, owner}` | `:transition_missing_target` | `transition.location` |
| 4/5 | `{:transition_forbidden_attribute, owner, attr}` | `:transition_forbidden_attribute` | `attribute_locations[attr]` |
| 5 | `{:history_bad_parent, id, parent_kind}` | `:history_bad_parent` | history `state.location` |
| 5 | `{:history_bad_type, raw}` | `:history_bad_type` | `attribute_locations[:type]` |
| 6 | `{:final_has_states, id}` | `:final_has_states` | the offending child `state.location` |
| 7 | `{:default_entry_not_enterable, id, child_kind}` | `:default_entry_not_enterable` | the first child's `state.location` |
| 8 | `{:donedata_not_on_final, id}` | `:donedata_not_on_final` | `donedata.location` |
| 9 | `{:bad_namespace, uri}` | `:bad_namespace` | see Decision 2 |
| 10 | `{:bad_version, version}` | `:bad_version` | `attribute_locations[:version]`, else `document.location` |

`owner` in the shared 4/5 reasons is `{:initial, state_id_or_nil}` or
`{:history, history_id_or_nil}`, so one constructor serves both and the message
still says which element it is talking about. This is the concrete payoff of
Decision 5's "one rule, one owner" split.

#### Decision 4 (Open Question 4): errors only, no warnings

`{:ok, document} | {:error, [Error.t()]}`, exactly as the bead states. No
warning list, no `:strict` option.

Rationale. Every one of the ten checks is a spec MUST. v1's four warnings are
each either a stated non-goal here (unreachable states, unreachable history,
uncompilable expressions) or an error under this bead's own wording (a
non-top-level document `initial`, which the bead phrases as a resolution
requirement, not a suggestion). That leaves a warning channel with zero
producers, which is speculative API.

st-700 assigns `:strict` (warnings-as-errors) to this bead
(`docs/plans/260808-st-700-relaxed-parsing-options.md:29`), but a
warnings-as-errors switch is meaningless while nothing warns. Decision 3's
struct shape makes adding a channel later purely additive - a
`{:ok, document, warnings}` arm or a second list needs no change to any existing
reason. Deferring costs nothing; adding an empty channel now costs a public API
shape we would have to keep.

#### Decision 5 (Open Question 5): one rule, one owner

Check 2 walks **every** transition in the document - `State.transitions` on
every kind including `:history`, and `State.initial_element.transitions` - and
owns target *existence* exclusively. Checks 3, 4 and 5 assert only the
structural rules (descendancy, count, non-null target, forbidden attributes) and
**skip descendancy for a target that check 2 already reported as unresolved**.

Rationale. The alternative (checks 4 and 5 resolve their own targets) produces
two errors on the same span for one mistake, which is exactly the error-output
quality the bead's last line calls out. Making existence one universal rule with
one owner means every unresolved target anywhere gets the same code and the same
message shape, and the structural checks read as "given it resolves, is it in
the right place".

The one thing check 2 does *not* own: `State.initial` and `Document.initial` are
IDREFS attributes, not transitions, so check 3 owns both their existence
(`:unresolved_initial`) and their descendancy. Check 2 never sees them.

Practical consequence: the transition walk is a single shared traversal in the
context builder, yielding `{transition, owner}` pairs where `owner` is
`{:plain, state}`, `{:initial, state}`, or `{:history, state}`. Checks 2, 4 and
5 all consume it.

#### Decision 6 (Open Question 6): "enterable" means "not a history pseudo-state"

Check 7 fires when a state has **no** `initial` attribute and **no**
`initial_element`, has a non-empty `states` list, and that list's **first**
element has `kind: :history`. Reason `{:default_entry_not_enterable, id, :history}`.

Rationale. Spec 3.3's fallback is "the state's first child state in document
order". Spec 3.10 makes `<history>` a pseudo-state entered only by a transition
that targets it; entering one as a default child is meaningless, and the
compiler would have to either special-case or crash on it. That is the whole
content of "enterable" at this layer.

Two things check 7 deliberately does **not** treat as errors:

- **A state with no state children at all.** That is an atomic state, which is
  legal and has no default entry to compute. The check requires a non-empty
  `states` list before it fires.
- **A first child with no `id`.** Default entry is positional, not by name, so a
  `nil` id is entirely enterable. `lib/statifier/document/state.ex:51` already
  says a nil id is not an error.

ADR-0002 compliance: the validator defines a private `compound?/1` helper
(`kind in [:state, :parallel] and states != []`) used by checks 5 and 7. It is
`defp`, module-local, and its doc comment states outright that it is a
validator-local convenience and **not** an Appendix D predicate - those live on
the Machine and this module must not be mistaken for a second home for them.

#### Decision 7 (Open Question 7): scope discipline - ten checks, six beads

This bead implements its ten checks and no more. The six representable-but-invalid
shapes with no assigned check (research C6) were filed as discovered beads,
linked `discovered-from: st-l5k.5`, labelled `area:parser`:

| Bead | Shape |
|---|---|
| **st-dje** (P2) | `<final>`'s full content model - a `:final` carrying `transitions` (st-l5k.4 Residual Note 1, named at `lib/statifier/document/state.ex:50`) |
| **st-i0x** (P2) | out-of-range enum values for `transition type` and `scxml binding` (st-l5k.4 Residual Note 2, same root cause as C1) |
| **st-6lu** (P3) | duplicate attributes on one element (st-l5k.4 Residual Note 1) |
| **st-f6k** (P3) | `<content>` with both `expr` and `text` (spec 5.6) |
| **st-hyx** (P3) | `<donedata>` with both `<content>` and `<param>` (spec 5.5; moot until `<param>` lands in Phase 3) |
| **st-2jp** (P3) | whether an explicitly written `id=""` is an error |

The closest call was st-dje. `lib/statifier/document/state.ex:58-62` names it by
name and offers two resolutions ("either check 6 widens its scope or a ninth
check appears"), and widening check 6 from "no state children" to "the 3.7
content model" is arguably within its existing spec anchor. It is filed rather
than folded in because the acceptance criteria enumerate one fixture per check
and one code per check, so widening check 6 changes what
`:final_has_states` means and what its fixture proves. **A reviewer who prefers
the widening should say so; it is a one-phase change to Phase 4 and st-dje
closes as a duplicate.**

st-i0x is deliberately narrower than it could be: Decision 1's `validate/2`
source argument is the mechanism it needs, and this bead builds that mechanism
for `<history type>`. st-i0x is then a mechanical application to two more
attributes.

#### Decision 8: where the spec is stricter than the bead, the spec wins

Three places, each stated here so the divergence from the bead's wording is on
the record rather than discovered in review.

- **Spec 3.10: a `<history>`'s transition is required, and its target is
  non-null.** The bead says "its default transition, **when present**". Check 5
  therefore imposes the same exactly-one-transition and non-null-target rules
  that check 4 imposes on `<initial>`, using the same `:transition_count` and
  `:transition_missing_target` reasons with `owner: {:history, id}`.
  `Initial.transitions` and a history state's `transitions` have the same list
  shape (`lib/statifier/document/initial.ex:20-25` says so), so the sub-check is
  literally shared.
- **Spec 3.3: `initial` MUST NOT occur on an atomic state.** Check 3 gains
  `{:initial_on_atomic_state, id}`, fired when a state carrying an `initial`
  attribute or an `initial_element` has an empty `states` list, or has a `kind`
  of `:parallel`, `:final`, or `:history`. `lib/statifier/document/state.ex:48`
  already assigns this row to check 3, so the intent existed even though the
  wording did not reach it. **When this fires for a state, check 3 skips that
  state's descendancy check** - the initial cannot be a descendant of a state
  with no descendants, and one mistake should produce one error.
- **Spec 3.6: an `<initial>`'s transition MUST specify a non-null target.**
  The bead says "has a target", which is the same rule; recorded only because
  `target: []` is ambiguous between absent and `target=""`, and the check
  resolves it as "empty list means no usable target" for both spellings.

Not adopted from the spec: **3.14's "unique within the session"**. The bead says
"across the document" and the two coincide for a single document, diverging only
once `<invoke>` spawns child sessions in Phase 3+. Document scope is what this
layer can see. Also: `nil` ids are excluded from the uniqueness set (they mean
"the author omitted an optional attribute"), and there are no synthetic
`<initial>` ids to exclude - v2 avoided v1's problem structurally
(`lib/statifier/document/initial.ex:11-14`).

#### Decision 9 (Open Question 9): `Statifier.parse/1` is not this bead's job

st-dtr ("Gives Statifier a public entry point") exists and is blocked by this
bead. `test/support/case.ex:112` keeps flunking until st-dtr lands. Nothing in
this bead's description mentions the public entry point, and composing
parse+lower+validate is a separate decision about the public surface.

#### Decision 10 (Open Question 8): the valid document is an inline heredoc

The corpus-shaped valid document lives as a `@valid_document` module attribute
in `test/statifier/validator_test.exs`, a triple-quoted heredoc with 4-space
base indentation, per CLAUDE.md's XML-in-tests convention.

Rationale. `test/fixtures/` holds only the unrelated `adr_judge` harness; every
parser and lowering test in the repo embeds its XML inline. Starting an XML
fixture-file directory is a testing-convention change that should be argued on
its own merits, not smuggled in by the first test that wants two documents.
Inline also keeps `Location.slice/2` assertions trivially correct, since the
heredoc *is* the source binary Decision 1 requires.

#### Decision 11: changelog fragment - yes

`changelog.d/st-l5k.5.md` is warranted, under `### Changed`.

The rule while v2 is unreleased is "write a fragment when v2 differs from v1"
(`changelog.d/README.md:40-50`). This bead is squarely that: v1 silently
rewrote the source string to insert `xmlns` and `version` when they were absent
(`../statifier/lib/statifier/parser/scxml.ex:76-103`) and accepted
`version="2.0"` without comment. v2 rejects both. That is different behavior for
the same input, visible to anyone who fed v1 a boilerplate-free fragment.

Re-implementing the five checks v1 already had is invisible and gets no line.

## Phase 1: Error struct, validator skeleton, shared context, check 1

### Overview

Stands up the layer end to end with one check in it, so the phase has real
behavior to gate on rather than a struct with no consumer. Establishes the
collect-all contract, the offset sort, the throwaway context, and the shared
transition walk that later phases consume.

### Changes Required

#### 1. The error struct

**File**: `lib/statifier/validator/error.ex` (new)
**Changes**: `%Statifier.Validator.Error{reason, message, location}`, all three
`@enforce_keys`'d. The complete `@type reason` union from Decision 3's table,
declared once. `code/1` returning the tag atom. Phase 1 adds only the
`duplicate_id/2` constructor; the moduledoc states, following
`Statifier.Lowering.Error`'s precedent, that later phases add constructors
rather than reopening the type.

```elixir
@spec code(reason()) :: atom()
def code(reason) when is_tuple(reason), do: elem(reason, 0)

@spec duplicate_id(id :: binary(), location :: Location.t()) :: t()
def duplicate_id(id, %Location{} = location) when is_binary(id) do
  %__MODULE__{
    reason: {:duplicate_id, id},
    message: "duplicate state id #{inspect(id)}",
    location: location
  }
end
```

**Changes**: `build/2` walks the document once, threading ancestry, and returns
`%Context{source, states, ancestors, parents, transitions}` where `transitions`

id are present in `parents`/`transitions` but absent from `states`/`ancestors`,
since nothing can name them.

Also exposes `descendant?/3` (`ancestor_id in ancestors[descendant_id]`) and the
private-to-the-layer `compound?/1` from Decision 6.

#### 3. The validator entry point

**File**: `lib/statifier/validator.ex` (new)
**Changes**: `validate/2` with an `is_binary(source)` guard. Builds the context,

#### 4. Check 1

   so it is an error.

## Phase 3: `<initial>` and `<history>` structure - checks 4 and 5

### Overview

The two elements whose whole content model is one constrained transition, sharing

### Changes Required

#### 1. The shared transition sub-check

**File**: `lib/statifier/validator/checks/default_transition.ex` (new)
**Changes**: given `owner` and a `[Transition.t()]`, reports

is the only oracle available at this layer, and closing it means changing what
lowering records, which is st-l5k.4's contract, not this bead's. `cond` needs no
oracle: it is `nil` when absent and `""` when written empty.

## Testing Strategy

### Unit Tests

Path-mirroring, `use ExUnit.Case, async: true` (**not** `Statifier.Case`, which
is reserved for the conformance corpus and still flunks at
`test/support/case.ex:112`). A local `validate!/1` helper per file that parses,
lowers, and validates a heredoc, returning the error list - mirroring the local
`lower!/1` helpers at `test/statifier/lowering/lowering_test.exs:10-18`. There is
no shared XML-to-`%Document{}` helper in the repo and this bead does not add one.

`describe` names are `"<function>/<arity> - <scenario>"`; `test` names are full
sentences. Pattern-match asserts dominate:
`assert %Error{reason: {:duplicate_id, "a"}, location: %Location{start_line: 4}} = error`
over a stack of equality asserts. Messages are asserted with `=~` only, never for
exact text, so wording stays editable
(`test/statifier/lowering/error_test.exs:22-28`).

Per the acceptance criteria, **every** error code gets an invalid fixture
asserting both the code and `location.start_line`. Counting Decision 8's
spec-driven additions, that is 17 fixtures across the six phases.

Hand-built `%Document{}` literals are used for exactly one case: the
`history_type` on a non-history kind row that lowering cannot produce
(`lib/statifier/document/state.ex:49`). That row has no check and therefore no
fixture; it is named here only so the omission is deliberate.

### Conformance Tests

None expected to move. The validator has no caller until st-dtr gives
`Statifier.parse/1` a body, so no corpus test's behavior changes. `mix test.regression`
must stay green; the internal list is globbed, so the new test files are covered
the moment they exist.

### Manual Testing Steps

1. In `iex -S mix`, parse + lower + validate the boilerplate-free fragment
   `<scxml><state id="a"/></scxml>` and read both errors. This is the gap st-700
   accepted and this bead closes - it should now be impossible to get a
   boilerplate-free fragment past the pipeline.
2. Validate the all-at-once fixture and read the report top to bottom as a
   document author would. The bead's last line is "Error output quality matters:
   these are the messages document authors see most."
3. Feed a document with an `<initial>` naming a grandchild and confirm it passes,
   then one naming a sibling and confirm it fails. This is the v1 bug
   (`initial_state_validator.ex:154-155`) and it is the single most likely place
   for a port to reintroduce it.
4. Validate a prefixed-root document and confirm check 9 is silent.

## Performance Considerations

The context is one traversal; each check is one fold over an already-built map or
list. Descendancy is a list membership test against a precomputed ancestor chain,
which is O(depth) rather than the O(states) re-flatten v1 did per target
(`../statifier/lib/statifier/validator/utils.ex`, `collect_all_states/1` +
`state_exists?/2` called once per target by each of five sub-validators).

The context is deliberately throwaway. It must **not** be returned, cached, or
handed to the compiler: st-wju.1 builds the real interned index, and sharing
would couple two layers the architecture keeps independent
(`docs/research/260807-st-l5k.2-typed-document-structs.md:460`). Correctness over
speed here, per the bead's design note.

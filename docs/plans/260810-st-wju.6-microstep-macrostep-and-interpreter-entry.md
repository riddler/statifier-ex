# Microstep, macrostep, and the interpreter entry - Implementation Plan

## Overview

Turns the pure queries st-wju.3/4/5 landed into a running machine. One new
module, `Statifier.Interpreter` (`lib/statifier/interpreter.ex`), holds the
Appendix D loop with its loop state reified onto `%Statifier.MachineState{}`
(`docs/observability.md` constraint 1, ADR-0012):

- `microstep/2` - the pseudocode's `microstep(enabledTransitions)` verbatim:
  `exitStates`, `executeTransitionContent`, `enterStates`.
- `microstep/1` - the resumable unit of progress: one selection round
  (eventless first, else dequeue one internal event) followed by `microstep/2`
  when the set is non-empty. Returns `{machine_state, [effect]}` or
  `:quiescent`. A step debugger is this function in `iex` with no support code.
- `macrostep/1` - the fold over `microstep/1` to quiescence, emitting
  `Trace.MacrostepStable`.
- `main_event_loop/1` - one iteration of the pseudocode's outer `while running`
  loop plus its trailing `exitInterpreter()` call. The iteration itself is
  driven by the caller handing in one external event per call (ADR-0003), which
  is where the external-queue divergence comment lives.
- `exit_interpreter/1` - the termination block: exit every active state in exit
  order, emit `Trace.Done` and the terminal `{:done, %Effect.Done{}}`, set
  `status: :done`.
- `initialize/2` and `handle_event/2` - the two entry points a session, a test
  harness, or an `iex` user drives the core through.

Bead: st-wju.6. No research document exists. The bead's description, its nine
acceptance criteria, and its **four** cross-bead notes (handed over from
st-wju.2, .3, .4, .5) are the specification, read alongside ADR-0002 (literal
port), ADR-0003 (pure core, one external event per call), ADR-0012 /
`docs/observability.md` (constraints 1-5), and the four landed sibling plans in
`docs/plans/`.

**A note on the word "phase".** The project roadmap numbers its own phases -
Phase 1 is the core engine (this epic, `st-wju`), Phase 3 is the datamodel
(`st-af3`), Phase 4 is sessions and invoke (`st-cmq`). This plan numbers its
five implementation phases independently. Every reference to a roadmap phase
below names the bead too; a bare "Phase N" always means a phase of *this* plan.

No human was available while this plan was written. Every question the bead left
open is settled below under "Decisions", each stated as an assumption a reviewer
may overturn; the six least settled are listed again under "Open Questions" so a
reviewer can find them without reading the whole document.

## Current State Analysis

Nothing in `lib/` drives the interpreter today. `lib/statifier/interpreter/`
holds four query modules and no loop; `lib/statifier/interpreter.ex` does not
exist. `docs/observability.md:151` still records the seam as "not yet
implemented".

  `microstep`, `trace`. `new/2` (`:157-171`), `enqueue_internal/2` (`:195`),
  `dequeue_internal/1` (`:205-211` - `{:ok, event, machine_state} | :empty`),
  `internal_events/1` (`:220`), `raise_internal/4`, `raise_platform/4`,

  its external-queue section (`:21-31`) says in as many words that "the
  `main_event_loop` port, not yet implemented, must repeat this comment where
  it matters".
- **`Statifier.Interpreter.Selection`** - `select_eventless_transitions/1`

## Desired End State

One new module and a small set of visibility and prose changes:

- `Statifier.Interpreter` (`lib/statifier/interpreter.ex`) - `initialize/2`,
  `handle_event/2`, `main_event_loop/1`, `macrostep/1`, `microstep/1`,
  `microstep/2`, `exit_interpreter/1`, all public; private helpers for the
  selection round, the transition-content pass, and the exit walk.
- `Statifier.Interpreter.ExitEntry.run_onexit_blocks/2` and `static_donedata/2`
  become public with `@doc`s (Decision 9). No behavior change.
- `Statifier.Machine.Transition.t_index` widens to `non_neg_integer() | nil`
  with a moduledoc sentence, for the synthesized initial transition
  (Decision 3).
- Prose: `lib/statifier/effect.ex`'s vocabulary table (five rows stop saying
  "not yet produced"), `lib/statifier/effect/done.ex`,
  `lib/statifier/machine_state.ex`'s three "not yet implemented" references and
  its counter contract, and `docs/observability.md:151`'s seam row.

The behavioral end state, stated so a reviewer can check it without the spec in
hand:

- **`microstep/1` is the resumable unit.** Given a machine_state it either
  returns `{machine_state, [effect]}` having made exactly one round of progress,
  or returns `:quiescent` having changed nothing at all. `:quiescent` means
  either "not running" or "no eventless transition is enabled and the internal
  queue is empty". No interpreter position ever lives on the call stack: a
  machine_state round-tripped through `:erlang.term_to_binary/1` and back
  continues identically (asserted).
- **`macrostep/1` is a fold and nothing more.** Stepping with `microstep/1`
  until `:quiescent` and folding with `macrostep/1` from the same start produce
  the same normalized position and the same effect sequence (the constraint-1
  test).
- **Counters.** `begin_macrostep/1` is called in exactly two places
  (`initialize/2`, `handle_event/2`); `begin_microstep/1` in exactly one (the
  selection round, and only when the selected set is non-empty). The
  initialization macrostep is macrostep 1; the first accepted external event is
  macrostep 2. A selection round that dequeues an internal event enabling no
  transitions does not advance `microstep`. No trace effect and no cause is
  ever stamped `microstep: 0`.
- **Trace, gated.** Seven vocabulary points now emit: `ExitSet`, `EntrySet`,
  `ContentExecuted` from st-wju.4/5, and `EventDequeued`,
  `TransitionsSelected`, `MacrostepStable`, `Done` from here. A full
  `initialize/2` plus `handle_event/2` run with `trace: false` produces **zero**
  `Effect.trace?/1` members (asserted) while its `:log` and `:done` effects are
  unchanged.
- **Initialization.** `initialize(machine, opts)` binds `:trace` and
  `:datamodel` through `MachineState.new/2`, enters the top-level initial
  states through `enter_states/2` on the initial transition (real when the
  document wrote `<initial>` under `<scxml>`, synthesized otherwise), then runs
  the initialization macrostep to quiescence. A document that stabilizes with no
  external event does so here; a document whose initial state *is* a top-level
  `<final>` terminates here, before any event, emitting `{:done, _}`.
- **Events.** `handle_event(machine_state, event)` returns
  `{:error, :not_running}` on a machine that has terminated, and otherwise
  `{:ok, machine_state, effects}`: a new macrostep, the `EventDequeued`
  (`from: :external`) trace, the external selection round, then macrostep to
  quiescence.
- **Termination.** When `enter_states/2` has set `running: false`,
  `main_event_loop/1` runs `exit_interpreter/1`: every active state in exit
  order runs its `onexit` blocks and leaves the configuration, the top-level
  final's static `<donedata>` is collected, `Trace.Done` and then exactly one
  `{:done, %Effect.Done{}}` are appended - the `:done` effect is the last member
  of the returned list - and `status` becomes `:done`.

Verification: `mix quality` green with coverage at or above the floor;
`mix gate.verify` confirming the run was full and unscoped; `mix adr.check`
clean; `test/statifier/interpreter/interpreter_acceptance_test.exs` asserting
every acceptance-criteria line a test can decide.

## What We're NOT Doing

- **No invoke passes.** The pseudocode's `for state in statesToInvoke...`,
  `statesToInvoke.clear()`, the `applyFinalize`/`autoforward` walk over the
  configuration, and `cancelInvoke` in `exitInterpreter` are all skipped with
  an inline comment naming **st-cmq**. `MachineState` deliberately has no
  `states_to_invoke` field (`machine_state.ex:33-41`) and this bead does not add
  one.
- **No external queue and no blocking wait.** `externalQueue.dequeue()` and
  `isCancelEvent/1` are skipped with an inline comment naming **ADR-0003** and
  **st-cmq**: the pure core takes one external event per call, the session owns
  the waiting ones. This is the comment st-wju.2's note requires at the port
  site.
- **No `_event`.** `datamodel["_event"] = ...` appears twice in the pseudocode
  (internal and external event) and is left as two commented seams naming
  **st-af3**, exactly where the assignment belongs. No datamodel write happens
  in this bead.
- **No datamodel initialization and no global `<script>`.** `interpret`'s
  `if doc.binding == "early": initializeDatamodel(...)` and
  `executeGlobalScriptElement(doc)` are commented seams naming st-af3.
  `MachineState.new/2` already takes a `:datamodel` option and this bead passes
  it through unchanged.
- **No donedata evaluation.** Only `{:static, term}` rides; a
  `{:compiled, _, _}` donedata becomes `nil`, reusing st-wju.4's
  `static_donedata/2` verbatim rather than writing a second one. Not a
  rescue-to-default: nothing failed, and `FeatureDetector` flunks any document
  carrying an expression.
- **No public `Statifier` facade, no `Statifier.Case` wiring, no
  `FeatureDetector` change, no ratchet movement.** That is **st-wju.7**, whose
  own title is "wires the four-function API and turns the corpus on". This bead
  stops at `Statifier.Interpreter`.
- **No `Statifier.Session`.** ADR-0003's effect interpreter is st-cmq. Effects
  are returned and nothing here interprets them.
- **No `condition_match/2` change.** Its `{:error, {:unsupported, :cond}}` stub
  is st-af3's to replace (st-wju.3's note); the selection walk already treats an
  error as not-enabling, so this bead touches neither.
- **No `Effect.Done.new/2`.** One producer (`exit_interpreter/1`), so a
  constructor would be a module to keep in sync with one call site - the same
  call st-wju.5 made for `Effect.Log`. Recorded because a reviewer may ask.
- **No changelog fragment.** Nothing here is reachable from a public API until
  st-wju.7 (`changelog.d/README.md` - most changes need none).
- **No timing, no wall clock, no delayed sends.** `<send>` with a delay is an
  effect st-cmq interprets; nothing in this bead reads a clock.
- **No `microstep/1` pause point between select and enter.** st-wju.2's
  Decision 11 fixes pause granularity at whole microsteps and says adding a
  `current_event` field later is additive. This port does not need one
  (Decision 4), so the field is not added.

## Implementation Approach

Five phases, in dependency order, each landing code together with its own tests
so no phase leaves an untested function behind to sink the coverage floor. The
split is along the algorithm's own boundaries, and each phase's behavior is
directly testable from a machine_state built with the tools the previous phases
(and st-wju.4) already provide:

1. **`microstep/2` and `microstep/1`** - the literal port and the resumable
   round, with the `EventDequeued` and `TransitionsSelected` traces and the
   `begin_microstep/1` call. Testable by hand: enter a configuration with
   `ExitEntry.enter_states/2`, then call `microstep/1`.
2. **`macrostep/1`** - the fold, plus `Trace.MacrostepStable`. Adds quiescence
   and nothing else; termination is still just "the fold stops".
3. **`main_event_loop/1` and `exit_interpreter/1`** - the outer-loop body, the
   three skipped passes with their comments, the exit walk, `Trace.Done`, the
   terminal `{:done, _}`, and `status: :done`. Carries the two ExitEntry
   visibility changes.
4. **`initialize/2` and `handle_event/2`** - the entry points, the
   `begin_macrostep/1` calls, the synthesized initial transition, and the
   `{:error, :not_running}` shape.
5. **The acceptance test, the prose sweep, and the cross-bead notes** - the
   constraint-1 resumability test, the trace-off assertion, the counter-writer
   assertions, and every "not yet implemented" line this bead makes false.

Each phase is independently committable and gate-verifiable: no phase adds a
function that only a later phase calls, and no phase leaves a partially wired
call site. Phases do not parallelize across worktrees; `docs/workflow.md`'s
parallelism is across beads, and every phase here edits the same module.

Every design question is settled below before any code is written, because
st-wju.7 wires the corpus onto these exact signatures.

## Decisions

**Decision 1 - `microstep` has two arities: `/2` is the literal port, `/1` is
the resumable round.**

```elixir
@spec microstep(machine_state :: MachineState.t()) ::
        {MachineState.t(), [Effect.t()]} | :quiescent
def microstep(machine_state)

@spec microstep(machine_state :: MachineState.t(), enabled_transitions :: [Transition.t()]) ::
        {MachineState.t(), [Effect.t()]}
def microstep(machine_state, enabled_transitions)
```

The bead and `docs/observability.md:39-40` both specify
`microstep(machine_state) -> {machine_state, [effect]} | :quiescent`. Appendix D
specifies `microstep(enabledTransitions)`, whose body is exactly
`exitStates`/`executeTransitionContent`/`enterStates` - the selection lives one
level up, in `mainEventLoop`'s inner loop. Naming only one of the two
`microstep` would either break the literal port (ADR-0002) or break the
observability constraint.

Two arities satisfy both with no invented name. `microstep/2` is the pseudocode
function, diffable line for line. `microstep/1` is `mainEventLoop`'s inner-loop
*body* hoisted into a named function so a paused position is a value rather than
a stack frame - which is the mechanical deviation `docs/observability.md:43-45`
sanctions and ADR-0002 requires a comment for. Both `@doc`s say which is which
in their first line, so a reader diffing against the spec is never in doubt.

**Decision 2 - `:quiescent` is a bare atom, and a `:quiescent` round changes
nothing.**

`microstep/1` returns `:quiescent` when either `running` is `false` or no
eventless transition is enabled *and* the internal queue is empty. Both tests
are made before any mutation, so there is no machine_state to hand back and none
is lost: the caller's own machine_state is still current. This is the property
that makes the fold a two-line function and the debugger loop
`while microstep(ms) != :quiescent`.

The one consequence, recorded because it is a visible deviation from
`docs/observability.md:64`'s "transitions selected (includes the empty set)": the
*terminal* eventless probe of a macrostep - the one that finds nothing and then
finds an empty queue - emits no `TransitionsSelected`, because the round it
belongs to produces no effect list. Every other selection, including an
eventless probe that comes back empty while the queue still has events, does
emit one with `t_indexes: []`. Quiescence at that exact point is recorded by
`Trace.MacrostepStable`, stamped with the same counters, so no information is
lost - only the vocabulary row that carries it changes. Inline comment at the
site.

**Decision 3 - the initial transition is synthesized when the document wrote no
`<initial>` element, and `Transition.t_index` widens to allow `nil`.**

```elixir
# `expandScxmlSource(doc)` (Appendix D's own normalization step) is what gives a
# document an `<initial>` element where it wrote none; this is that step, done
# lazily for the root only. ADR-0002 mechanical deviation: a synthesized
# transition is not a document element, so it has no `t_index`.
defp initial_transition(%Machine{} = machine) do
  case Machine.at(machine, 0).initial_transition do
    nil ->
      %Transition{
        t_index: nil,
        source: 0,
        targets: Machine.initial(machine),
        events: [],
        type: :external,
        content: [],
        location: machine.location
      }

    t_index ->
      Machine.transition(machine, t_index)
  end
end
```

`interpret` calls `enterStates([doc.initial.transition])`, and the spec's own
`expandScxmlSource` is defined as normalizing a document by adding the
`<initial>` elements it left implicit - so synthesizing here is the spec's step,
not an invention. A root that *did* write `<initial>` yields the compiler's real
transition, with its real `t_index` and its content.

`t_index: nil` is a one-line type widening on a landed struct
(`non_neg_integer() | nil`) with a moduledoc sentence. Blast radius, checked by
reading every consumer: `Selection`'s `Enum.uniq_by(& &1.t_index)` never sees
this transition (it is never selected); `Trace.TransitionsSelected` never names
it for the same reason; `ExitEntry` reads only `source`, `targets`, `type`, and
`content`; `Content.owner()`'s `{:transition, t_index}` is only built for a
non-empty content block and this transition's is `[]`. The alternative - a fake
index one past the end of `machine.transitions` - would make `Machine.transition/2`
raise on an index a trace effect had published, which is worse than an honest
`nil`.

Note what this does **not** do: the root is entered through
`add_ancestor_states_to_enter/4` (its targets' ancestor walk with a `nil`
domain), never through `add_descendant_states_to_enter/3`, so the root is not
flagged in `states_for_default_entry` and a written root `<initial>`'s content
does **not** run on initialization. That is the pseudocode's own behavior -
`enterStates` runs `s.initial.transition`'s content only for members of
`statesForDefaultEntry` - and is ported as written.

**Decision 4 - the microstep boundary stays whole; no `current_event` field.**

st-wju.2's Decision 11 predicted this and asked the port to revisit if it found
it needed to pause between select and enter. It does not: `microstep/1` selects
its own transition set and consumes it within the same round, and the external
event handed to `handle_event/2` is consumed by that macrostep's first selection
round. At every `microstep/1` boundary no event is in flight. The field stays
absent, and the decision is re-confirmed rather than re-argued.

**Decision 5 - the counters.**

- `begin_macrostep/1` in exactly two places: `initialize/2` (macrostep 1) and
  `handle_event/2` after the not-running guard (macrostep 2 onward). A rejected
  event advances nothing.
- `begin_microstep/1` in exactly one place: the private selection-round helper,
  and only on the non-empty branch, immediately before `microstep/2` runs. A
  whole block therefore runs at one stamp, which is st-wju.5's note's
  requirement.
- **The initial entry is microstep 1**, not 0: `initialize/2` calls
  `begin_microstep/1` before `enter_states/2`. The pseudocode's
  `enterStates([doc.initial.transition])` is not inside `microstep`, so a purely
  positional reading would leave it at 0 - but st-wju.2's counter contract
  justifies the "no advance" rule with "*no exit or entry happened*", and an
  entry happens here. Taking that justification at its word yields the stronger
  and more useful invariant: **no effect and no cause is ever stamped
  `microstep: 0`**, so `0` keeps meaning exactly what the contract says it means
  ("no step has begun") and never doubles as a real step number. Asserted by a
  test over a full run.
- Selection-phase trace effects (`EventDequeued`, `TransitionsSelected`) are
  stamped *before* `begin_microstep/1`, so their `microstep` is the number of
  microsteps **completed** in this macrostep so far. This is forced rather than
  chosen: the counter cannot be advanced before the selection result is known,
  because an empty result must not advance it. Stated in the module's counter
  docs, which is the bead's "microstep-vs-selection-round decision written in
  the counter docs" criterion.

**Decision 6 - `main_event_loop/1` is one iteration of the outer loop plus the
trailing `exitInterpreter()`.**

```elixir
@spec main_event_loop(machine_state :: MachineState.t()) ::
        {MachineState.t(), [Effect.t()]}
def main_event_loop(machine_state)
```

The pseudocode's `mainEventLoop` is `while running:` over macrosteps, each
iteration ending in a blocking `externalQueue.dequeue()`. This core takes one
external event per call (ADR-0003) and the session owns the waiting ones
(st-cmq), so the `while` is driven by the caller: one call of `initialize/2` or
`handle_event/2` performs one iteration. `main_event_loop/1` is that iteration's
tail - macrostep to quiescence, then the post-loop `exitInterpreter()` when
`running` went false - and it is the site that carries the external-queue
divergence comment st-wju.2's note requires, verbatim in substance:

```elixir
# ADR-0002 mechanical deviation, ADR-0003. Appendix D's `mainEventLoop` owns
# both queues and blocks on `externalQueue.dequeue()` at the end of every
# iteration. This core takes one external event per call, so the outer `while
# running` loop is driven by the caller (`handle_event/2`) and the waiting
# external events live in the session (st-cmq). The semantics of processing one
# external event are unchanged; only the storage of the waiting ones moves
# outward. `isCancelEvent/1` moves out with them.
```

The two invoke passes and `statesToInvoke.clear()` are skipped here with their
own comment naming st-cmq, in the exact position the pseudocode puts them
(between quiescence and the external wait), so a later bead fills in a gap
rather than rediscovering a location. The pseudocode's `if not internalQueue.isEmpty(): continue`
guard after invoking is skipped with the same comment: it exists only because
invoking can raise internal events, and nothing invokes yet.

**Decision 7 - `macrostep/1` is public, and emits `Trace.MacrostepStable` only
when the fold ended in quiescence rather than in termination.**

The bead permits the fold to start private "but it must be trivially
publishable". Publishing it now costs one `@doc` and is what the constraint-1
acceptance test drives, so it is public from the start. `macrostep/2` (the
accumulator) is private.

`Trace.MacrostepStable`'s own moduledoc says it is emitted "when the
configuration reaches quiescence, i.e. the macrostep's microstep loop has no
more eventless transitions or internal events to drain". A fold that ended
because `running` went false did not reach quiescence - it terminated - and
`Trace.Done` is that event's vocabulary row. So `macrostep/1` reads `running`
after the fold and emits the stable trace only when it is still true. The two
trace effects are therefore mutually exclusive per macrostep, which is a
testable property and the one a timeline UI wants.

Both `macrostep/1` and `macrostep/2` carry an ADR-0002-citing comment directly
above the `def`, because the name scores 0.926 Jaro against the canonical
`microstep` and `mix adr.check` would otherwise report it as a re-derivation
(verified against the guard's own algorithm). The comment says the true thing:
`macrostep` is not a pseudocode function name at all - it is
`docs/observability.md`'s vocabulary for `mainEventLoop`'s inner
`while running and not macrostepDone` loop, hoisted into a fold so a paused
position is a value.

**Decision 8 - the entry-point shapes are asymmetric, and only the one that can
fail is tagged.**

```elixir
@spec initialize(machine :: Machine.t(), opts :: keyword()) ::
        {MachineState.t(), [Effect.t()]}

@spec handle_event(machine_state :: MachineState.t(), event :: Event.t()) ::
        {:ok, MachineState.t(), [Effect.t()]} | {:error, :not_running}
```

`initialize/2` cannot fail: a `%Machine{}` is valid by construction
(`docs/architecture.md:34-37`), so an `{:ok, _, _}` wrapper would be a tag with
one possible value and would put `{:ok, _, _} =` noise at every call site. It
returns the same untagged pair `microstep/2`, `macrostep/1`, `main_event_loop/1`,
`exit_states/2`, and `enter_states/2` all return.

`handle_event/2` has a real error case, so it takes CLAUDE.md's
`{:ok, v} | {:error, e}` form. The guard matches on `%MachineState{running: false}` -
Appendix D's own flag, so the clause reads as the pseudocode's loop condition -
and the reason atom is `:not_running`. `running` and `status` disagree only
inside `exit_interpreter/1`, which never returns mid-flight, so at any
caller-visible boundary the guard and `status: :done` name the same machines.

**Decision 9 - `ExitEntry.run_onexit_blocks/2` and `static_donedata/2` become
public rather than being duplicated.**

`exitInterpreter`'s per-state body is `for content in s.onexit: executeContent(content)`
followed by `configuration.delete(s)`, and its final line is
`returnDoneEvent(s.donedata)`. Both pieces already exist in `ExitEntry` as
private helpers, ported and tested. Re-implementing them in
`Statifier.Interpreter` would be a second copy of the `{:onexit, state_index,
ordinal}` owner convention and a second `<donedata>` folding rule to keep in
sync with st-af3's evaluation work - exactly the "parallel summary function"
failure `docs/architecture.md:101-105` names. Promoting them to public with
`@doc`s is additive, changes no behavior, and keeps both spec rules in the
module that owns exit and entry.

`exit_interpreter/1` itself lives in `Statifier.Interpreter`, not in `ExitEntry`:
it is a loop function (`interpret`'s counterpart to `mainEventLoop`), it emits
the terminal effects, and it sets `status`. `ExitEntry` owns what the exit and
entry *blocks* do; the interpreter owns when the machine stops.

**Decision 10 - `exit_interpreter/1`'s shape.**

```elixir
def exit_interpreter(%MachineState{machine: machine} = machine_state) do
  configuration_at_exit = machine_state.configuration
  states_to_exit = Machine.exit_order(machine, machine_state.configuration)
  # fold: onexit blocks, delete from configuration, collect top-level donedata
  ...
end
```

Five details, each ported deliberately:

1. **No history recording.** The bead's description says "no history recording
   matters anymore but the pseudocode records anyway - port as written".
   Appendix D's `exitInterpreter` has no history-recording loop at all - unlike
   `exitStates`, which has two consecutive `for s in statesToExit` loops for
   exactly that purpose. "Port as written" therefore resolves to recording
   nothing. Flagged in Open Questions because the bead's phrasing implies the
   opposite; the pseudocode is the tiebreaker ADR-0002 names.
2. **`cancelInvoke` skipped**, comment naming st-cmq.
3. **`returnDoneEvent(s.donedata)`** fires for a state that is `final?/2` with
   `parent == 0` - the pseudocode's `isFinalState(s) and isSCXMLElement(s.parent)`,
   the same test `raise_completion_events/2` already makes
   (`exit_entry.ex:720-732`). The donedata is `ExitEntry.static_donedata/2`'s
   value. Since the root is compound, at most one of its children is active, so
   at most one top-level final is in the exit set - the "emitted exactly once"
   criterion holds by construction, and a test pins it.
4. **The terminal effects come last, `{:done, _}` last of all.** The exit walk's
   own effects (onexit `:log`s, `ContentExecuted` traces), then `Trace.Done`,
   then `{:done, %Effect.Done{}}`. "The `:done` effect is the final member of
   the effect list" is then a property a consumer can rely on and a test can
   assert. The pseudocode calls `returnDoneEvent` mid-walk; moving the emission
   to the end is a mechanical deviation (effects are a returned list, not an
   I/O call) with an inline comment, and it changes no order that is observable
   in the pseudocode's own terms.
5. **`Trace.Done.configuration` is captured before the walk.** Its `@doc` says
   "the configuration as it stood at exit"; after the walk it is empty, which
   would make the field useless. `Effect.Done` carries no configuration, so
   there is nothing to keep consistent with.

`status: :done` is set at the end, which is the window
`machine_state.ex:43-56` describes: `running: false` from top-level final entry
until `exit_interpreter/1` finishes, then `status: :done`.

**Decision 11 - `executeTransitionContent` is a named private helper and
iterates the enabled set in the order it arrives.**

```elixir
# `executeTransitionContent(enabledTransitions)` (Appendix D) - each enabled
# transition's own content block, through the same block runner every other
# content site uses. The pseudocode iterates `enabledTransitions` in the order
# it was given; selection already produced them in the document order of the
# states that selected them (`Selection.select_transitions/2`'s own `@doc`), so
# there is nothing to sort here.
defp execute_transition_content(machine_state, enabled_transitions)
```

The bead says "execute the enabled transitions' content in document order"; the
pseudocode says iterate the list. These agree, because the list *is* in the
document order of the selecting states and `remove_conflicting_transitions/2`
only removes from it. Porting the iteration and stating why is more literal than
adding a sort the pseudocode does not have.

Owner is `{:transition, t.t_index}` through
`Statifier.Interpreter.Content.execute_block/3`, which short-circuits on an
empty block, so a targetless or content-free transition costs one list match.

**Decision 12 - the selection round is one private helper shared by the internal
and external paths.**

```elixir
# The `if not enabledTransitions.isEmpty(): microstep(...)` tail shared by all
# three of the pseudocode's selection sites (eventless, internal event,
# external event), factored so `begin_microstep/1` has exactly one call site
# (the counter contract, `Statifier.MachineState`).
defp run_selected(machine_state, transitions, event)
```

It emits `Trace.TransitionsSelected` (with `t_indexes:
Enum.map(transitions, & &1.t_index)` per st-wju.3's note, and `event:` the
matched event or `nil` for an eventless round), then on a non-empty set calls
`begin_microstep/1` and `microstep/2`. Factoring it is what makes "counters
advance in exactly one place each" a grep-checkable fact rather than a review
promise, and the `Effect.trace/3` gate keeps the `Enum.map/2` unevaluated when
tracing is off.

**Decision 13 - the machine_state returned by selection is threaded, never
discarded.** st-wju.3's note asks for this explicitly. Both
`Selection.select_transitions/2` and `select_eventless_transitions/1` are
destructured as `{machine_state, transitions}` and the returned machine_state is
what the round continues with, so st-af3's `error.execution`-on-failed-`cond`
enqueue lands as a body change in `condition_match/2`'s caller and not a
signature change anywhere. A test pins that the machine_state comes back
unchanged today, so the day it stops is a deliberate edit.

## Phase 1: Ports microstep, the literal one and the resumable one

### Overview

`Statifier.Interpreter` with `microstep/2` (the pseudocode function) and
`microstep/1` (one selection round), the `EventDequeued` and
`TransitionsSelected` trace emissions, and the single `begin_microstep/1` call
site.

### Changes Required:

#### 1. The module

**File**: `lib/statifier/interpreter.ex` (new)
**Changes**: the module, its moduledoc, and four functions.

The moduledoc is the map of the loop: which function ports which pseudocode
block; the constraint-1 statement that any `%MachineState{}` is a complete,
resumable position and that this module keeps nothing on the stack; the counter
docs of Decision 5 (including the microstep-versus-selection-round rule and the
"never stamped `microstep: 0`" invariant); and a list of the deviations with
their reasons, each of which also appears inline at its site.

```elixir
@doc """
`microstep(enabledTransitions)` (Appendix D) - exit, run the transitions' own
content, enter. ...
"""
@spec microstep(machine_state :: MachineState.t(), enabled_transitions :: [Transition.t()]) ::
        {MachineState.t(), [Effect.t()]}
def microstep(%MachineState{} = machine_state, enabled_transitions) do
  {machine_state, exit_effects} = ExitEntry.exit_states(machine_state, enabled_transitions)
  {machine_state, content_effects} = execute_transition_content(machine_state, enabled_transitions)
  {machine_state, enter_effects} = ExitEntry.enter_states(machine_state, enabled_transitions)

  {machine_state, exit_effects ++ content_effects ++ enter_effects}
end
```

## Phase 2: Folds microsteps to quiescence

### Overview

`macrostep/1` - the fold over `microstep/1` - plus `Trace.MacrostepStable`.
After this phase a machine driven by hand drains its eventless transitions and
its internal queue in one call.

### Changes Required:

#### 1. The fold

**File**: `lib/statifier/interpreter.ex`
**Changes**: `macrostep/1` (public) and `macrostep/2` (private accumulator) per
Decision 7, each with an ADR-0002-citing comment directly above the `def`
because the name is a 0.926 near-miss on the canonical `microstep` and
`mix adr.check` would otherwise report it.

```elixir
# ADR-0002: `macrostep` is not an Appendix D function name. It is
# docs/observability.md's vocabulary for `mainEventLoop`'s inner
# `while running and not macrostepDone` loop, hoisted into a fold over
# `microstep/1` so that a paused position is a value on `%MachineState{}`
# rather than a stack frame (constraint 1). Mechanical, not semantic: the
# loop's condition and body are unchanged.
def macrostep(%MachineState{} = machine_state) do
  {machine_state, effects} = macrostep(machine_state, [])

  stable =
    if machine_state.running do
      Effect.trace(machine_state, Effect.Trace.MacrostepStable,
        configuration: machine_state.configuration
      )
    else
      []
    end

  {machine_state, effects ++ stable}
end
```

The `@doc` states the two ways the fold ends (quiescence, termination), that
only the first emits `MacrostepStable`, and that `macrostep/1` is deliberately
public so a stepper and the fold are the same code path.

## Testing Strategy

### Unit Tests:

Four new test files under `test/statifier/interpreter/`, one per phase of
behavior, plus the acceptance file:

- `microstep_test.exs` - `microstep/1` and `/2`, the selection round, the
  `EventDequeued`/`TransitionsSelected` traces, the counter cases.
- `macrostep_test.exs` - the fold, eventless retry after every microstep,
  internal-queue drain, `MacrostepStable`.
- `termination_test.exs` - `main_event_loop/1`, `exit_interpreter/1`, the
  terminal effects, `status`.
- `entry_test.exs` - `initialize/2`, `handle_event/2`, the counter values, the
  error shape, the three initial-transition shapes.
- `interpreter_acceptance_test.exs` - the bead's own criteria.

Key edge cases, each with a named test: an internal event that enables nothing
(consumed, no microstep); a macrostep that terminates mid-fold (no
`MacrostepStable`); an initial state that is a top-level final (termination
before any event); a `<history>` value untouched by `exit_interpreter/1`; a
transition with no content (no block, no `ContentExecuted`); an external event
matching nothing (accepted, counter advanced, configuration unchanged); a root
whose initial transition is synthesized versus written.

Fixtures follow the landed convention: `compile!/1` over a triple-quoted heredoc
at 4-space base indentation through the real `Parser -> Lowering -> Validator ->
Compiler` pipeline, preceded by a hand-drawn document-order index comment, with
a pinned `@indexes` map so assertions read in ids rather than integers. No
`%Machine{}` literal ever: the machine always comes from the real pipeline.

A starting *position* is planted one of three ways, in this order of
preference:

1. `initialize/2` (Phase 4 onward, and every test in Phase 5) - the honest
   entry point, and the only one that exercises the initial-entry path.
2. `ExitEntry.enter_states/2` on a document's own transition - when the test is
   about entry from a real transition.
3. The landed `machine_state/2` helper,
   `%{MachineState.new(machine, opts) | configuration: MapSet.new(indexes)}`
   (`selection_acceptance_test.exs:150-152`,
   `exit_entry_enter_test.exs:155-160`) - for an arbitrary mid-document
   configuration neither of the above can reach. Phases 1-3 depend on this one,
   since `initialize/2` does not exist until Phase 4. The planted set is always
   a **full** configuration, ancestors included (ADR-0005).

Position comparisons never use `==` on two `%MachineState{}` values (st-wju.2's
note on `:queue` structural inequality); they compare a normalized view of
`configuration`, `MachineState.internal_events/1`, `history_values`, `macrostep`,
`microstep`, `status`, and `running`.

Every test asserting `lib/` behavior carries its sabotage line per
`docs/testing.md:78-134`.

## Performance Considerations

- **Effect accumulation appends.** `effects ++ new_effects` per round and per
  fold iteration, matching `ExitEntry` and `Content`. Quadratic in the number of
  microsteps per macrostep, which is single digits for every corpus document. If
  a pathological document ever makes it measurable, the fix is a
  prepend-and-reverse inside `macrostep/2` alone, with a mechanical-reason
  comment - the shape is deliberately confined to one private function for that
  reason.
- **Trace off allocates nothing.** `Effect.trace/3` reads one boolean and
  returns `[]` without evaluating its `fields`, so no `t_index` list, no
  configuration copy, and no payload struct is built for any of this bead's four
  trace points when tracing is off. This is asserted rather than assumed: a
  named test pins zero trace members over a full run.
- **`Selection.select_eventless_transitions/1` runs once per microstep**,
  including the terminal probe that finds nothing. That is the pseudocode's own
  loop and is what "eventless retried after every microstep" means; it is not an
  inefficiency to optimize away, and doing so would be the fused loop
  `docs/observability.md:41-42` forbids.
- **`MachineState.active_leaf_states/1` is `O(configuration)`** and is called
  once per selection walk by `Selection` (its own `@doc` warns it is not meant
  for a per-microstep path). This bead does not add a call; noted so a later
  profiler knows where to look before anyone re-derives the observation.
- **`exit_interpreter/1` is O(configuration)** and runs once per machine
  lifetime.

## Appendix D Deviations

Per ADR-0002 and `.claude/wurk/plan.md`'s Appendix D rule, these are the only
deviations this bead makes to the pseudocode. Every one is mechanical, and every
one carries an inline comment at its site:

1. **Loop state moves onto the struct.** `mainEventLoop`'s locals
   (`enabledTransitions`, `macrostepDone`, the current event, the queue
   position) are either reified on `%MachineState{}` or become a return value.
   `docs/observability.md:43-45` sanctions exactly this; the pseudocode's
   functions still map one to one. This is the deviation that makes a paused
   position a value.
2. **`microstep` gains a second arity.** `microstep/2` is the pseudocode
   function; `microstep/1` is the inner-loop body hoisted so it can be stepped
   (Decision 1). No semantic content moves between them.
3. **The outer `while running` loop is driven by the caller** (Decision 6).
   ADR-0003: the pure core takes one external event per call and the session
   owns the waiting ones, so `externalQueue.dequeue()` and `isCancelEvent` move
   outward. The semantics of processing one external event are unchanged. This
   is the divergence `lib/statifier/machine_state.ex:21-31` instructs this port
   to comment at its site.
4. **The invoke passes are skipped** - the two `statesToInvoke` loops,
   `statesToInvoke.clear()`, the post-invoke `internalQueue` re-check, the
   `finalize`/`autoforward` walk, and `cancelInvoke` in `exitInterpreter`. Each
   carries a comment naming st-cmq. Nothing in this core can invoke, so nothing
   is skipped that could have fired.
5. **`datamodel["_event"] = ...` is not written** (both sites), and
   `interpret`'s early-binding datamodel initialization and
   `executeGlobalScriptElement` are not run. Commented seams naming st-af3. A
   deferral, not a divergence: no document that could observe `_event` is
   executable today.
6. **Effects are returned rather than performed.** `returnDoneEvent(s.donedata)`
   becomes the `{:done, %Effect.Done{}}` effect, and it is appended at the end of
   `exit_interpreter/1` rather than emitted mid-walk (Decision 10 item 4).
   ADR-0003.
7. **Four gated trace effects are added** - `EventDequeued`,
   `TransitionsSelected`, `MacrostepStable`, `Done`. Not in the pseudocode at
   all; they are ADR-0012 constraint 2's remaining rows, and they are inert when
   `trace: false`. The one place the vocabulary is not emitted where constraint 2
   would have it - the terminal eventless probe - is Decision 2, commented at its
   site.
8. **The initial transition is synthesized when the document wrote no
   `<initial>` element** (Decision 3). This is the spec's own
   `expandScxmlSource(doc)` normalization, done lazily for the root, rather than
   an addition to it.
9. **Step counters advance** where the pseudocode counts nothing (Decision 5).
   ADR-0012 constraint 4. They are read by trace payloads and causes and by
   nothing that decides behavior, so no branch depends on a counter.

Nothing here alters which transitions fire, which states are exited or entered,
in what order content runs, what goes on the internal queue, or when the machine
stops.

## Open Questions

No human was available while this plan was written, so nothing here blocks
implementation: every question below is settled in the Decisions section and the
assumption is recorded so a reviewer can overturn it cheaply. These six are the
ones most worth a second opinion.

1. **Decision 10 item 1 - `exit_interpreter/1` records no history.** The bead's
   description says "no history recording matters anymore but the pseudocode
   records anyway - port as written". Appendix D's `exitInterpreter` has no
   history-recording loop; only `exitStates` does, and it has two consecutive
   `for s in statesToExit` loops precisely because of it. "Port as written" is
   therefore read here as "record nothing", and the bead's phrasing is read as a
   slip. This is the single place where this plan contradicts a literal sentence
   of the bead, which is why it is first. If a reviewer intends the recording,
   it is a five-line reuse of `ExitEntry`'s existing first pass - but it would be
   a deviation *from* the pseudocode rather than toward it, and would need its
   own ADR-0002 comment.
2. **Decision 5 - the initial entry is microstep 1, not microstep 0.**
   Positionally, `enterStates([doc.initial.transition])` is outside `microstep`,
   which argues for 0. st-wju.2's counter contract justifies its "no advance"
   rule with "no exit or *entry* happened", which argues for 1, and 1 buys the
   invariant that nothing is ever stamped `microstep: 0`. A reviewer who prefers
   0 changes one line in `initialize/2` and one assertion; every trace consumer
   then has to treat `microstep: 0` as both "not started" and "the initial
   entry".
3. **Decision 2 - the terminal eventless probe emits no `TransitionsSelected`.**
   `docs/observability.md:64` says the row fires whenever `select_transitions`
   returns, "includes the empty set". A `:quiescent` return has no effect list to
   carry it, and `MacrostepStable` marks the same instant with the same counters.
   The alternative is changing `:quiescent` into
   `{:quiescent, machine_state, effects}`, which costs the fold's two-line shape
   and the debugger's `!= :quiescent` idiom. The bead explicitly leaves the shape
   to this plan, so both readings are in bounds.
4. **Decision 1 - `microstep` at two arities.** It satisfies both the bead's
   `microstep(machine_state)` and Appendix D's `microstep(enabledTransitions)`
   with no invented name, but a reader who does not notice the arity could
   mistake one for the other. The alternative is naming the resumable one
   something like `step/1`, which reads clearly but no longer matches the
   signature `docs/observability.md` and the bead both write down. Reversing is a
   rename.
5. **Decision 3 - `Transition.t_index` widens to allow `nil`.** It is a type
   change to a struct three landed beads reference, made for exactly one
   synthesized value that never reaches selection, a trace payload, or a content
   owner. The alternatives are a fake index one past the end of
   `machine.transitions` (which would make `Machine.transition/2` raise on an
   index that had been published) or synthesizing the root's initial transition
   in the compiler (st-wju.1 territory, and a larger change). If a reviewer
   prefers the compiler route, Decision 3's helper disappears entirely.
6. **Decision 8 - the entry points have asymmetric return shapes.**
   `initialize/2` is untagged because it cannot fail; `handle_event/2` is tagged
   because it can. st-wju.7 wraps both, so a reviewer who wants uniformity at
   that boundary should say so now: making `initialize/2` return
   `{:ok, machine_state, effects}` is a one-line change here and a smaller diff
   than doing it after st-wju.7 encodes against it.

# Generic DOM with Source Locations Implementation Plan

## Overview

Build the first arrow of the parser pipeline: XML string -> generic DOM node
(`name`, `attributes`, `children`, `location`), with a source location on every
node and no SCXML-specific clause anywhere in the handler. No lowering.

Beads issue: `st-l5k.3`. Source research:
`docs/research/260807-st-l5k.3-sax-dom-source-locations.md`.

The hard part is locations. Saxy 1.6.1 passes handlers no position data at all,
so positions have to be produced alongside the event stream. This plan settles
that mechanism and the eight other open questions the research doc left, then
sequences the work into three phases that each end on a green gate.

## Current State Analysis

### What exists

- `lib/` is greenfield for parsing. `lib/statifier.ex` is the only library
  module outside `lib/mix/`. There is no `lib/statifier/parser/`.
- Saxy is already a runtime dependency (`mix.exs:42`, pinned to `1.6.1` in
  `mix.lock`) and vendored in `deps/saxy`. Nothing consumes it yet.
- `test/support/case.ex:118` still flunks on `Statifier.parse/1`; wiring that is
  st-wju.7, not this bead. This bead's tests are internal unit tests under
  `test/statifier/parser/`, which `test/passing_tests.json` globs into the
  regression ratchet the moment they are written.

### Verified Saxy behavior

Probed against the vendored 1.6.1 in this worktree, not assumed:

| Input | Result |
|---|---|
| `<!-- c -->` | no event of any kind |
| `x="1&amp;2"` | `{"x", "1&2"}` - attribute values arrive **entity-expanded** |
| `t1 &amp; t2<![CDATA[cd]]>t3` | **three** `:characters` events: `"t1 & t2"`, `"cd"`, `"t3"` |
| `<b/>` | `:start_element` **and** `:end_element` |
| `{:stop, term}` from a handler | `Saxy.parse_string/3` returns `{:ok, term}` |
| `<a><b></c></a>` | `{:error, %Saxy.ParseError{reason: {:wrong_closing_tag, "b", "c"}, position: 10}}` |
| `<a` | `{:error, %Saxy.ParseError{reason: {:token, :name_start_char}, position: 2}}` |
| `encoding="ISO-8859-1"` | `{:error, %Saxy.ParseError{reason: {:invalid_encoding, "ISO-8859-1"}, position: 30}}` |
| `&foo;` | expands to the literal `"&foo;"` in `:characters` - unknown entities are kept, never markup |

Three consequences that shape the design: character data must be **coalesced**
across events; `{:stop, ...}` is a clean abort channel that never produces a
`{:bad_return, ...}` error; and `position` in `Saxy.ParseError` is a **byte
offset**, not a line/column.

### Constraints

- `docs/architecture.md` "Parser: DOM first, then lowering" fixes the node field
  set and states that locations are a property of every node.
- ADR-0012 item 3 / `docs/observability.md` Constraint 3: locations must survive
  to the Machine. The DOM is the origin, so what it records bounds what any
  downstream diagnostic can say.
- ADR-0014: expression spans are LSP-style with **exclusive ends**, and they are
  relative to an expression string that lives inside an attribute value.
  Translating one into a document position requires knowing where that value
  starts.
- Design principle 4: the DOM is deliberately **not** validated. It is whatever
  the XML said. A DOM that rejected or normalized anything would be doing the
  validator's job.
- `docs/testing.md`: every test asserting `lib/` behavior carries a sabotage
  line. Coverage floor is 90% (`coveralls.json`).

## Desired End State

`Statifier.Parser.parse/1` takes a binary and returns
`{:ok, %Statifier.Parser.DOM.Element{}}` or
`{:error, %Statifier.Parser.ParseError{}}`, never raises, and:

- every element and text node carries a `%Statifier.Parser.Location{}` span with
  1-based line/column, 0-based byte offsets, and an exclusive end;
- every attribute carries both its full `name="value"` span and a separate span
  for the value text inside the quotes;
- element order, text content, and whitespace are preserved verbatim;
- element and attribute names are exactly the bytes Saxy reported, with no
  namespace resolution;
- malformed XML returns `{:error, %ParseError{}}` carrying the failing byte
  offset converted to a line/column, tolerating a missing position;
- no module under `lib/statifier/parser/` mentions any SCXML element name - a
  test enforces this mechanically.

Verify with: `mix quality` green, and the location-accuracy sweep in Phase 3,
which slices each node's span back out of the source and asserts it starts with
`<name`.

### Key Discoveries

- `deps/saxy/lib/saxy/handler.ex` - the complete event contract; no position
  field exists anywhere in `deps/saxy/lib/saxy/state.ex` either.
- `deps/saxy/lib/saxy/parse_error.ex` - `[:reason, :binary, :position]`; the
  only positional data Saxy produces, and only on failure.
- `deps/saxy/lib/saxy/simple_form/handler.ex` - the seven-clause stack idiom
  this handler follows, minus locations.
- `../statifier/lib/statifier/parser/scxml/location_tracker.ex:41-101` - v1's
  mechanism, and the concrete list of what not to repeat: per-line occurrence
  counting, first-match columns, matches inside comments, O(n^2), and attribute
  columns that were never computed at all.
- `../statifier/lib/statifier/parser/scxml/state_stack.ex:257-317` - the
  eight-clause family that a single `children` list erases.

## What We're NOT Doing

- **No lowering.** No typed `Document`, `State`, `Transition`, no builders. That
  is st-l5k.4.
- **No validation.** Unknown elements, duplicate attributes, missing `xmlns`,
  and structurally nonsensical documents all parse into a DOM successfully.
- **No XML normalization.** v1's `normalize_xml/2` (`../statifier/lib/statifier/parser/scxml.ex:47-103`)
  injected `xmlns`, `version`, and an XML declaration before parsing. That is
  SCXML-specific *and* it silently shifted every location after it. v2 parses
  exactly the bytes it is given.
- **No namespace resolution.** No prefix-to-URI mapping, no `xmlns` scope stack.
- **No comment or PI nodes** in the DOM.
- **No streaming.** `parse/1` takes a whole binary. `Saxy.Partial` gives
  chunk-granularity brackets only, which cannot satisfy "every node has a
  location".
- **No wiring into `test/support/case.ex`** (st-wju.7) and no conformance tests
  ratcheted - nothing can pass until an interpreter exists.
- **No changelog fragment.** Per `changelog.d/README.md`, the rewrite rule is
  "write a fragment when v2 differs from v1", judged by what a caller of the
  public API can tell. There is no public parse API yet; the fragment belongs to
  whichever bead lands `Statifier.parse/1`.

## Implementation Approach

Two passes over the source, zipped.

Saxy gives semantics (well-formedness, entity expansion, character data,
attribute values) but no positions. A second, much simpler left-to-right scan
gives positions but no semantics. Both produce **element boundaries in document
order**, and that is the join key: the Nth start tag the scanner found is the
Nth `:start_element` Saxy emits. The handler carries the scanner's output as a
queue and pops one record per element event.

```
source binary
   |-- Statifier.Parser.Markup.scan/1 --> [markup record]   (positions, no semantics)
   |                                            |
   |-- Saxy.parse_string/3 -------------------> | zip by index in the handler
                                                v
                                     %DOM.Element{} tree
```

### Decision 1: how locations are obtained

**A dedicated markup scanner (`Statifier.Parser.Markup`), zipped against the SAX
event stream by index.**

The scanner is a single left-to-right codepoint walk that only ever answers "is
this a markup construct, and where does it start and end". It classifies each
`<` by the bytes that follow it: `!--` comment (skip to `-->`), `![CDATA[` (skip
to `]]>`), `!DOCTYPE` (skip to `>`, honoring an internal subset `[...]`), `?` PI
(skip to `?>`), `/` end tag, anything else a start tag. Start tags are scanned
to their `>` while respecting quoted attribute values, so a `>` inside an
attribute never ends a tag. It never interprets content, never expands entities,
never validates. A self-closing `<b/>` emits **two** records - a `:start` and an
`:end` with identical spans - so the record stream is 1:1 with Saxy's element
events by construction.

Rationale: it is the only option that meets the acceptance criteria. Note in
particular that the bead's own proposed fallback - "a pre-pass that indexes
newline offsets in the binary plus byte-offset tracking" - **cannot work as
written**: indexing newlines converts an offset into a line/column, but Saxy
exposes no offset at handler callbacks either, so there is nothing to convert.
The scanner is that fallback with the missing half supplied; the newline index
it implies is folded into the scan itself, which already knows the line and
column of every construct it passes.

The alternatives, all rejected:

- **v1's re-scan-per-element regex** - documented wrong (per-line occurrence
  counting, first-occurrence columns, matches inside comments) and O(n^2).
- **`Saxy.Partial` chunk feeding** - yields chunk brackets, not per-element
  positions.
- **`:xmerl_sax_parser`** - gives a line per event but no column, and creates
  atoms from element names, which is the reason Saxy was chosen.
- **Patching Saxy** - upstream has no issue, PR, or maintainer statement on
  position tracking (research doc, "Upstream status"); a fork is a permanent
  maintenance liability for one field.

The obvious risk is the two passes disagreeing. It is mitigated mechanically:
every popped record's name is compared to the name in the Saxy event, and a
mismatch aborts with `{:location_desync, expected, got}` rather than attaching a
wrong location. Because Saxy does no namespace processing and no expansion
touches names, the two spellings are byte-identical whenever the scan is in
sync, which makes this a strong invariant rather than a formality. The scanner
is also a **total function** - it never raises on any binary, including
malformed XML - so on a malformed document Saxy's error is what surfaces, not a
scanner crash. The mechanism choice and its rationale go in
`Statifier.Parser.Markup`'s moduledoc and an inline comment at the zip site,
satisfying the bead's sixth acceptance criterion.

### Decision 2: what a location contains

**An exclusive-end span with both line/column and byte offsets.**

```elixir
%Statifier.Parser.Location{
  start_line: 3, start_column: 5, start_offset: 42,
  end_line: 3, end_column: 28, end_offset: 65
}
```

Lines and columns are 1-based; columns count Unicode codepoints, not bytes, so
the scanner walks codepoints and advances the two counters independently. Byte
offsets are 0-based and the end is **exclusive**, matching ADR-0014's LSP-shaped
spans. Keeping offsets alongside line/column is what makes ADR-0014's
attribute-relative expression spans translatable into document positions by
plain arithmetic instead of a second scan.

An element's span runs from the `<` of its start tag to the byte after the `>`
of its end tag (for a self-closing element, the tag itself). Alternative
considered: span the start tag only. Rejected because the whole-element span is
a strict superset - `start_line`/`start_column` is exactly the v1 point that
carets want, and the end additionally supports underlining, folding, and
"which element contains offset N" queries, at zero extra cost since both ends
are already known.

The bead's design note proposes a bare point (`line`, `column`, 1-based). A span
is a superset of that point, not a departure from it: `start_line` and
`start_column` **are** the proposed point, so the acceptance criterion "every
node carries line/column" is met literally, and the extra fields cost one struct
that is built once per node either way. The reason to pay it now rather than
later is ADR-0012's own argument - the seam is cheap while the code is being
written and expensive to retrofit - and ADR-0014 has already committed the
project to exclusive-end spans one level down, inside attribute values. Two
different location shapes meeting at the attribute boundary would be the worse
outcome.

### Decision 3: attribute-level locations

**Attributes are an ordered list of structs, each with two spans.**

```elixir
%Statifier.Parser.DOM.Attribute{
  name: "cond",
  value: "x > 1",           # Saxy's entity-expanded value
  location: %Location{},    # covers cond="x > 1", quotes included
  value_location: %Location{} # covers x > 1, quotes excluded
}
```

`value_location` exists specifically for ADR-0014: an expression span is
relative to the expression string, and `value_location.start_offset` is what
turns it into a document position. The attribute's name starts at
`location.start_*` exactly, so no separate name span is stored.

The bead's design note proposes a map (`%{name => {value, location}}`) or a
parallel attribute-location map, and agrees on the substance - keep attribute
locations, because the validator wants to point at the attribute rather than the
element. This plan takes the list instead, for two reasons. First, a map is
lossy in exactly the case the parser exists to report: a document with a
duplicate attribute silently loses one of them, and the DOM's job is to say what
was written and let the validator object. Second, one struct with named fields
beats a `{value, location}` tuple or two structures kept in step - the parallel
map is the "bolted-on bookkeeping" shape `docs/architecture.md` names as the
thing to avoid. Ergonomics are covered by `DOM.attribute(node, name)`; with at
most a dozen attributes per element the scan is not a cost worth a data
structure.

Known, documented limitation: `value` is Saxy's expanded text while
`value_location` covers raw source, so when the raw text contains entity or
character references, offsets *inside* the value do not map 1:1 onto the source.
No SCXML attribute in the corpus contains a reference; the moduledoc states it
and a test pins the behavior.

### Decision 4: text, comments, and whitespace

**Text nodes are children. Comments and PIs are not in the DOM. Whitespace is
preserved verbatim.**

The bead's design note offers a choice between bare binaries in `children` and
`{:text, string}` tuples. Neither can carry a location, and the bead's own
headline requirement is that a location is a property of **every** node, so this
plan takes the third option the note's "final names implementer's call" leaves
open: a struct.

Character data becomes `%DOM.Text{value, location}` interleaved with elements in
`children`, in document order, so mixed content is representable (`<content>`
and `<data>` need it). Consecutive `:characters` events are coalesced into one
text node, which is required, not cosmetic: entity references and CDATA split a
single text run into multiple events. A text node's span runs from the end of
the preceding markup record to the start of the next one, so it covers the raw
source of the run - `<![CDATA[` delimiters and `&amp;` sequences included - while
`value` holds Saxy's decoded text.

Whitespace-only text is **kept**. This is the decisive argument: dropping it
would require the handler to know that whitespace inside `<content>` and
`<data>` is significant while whitespace between `<state>` elements is not,
which is precisely an SCXML-specific clause, and the bead forbids those. Keeping
it also matches "the DOM is whatever the XML said". Lowering ignores it in one
place via `DOM.elements/1`, which filters `children` to elements.

Comments and PIs are dropped. Saxy emits no events for them, so surfacing them
would mean driving the DOM from the scanner rather than the event stream -
strictly more coupling, for no consumer in the epic. The scanner still skips
them correctly, so they cost locations nothing. Alternative noted for the
record: emitting `%DOM.Comment{}` from the scanner queue is an additive change
if a future formatter or round-tripper needs it.

Content outside the root element (the prolog, the XML declaration, trailing
whitespace) is discarded; `parse/1` returns the root element.

### Decision 5: the error shape

**`{:error, %Statifier.Parser.ParseError{}}`, a v2 struct.**

```elixir
defexception [:reason, :message, :location, :byte_offset]
```

`reason` carries Saxy's own reason term unchanged (`{:token, _}`,
`{:wrong_closing_tag, _, _}`, `{:invalid_pi, _}`, `{:invalid_encoding, _}`) plus
the v2-only `{:location_desync, expected, got}`, so callers can pattern match
without depending on message text. `message` is `Exception.message/1` on the
Saxy error. `location` is a zero-width `%Location{}` at the failing offset,
derived by converting the byte offset over the original binary - the same span
type every node uses, so consumers have one shape to handle. `byte_offset` is
kept raw.

It is a `defexception` so a caller who wants `raise` semantics can have them,
but `parse/1` itself never raises: `Saxy.parse_string/3` returns errors as
tuples, and the desync guard uses `{:stop, {:error, err}}`, which Saxy turns
into `{:ok, {:error, err}}` for `parse/1` to unwrap. Because the handler always
returns `{:ok, _}` or `{:stop, _}`, `{:bad_return, _}` is unreachable in
practice - but the converter still tolerates `position: nil` and `binary: nil`,
which the research doc flagged as observed upstream, by leaving `location` and
`byte_offset` nil. A unit test calls the converter directly with a nil position
to cover that branch.

Alternative considered: return the raw `%Saxy.ParseError{}`. Rejected because it
leaks a byte offset to every caller and pins the public error shape to a
dependency's struct.

### Decision 6: namespaces

**Raw qualified names, verbatim.** `xmlns` is an ordinary attribute; `foo:bar`
is the literal name `"foo:bar"`. Resolving prefixes would put namespace
machinery (a scope stack, URI mapping) in a handler whose entire premise is
having no element knowledge. Lowering decides what a name means; the DOM reports
what was written. Tested with a prefixed fixture.

This is the one place the plan disagrees with the bead's design note, which
proposes storing **local names only** plus the declared default namespace
recorded once on the root. The disagreement is narrow and, on every document in
the corpus, invisible: the corpus has no prefixed names, so local name and
qualified name are the same string. Where they differ, stripping the prefix
loses the only evidence that an element was foreign, and the note's own plan is
to "reject or warn on prefixed elements from foreign namespaces at lowering
time" - which lowering cannot do if the parser has already discarded the prefix.
Stripping is also namespace-*aware* work, sitting awkwardly against the same
note's "the DOM layer stays namespace-dumb". The second half of the proposal
needs no special field either: the root's `xmlns` declaration is already an
ordinary attribute on the root element, with a location, reachable as
`DOM.attribute(root, "xmlns")`.

### Phasing

Three phases, each independently gate-verifiable and committable:

1. Position primitives - `Location`, `ParseError`, and the `Markup` scanner.
   Pure, Saxy-free, fully unit-testable on its own.
2. The DOM and the handler - structs, the zip, `parse/1` end to end.
3. Acceptance hardening - the malformed-input matrix, the location-accuracy
   sweep, and the mechanical no-SCXML-clauses guard.

Phases 1 and 2 are not splittable further: a `Location` struct with no producer
has nothing to assert against, and a handler without the scanner cannot attach a
location, so an intermediate gate would be vacuous.

### Where this plan diverges from the bead's design notes

The bead's `design` field proposes answers to the same questions. This plan
adopts its handler mechanics (stack of open elements, accumulate children
reversed, reverse once on pop), its whitespace rule (explicit and tested,
either way), its fixture and sabotage guidance, and its core attribute
judgment (locations on attributes, because the validator points at the
attribute rather than the element). It diverges in four places, each argued at
the decision above:

| Bead's proposal | This plan | Why |
|---|---|---|
| Location is a point (`line`, `column`) | Exclusive-end span with offsets | Superset of the point; ADR-0014 already committed to spans one level down, inside attribute values |
| Attributes as a map, or a parallel location map | Ordered list of `%Attribute{}` | A map drops duplicate attributes the validator should get to report; a parallel map is the bolted-on shape the architecture doc warns against |
| Text as bare binaries or `{:text, string}` | `%Text{value, location}` | Neither proposed form can carry the location the bead requires on every node |
| Store local names; record default namespace on the root | Raw qualified names; `xmlns` is just an attribute | Stripping prefixes destroys what lowering needs to reject foreign namespaces, and is itself namespace-aware work; identical on every corpus document |

The bead's suggested fallback mechanism (newline index plus byte-offset
tracking) is adopted in substance but corrected: Saxy supplies no offset at
callbacks, so the scanner produces the offsets that fallback assumed it could
read.

## Phase 1: Position primitives and the markup scanner

### Overview

Everything that computes a position, with no dependency on Saxy. At the end of
this phase the source can be scanned into an ordered list of markup records with
exact spans, and a byte offset can be converted into a location.

### Changes Required:

#### 1. The location span

**File**: `lib/statifier/parser/location.ex` (new)
**Changes**: The span struct, plus offset conversion for the error path.

```elixir
defmodule Statifier.Parser.Location do
  @moduledoc """
  A source span: 1-based line/column (columns counted in Unicode codepoints),
  0-based byte offsets, exclusive end - the shape ADR-0014 fixed for
  expression spans, used here for XML nodes so the two compose.
  """

  defstruct [:start_line, :start_column, :start_offset,
             :end_line, :end_column, :end_offset]

  @type t :: %__MODULE__{...}

  @spec at_offset(binary(), non_neg_integer()) :: t()
  @spec slice(t(), binary()) :: binary()
end
```

`at_offset/2` counts newlines and codepoints over `binary_part(source, 0, offset)`
and returns a zero-width span. `slice/2` returns
`binary_part(source, start_offset, end_offset - start_offset)` - the primitive
the Phase 3 accuracy sweep is built on.

#### 2. The parse error

**File**: `lib/statifier/parser/parse_error.ex` (new)
**Changes**: The exception struct and the converter from `%Saxy.ParseError{}`.

```elixir
@spec from_saxy(Saxy.ParseError.t(), binary()) :: t()
```

Nil `position` yields nil `location` and nil `byte_offset`. Also a
`desync/3` constructor for `{:location_desync, expected, got}`.

#### 3. The markup scanner

**File**: `lib/statifier/parser/markup.ex` (new)
**Changes**: The scan itself and its record struct.

```elixir
defmodule Statifier.Parser.Markup do
  @moduledoc """
  ... why this exists: Saxy 1.6.1 passes handlers no position data of any kind
  and has no option to enable it (deps/saxy/lib/saxy/handler.ex), so positions
  are produced by this independent scan and zipped against the event stream by
  index. See docs/plans/260807-st-l5k.3-sax-dom-source-locations.md, Decision 1.
  """

  defstruct [:kind, :name, :location, :attributes]
  # kind: :start | :end
  # attributes: [%{name: binary(), location: Location.t(), value_location: Location.t()}]

  @spec scan(binary()) :: [t()]
end
```

Total over any binary. Walks codepoints, tracking `{offset, line, column}`.
Constructs handled: comment, CDATA, DOCTYPE (including an internal subset),
PI, end tag, start tag (with quoted-value-aware attribute extraction, single
and double quotes). A self-closing tag emits a `:start` then an `:end` with
identical spans.

## Phase 2: The DOM, the handler, and `parse/1`

### Overview

The generic DOM node types, the six-clause Saxy handler that zips scanner
records against events, and the public entry point.

### Changes Required:

#### 1. The DOM node types

**File**: `lib/statifier/parser/dom.ex` (new; `Element`, `Text`, and `Attribute`
as sibling files or nested modules - implementer's call, one module per file
preferred)
**Changes**:

```elixir
defmodule Statifier.Parser.DOM.Element do
  defstruct [:name, :attributes, :children, :location]
  # attributes: [DOM.Attribute.t()]  - document order, duplicates preserved
  # children:   [Element.t() | Text.t()] - document order, whitespace kept
end

defmodule Statifier.Parser.DOM.Text do
  defstruct [:value, :location]
end

defmodule Statifier.Parser.DOM.Attribute do
  defstruct [:name, :value, :location, :value_location]
end
```

Plus helpers on `Statifier.Parser.DOM`:

```elixir
@spec elements(Element.t()) :: [Element.t()]            # children, elements only
@spec attribute(Element.t(), binary()) :: Attribute.t() | nil
@spec text(Element.t()) :: binary()                     # concatenated Text children
```

These are the three things lowering will otherwise re-implement per builder.

#### 2. The handler

**File**: `lib/statifier/parser/handler.ex` (new)
**Changes**: `@behaviour Saxy.Handler`, six clauses, no element names anywhere.

Handler state: `%{stack: [...], markup: [Markup.t()], cursor: {offset, line, column}, source: binary()}`.

- `:start_document` / `:end_document` - pass through; `:end_document` yields the
  root.
- `:start_element` - pop a `:start` record, guard its name against the event's,
  push a frame carrying the record and an empty child list.
- `:end_element` - pop an `:end` record, guard the name, build the
  `%Element{location: span(start_record, end_record)}`, reverse its children,
  and prepend it to the parent frame's children. **One clause, no context
  matching** - this is the single line that replaces v1's 79-clause
  `state_stack.ex`.
- `:characters` and `:cdata` - coalesce into the open frame's head `%Text{}` if
  one is there, else start a new one; span runs from `cursor` to the start of
  the next queued markup record.

Every pop advances `cursor` to the record's end. Name mismatch returns
`{:stop, {:error, ParseError.desync(...)}}`.

#### 3. The public entry point

**File**: `lib/statifier/parser.ex` (new)
**Changes**:

```elixir
@spec parse(binary()) :: {:ok, DOM.Element.t()} | {:error, ParseError.t()}
def parse(source) when is_binary(source) do
  markup = Markup.scan(source)

  case Saxy.parse_string(source, Handler, Handler.init(source, markup)) do
    {:ok, {:error, %ParseError{} = error}} -> {:error, error}   # desync abort
    {:ok, root} -> {:ok, root}
    {:error, %Saxy.ParseError{} = error} -> {:error, ParseError.from_saxy(error, source)}
  end
end
```

### Success Criteria:

## Phase 3: Acceptance hardening

### Overview

Turn each of the bead's acceptance criteria into a test that would catch its

### Changes Required:

#### 1. The malformed-input matrix

**File**: `test/statifier/parser/parse_error_test.exs` (new)
**Changes**: One case per reachable `Saxy.ParseError` reason, each asserting

| Input | Reason |
|---|---|
| `<a><b></c></a>` | `{:wrong_closing_tag, "b", "c"}` |

**File**: `test/statifier/parser/location_accuracy_test.exs` (new)
**Changes**: A generic property over a handful of fixtures modeled on real
corpus documents (declaration on line 1, a multi-line Apache license comment,
default `xmlns`, trailing whitespace inside start tags, attributes spread over
lines - all as triple-quoted heredocs at 4-space base indentation):

```elixir
# walk every element in the parsed tree
assert Location.slice(element.location, source) =~ ~r/\A<#{element.name}[\s\/>]/
assert Location.slice(attribute.value_location, source) == raw_value_text
```

This is the assertion that scales: it catches an off-by-one anywhere in the
scanner on any fixture, without hardcoding a single line number, and it is
exactly the check v1's mechanism would fail.

`elseif`, `else`, `foreach`, `invoke`, `donedata`, `cancel`, `script`).

## Testing Strategy

### Unit Tests

Under `test/statifier/parser/`, pattern-matching style, XML as triple-quoted
heredocs at 4-space base indentation:

- `location_test.exs` - `at_offset/2` across lines and non-ASCII, `slice/2`
- `markup_test.exs` - the construct matrix and totality (Phase 1 list)
- `dom_test.exs` - the three helpers
- `handler_test.exs` - the zip, coalescing, and the desync guard driven directly
- `parser_test.exs` - `parse/1` end to end, structure and text policy
- `parse_error_test.exs` - the malformed matrix and never-raises
- `location_accuracy_test.exs` - the slice-back-out property
- `generic_handler_test.exs` - the source-text guard

Key edge cases, all listed in the phase criteria: comments containing markup
text, `>` inside attribute values, CDATA containing `<`, entity references
splitting a text run, self-closing tags, multi-line start tags, non-ASCII
columns, CRLF, duplicate attributes, prefixed names.

### Conformance Tests

None. No SCION or W3C test can pass until an interpreter exists; the ratchet
does not move in this bead. The corpus is used only as a source of realistic
fixture shapes for the accuracy sweep.

### Manual Testing Steps

1. `iex -S mix`, parse a real SCION document read off disk, and confirm the tree
   shape and a nested element's reported line/column against the editor.
2. Parse the same document with a stray `<!-- <state id="x"/> -->` comment
   inserted; confirm no desync and that locations after the comment are right.
3. Corrupt the document (drop a closing tag) and confirm `{:error, %ParseError{}}`
   with a line/column at the failure, and no exception.

## Performance Considerations

Two O(n) passes over the source instead of one: the scanner walks every
codepoint once, Saxy walks the binary once. v1 was O(n^2) - a full-document
regex scan per element - so this is a strict improvement on the mechanism it
replaces, and parsing is a once-per-document cost outside any hot loop. The
scanner's output is a list proportional to the tag count and is dropped when
parsing finishes; only the `%Location{}` structs on the DOM survive, which
ADR-0012 already accepts as permanent Machine weight.

## Corpus/Ratchet Notes

`test/passing_tests.json`'s `internal_tests` list is globbed, so every new unit
test here joins the regression ratchet the moment it is written - no manual
ratcheting, and no shrinking of the file, so `mix gate.check` has nothing to
flag. No `.quality.exs`, `.credo.exs`, `coveralls.json`, or `.sobelow-conf`
change is needed, so no `docs/quality-gate-changes.md` entry is required
(ADR-0011).

## Residual Notes for Later Beads

Recorded, not blocking; none needs an answer before this bead ships.

1. **Relaxed input** (research doc Q6). v1 injected `xmlns` and `version` into
   `<scxml>` for documents that omitted them. This plan drops that behavior
   entirely. If a corpus document turns out to need it, it belongs in lowering
   or the validator as a stated leniency, never in the parser - the decision is
   st-l5k.4's or st-l5k.5's, and it is cheap either way because the DOM reports
   what was written.
2. **Comment nodes.** Dropped here; the scanner already locates them, so adding
   `%DOM.Comment{}` later is additive and does not disturb the zip.
3. **Entity-expanded attribute offsets.** Offsets inside a value whose raw text
   contains references do not map 1:1. If ADR-0014's expression spans ever have
   to point inside such a value, the fix is to have the scanner record the raw
   value text alongside its span; noted, not built, because no corpus attribute
   contains a reference.
4. **`Saxy.ParseError` reason coverage.** `{:bad_return, _}` is unreachable
   given the handler's return discipline, so it is covered only at the converter
   level. If a future handler change introduces a raising path, that test is the
   one to extend.

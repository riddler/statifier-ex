# Generate and Commit the Conformance Corpus Implementation Plan

## Overview

Run the corpus generator end to end from a cold scratch directory, prove the
run is reproducible (a second run is a zero diff), and land the emitted
`test/scion_tests/` and `test/scxml_tests/` trees as the committed corpus.
Beads issue: st2-00p.9.

The corpus files themselves are already committed - they arrived incidentally
as the emitter beads (st2-00p.6, st2-00p.7, st2-yo4) landed. What has never
been done is the thing this bead is actually for: a clean regeneration whose
output matches what is in git, and a mechanical check of the four acceptance
criteria. That reframes the work from "generate and commit" to "regenerate,
reconcile, and prove". One real defect has already been found by looking
(see Key Discoveries), and it is exactly the kind the reconciliation exists
to catch.

### Key Discoveries

- **`test/scxml_tests/mandatory/Expressions/` is committed with a capital E,
  and the emitter produces `expressions/`.** Verified directly:
  `Cases.Normalize.identifier("Expressions")` returns `"expressions"`
  (`tools/corpus/normalize.exs`). Git history explains it - commit `47f4a25`
  ("Rewrites the W3C emitter to the v2 test shape") committed the capitalized
  path, and `5c828f5` ("Normalizes corpus emitter names to snake_case") never
  recorded the case-only rename because this repo has
  `core.ignorecase=true` and the checkout sits on a case-insensitive
  filesystem. `corpus:emit` does `rm -rf "$CORPUS_W3_OUT"` and recreates, so
  on macOS the rename is invisible and `git status` stays clean; on a
  case-sensitive filesystem (CI, Linux) the same run yields 5 deletions under
  `Expressions/` and 5 additions under `expressions/`. This is the one known
  violation of acceptance criterion 4, and it is platform-dependent, which is
  why nobody has seen it.
  Affected files: `test309`, `test310`, `test311`, `test312`, `test344`.
  Module names are unaffected - `Macro.camelize("expressions")` is
  `"Expressions"`, so `SCXMLTest.Expressions.Test309` is already correct.
- **`Expressions` is the only offending segment.** `git ls-files test/scion_tests
  test/scxml_tests | tr '/' '\n' | sort -u | grep '[A-Z]'` returns exactly one
  line. That makes the fix a five-file rename, not a sweep.
- **The emitter is deterministic by construction.** Both `corpus:emit`
  invocations sort their input (`find ... -print0 | sort -z`), features are
  `Enum.sort`ed before interpolation (`scxml_w3/cases.exs:129`,
  same pattern in `scion/cases.exs`), output goes through
  `Code.format_string!/1`, and the stage `rm -rf`s the output roots first so
  a deleted upstream case cannot leave an orphan behind. The remaining
  reproducibility risks are upstream drift (SCION is cloned at `--depth 1`
  from `main`, unpinned) and the casing defect above.
- **Corpus filtering already reports staleness.** `scxml_w3/cases.exs:207`
  and its SCION counterpart print stale exclusion entries (entries that
  matched nothing) to stderr. A regeneration that silently stops matching an
  exclusion is therefore already loud; the plan should read that output
  rather than re-implement the check.
- **`test/passing_tests.json` has empty `scion_tests` and `w3c_tests` lists.**
  Nothing in the corpus is ratcheted, so renaming or regenerating corpus files
  cannot break `mix test.regression`. That makes Phase 1 zero-risk on the
  ratchet.
- **Module names drop the conformance segment.** `scxml_w3/cases.exs:139-144`
  builds `SCXMLTest.<Spec>.<Name>` from spec and name only, so
  `mandatory/scxml_event_processor/test193` and
  `optional/scxml_event_processor/test193` would collide. No collision exists
  today (`grep -rh '^defmodule' ... | sort | uniq -d` is empty; W3C test
  numbers are globally unique across conformance levels), but the corpus has
  no guard against one appearing.
- **`Statifier.Case`'s four-function contract is untouched by this bead**
  (ADR-0006). Nothing here goes near `test/support/case.ex`.

## Desired End State

- A cold `mise run corpus` (empty `tools/corpus/scratch/`) followed by
  `git status --porcelain test/scion_tests test/scxml_tests` produces no
  output, on a case-sensitive comparison rather than one masked by
  `core.ignorecase`.
- `test/scxml_tests/mandatory/expressions/` is the committed path; the
  capitalized directory is gone from the index.
- A committed test asserts the emitted-path invariant, so the class of defect
  found here fails a gate instead of waiting for CI on another platform.
- The four acceptance criteria are each backed by a command whose output was
  read, recorded in the bead's notes.
- `tools/corpus/README.md`'s Status section describes a generated-and-verified
  corpus rather than "remaining work".

## What We're NOT Doing

- **Not touching `test/support/case.ex`.** The 4 tests that reach
  `Statifier.parse/1` are correct behavior for an engine-less repo (ADR-0006:
  unsupported features flunk, never skip). Making them pass is Phase 1/2 work.
- **Not adding anything to `test/passing_tests.json`.** v2 has no engine;
  the ratchet starts at zero by design (`docs/testing.md`). Wiring the ratchet
  into the gate is st2-00p.10.
- **Not revisiting the exclusion manifests.** Both landed under st2-00p.8 and
  are accepted; ADR-0004 settles the reasoning. If a regeneration reports a
  stale entry, that is a finding to report, not a manifest edit to make.
- **Not pinning the SCION upstream clone to a SHA.** Reproducibility across
  time is a real concern but a separate decision (see Open Questions).
- **Not re-running the W3C fetch against w3.org uncached** when the local
  mirror can seed it. The mirror path is documented for exactly this.
- **Not changing the module-naming scheme** to include the conformance
  segment. No collision exists; a rename would churn 162 files for a
  hypothetical.
- **Not regenerating as part of `mix quality` or CI.** The generator needs
  network, Java, and a git clone; the gate does not get those dependencies.

## Implementation Approach

Three phases, ordered so each one leaves the tree committable on its own.

Phase 1 fixes the known defect and installs the invariant test - it is a
five-file rename plus one test file, needs no network, and can be verified
entirely locally. Phase 2 is the actual regeneration: cold scratch, full
pipeline, diff against the index. Doing it after Phase 1 means a non-empty
diff in Phase 2 is a real finding rather than the casing bug re-reported.
Phase 3 records the result - docs and bead notes - once there is a result to
record.

Phase 2's success criterion is "the diff is empty or every hunk in it is
explained", not "the diff is empty". A regeneration that legitimately picks up
an upstream SCION change should land that change as a reviewed commit; that is
precisely the property ADR-0006 committed the generated output to get.

## Phase 1: Reconcile the Committed Tree with the Emitter

### Overview

Rename the one stale path segment to what the emitter produces, and add a test
that pins the invariant so a case-only drift cannot hide behind
`core.ignorecase` again.

### Changes Required:

#### 1. The case-only rename

**Files**: `test/scxml_tests/mandatory/Expressions/{test309,test310,test311,test312,test344}_test.exs`

Rename the directory through git so the index records it, since a plain
filesystem `mv` is a no-op on a case-insensitive volume:

```bash
git mv test/scxml_tests/mandatory/Expressions test/scxml_tests/mandatory/expressions_tmp
git mv test/scxml_tests/mandatory/expressions_tmp test/scxml_tests/mandatory/expressions
```

File contents do not change. `git status` must then show 5 renames (or 5
deletions plus 5 additions, depending on rename detection), and
`git ls-files test/scxml_tests | grep Expressions` must return nothing.

#### 2. The emitted-path invariant test

**File**: `test/corpus/emitted_paths_test.exs` (new; joins the existing
`check_exprs_test.exs` and `normalize_test.exs` in that directory)

Assert two things over the tracked corpus trees:

- Every path segment under `test/scion_tests/` and `test/scxml_tests/` matches
  `~r/\A[a-z0-9_]+\z/` (with `_test.exs` stripped) - which is exactly the
  shape `Cases.Normalize.identifier/1` can produce, so any segment that fails
  is a segment the emitter did not write.
- Every `defmodule` line across both trees is unique, catching the latent
  conformance-segment collision described in Key Discoveries.

Read the file list from the filesystem, not from git, so the test works in a
fresh checkout. Both assertions are harness-only, so per `docs/testing.md` the
file carries the stated exemption rather than a sabotage note:

```elixir
# sabotage: n/a - asserts a property of generated files, no lib/ behavior
```

The first assertion is what would have caught this bug: on macOS the
filesystem reports the directory as `Expressions` regardless of
`core.ignorecase`, so the test goes red locally today and green after the
rename.

## Phase 2: Cold Regeneration and Zero-Diff Proof

### Overview

Run the full pipeline from an empty scratch tree and compare the output
against the index. This is the phase the bead is named for.

### Changes Required:

#### 1. Cold run

No file edits. Commands, in order:

```bash
mise run corpus:clean
CORPUS_W3_MIRROR=~/repos/github/ex_statechart/test/scxml_w3/cases mise run corpus:fetch
mise run corpus:transform
mise run corpus:emit
```

Run the stages separately rather than through the `corpus` aggregate so each
stage's counts and stderr are readable on their own. Capture all of it: the
`transformed N file(s)` line, the emitters' emitted/excluded counts, and any
`stale ... exclusions.exs entries` warning.

The mirror only supplies `.txml`, `.description`, and `manifest.xml`, and only
where the file is missing - it cannot displace our own transform output. If
the mirror is unavailable, drop `CORPUS_W3_MIRROR` and accept the throttled
crawl; `corpus:fetch:w3` skips files already on disk, so a 429 interruption
resumes.

#### 2. Diff evaluation

```bash
git status --porcelain test/scion_tests test/scxml_tests
git diff --stat test/scion_tests test/scxml_tests
```

Then re-check the case dimension explicitly, since `core.ignorecase=true`
hides exactly the defect Phase 1 fixed:

```bash
diff <(git ls-files test/scion_tests test/scxml_tests | sort) \
     <(cd . && find test/scion_tests test/scxml_tests -type f | sort)
```

Three outcomes, each with a defined response:

- **Empty diff.** Criterion 4 is met; nothing to commit in this phase.
- **Diff confined to upstream drift** (SCION `main` moved since the last
  clone, new or changed cases). Commit it as the reviewable diff ADR-0006
  exists to produce, with the upstream SHA named in the commit body. Re-run
  `corpus:emit` once more to confirm the second run is then a true zero diff.
- **Diff that is neither** - an emitter nondeterminism, a stale exclusion, a
  Saxon version difference. Stop and report. Do not paper over it by
  committing the new output; a generator that is not deterministic is a bug in
  `tools/corpus/`, and fixing it is a change to the emitter, not to the
  corpus.

#### 3. Second-run idempotence

Immediately after the first run settles, run `mise run corpus:emit` again on
the same scratch tree. This must be a zero diff unconditionally, since no
input changed. It isolates emitter nondeterminism from fetch drift, which the
single-run check cannot do.

### Success Criteria:

#### Automated Verification:
- [x] `mise run corpus` completes with exit 0 from an empty scratch tree
- [x] A second `mise run corpus:emit` leaves `git status --porcelain
      test/scion_tests test/scxml_tests` empty
- [x] The `git ls-files` vs `find` comparison above shows no path present in
      one and absent from the other
- [x] Neither emitter prints a stale-exclusions warning
- [x] Full quality gate passes: `mix quality`
- [x] `mix test --include scion --include scxml_w3` produces zero exceptions:
      `mix test --include scion --include scxml_w3 2>&1 | grep -E '^\s+\*\* \('`
      returns nothing
- [x] `mise run corpus:check` passes (every transformed mandatory expression
      compiles under predicator)

#### Manual Verification:
- [ ] Emitted counts match the committed tree: 118 SCION, 162 W3C, or a
      difference traced to a named upstream change
- [ ] Any non-empty diff is explained hunk by hunk before it is committed
- [ ] Spot-check two regenerated files (one SCION, one W3C) against their
      committed versions for byte identity, confirming the XML heredoc
      formatting round-trips

## Testing Strategy

### Unit Tests

- `test/corpus/emitted_paths_test.exs` (new, Phase 1) - the path-shape and
  module-uniqueness invariants over the generated trees. Harness-only, so it
  carries the stated sabotage exemption per `docs/testing.md`.
- No changes to `test/corpus/check_exprs_test.exs` or
  `test/corpus/normalize_test.exs`; both already cover their generators.

### Conformance Tests

- No test is ratcheted by this plan. `test/passing_tests.json`'s conformance
  lists stay empty until an engine exists.
- The full conformance run is used as a *harness* check, not a pass/fail
  check: every one of its 280 failures must be a `Statifier.Case` flunk, and
  any exception is a defect in the corpus or the harness.

### Manual Testing Steps

1. Confirm the invariant test fails before the Phase 1 rename and passes after.
2. From an empty scratch tree, run the three corpus stages individually and
   read each one's counts and stderr rather than only its exit code.
3. Run `corpus:emit` twice back to back and confirm the second run changes
   nothing.
4. Diff `git ls-files` against `find` over both corpus trees to check the case
   dimension that `core.ignorecase` hides.
5. Run the full conformance suite and grep the output for exceptions.

## Corpus/Ratchet Notes

Regeneration rewrites both corpus trees wholesale (`corpus:emit` `rm -rf`s the
output roots). Because both ratchet lists are empty, no registry entry can be
orphaned by this - `mix test.regression`'s "entry matches no file" failure
mode cannot fire. That will stop being true once st2-00p.10 lands and tests
start entering the registry: from then on, a regeneration that renames or
removes a ratcheted file is a registry edit too. Worth stating in the README's
Status rewrite so the next regeneration does not learn it the hard way.

## Open Questions

The repo convention is that a plan carries no open questions. These are
recorded rather than resolved because this plan was produced without a human
available to decide them, and each one is a judgment call rather than
something the codebase can answer. None of them blocks Phase 1 or Phase 2;
they are all reporting-level.

1. **"127+ SCION" in the acceptance criteria versus 118 emitted files.** 127
   is the native SCION case count after `corpus:fetch:scion` drops the
   `w3c-ecma` duplicate tree; 9 of those 127 are excluded by
   `tools/corpus/scion/exclusions.exs` under ADR-0004, leaving 118 emitted.
   **Assumption taken:** the criterion was written against upstream case count
   before the exclusion manifest existed (st2-00p.8, which this bead depends
   on), so 118 satisfies it and the bead text is what is stale. If the
   intended reading is "127 emitted files", the exclusions would have to be
   reversed, which contradicts an accepted ADR - so the assumption is the only
   coherent one, but the bead text should be amended by a human.

2. **`optional/ecma_profile/test278_test.exs` is emitted at all.**
   `tools/corpus/README.md` says the datamodel-specific optional suites
   "keep their original datamodel" and are therefore filtered out, but
   `conf_predicator.xsl` evidently transformed test278 to
   `datamodel="predicator"` and it emitted. Either the XSL reaches further
   into `ecma-profile` than the README claims, or test278 is an
   ecma-profile case that happens to use only portable `conf:` templates.
   **Assumption taken:** harmless - the file is tagged `:scxml_w3`, excluded
   by default, and not ratcheted. Left as is; the README prose may need a
   qualifier.

3. **Should the SCION clone be pinned?** `corpus:fetch:scion` clones
   `jbeard4/scxml-test-framework` at `--depth 1` from the default branch, so
   "regenerate" means something different next year than it does today. The
   zero-diff criterion is only meaningful against a fixed upstream.
   **Assumption taken:** out of scope here; pinning changes the meaning of the
   generator and deserves its own bead. Worth filing.

4. **Is zero-diff ever enforced mechanically?** Verifying it needs network,
   Java, and a git clone, none of which the quality gate has. Today it is a
   human-run check. **Assumption taken:** leave it manual and document the
   command; a nightly job or an opt-in CI stage would be a separate decision.

5. **SCION tests emit an empty description string** (`test_scxml(xml, "",
   ...)`) because the upstream JSON carries no description field. Cosmetic,
   and it makes SCION failure output less useful than W3C's.
   **Assumption taken:** out of scope for this bead.

6. **Does the `Expressions` rename warrant a changelog fragment?** Judged no
   (test-side only), but `changelog.d/README.md` is the authority and a human
   may read it differently.

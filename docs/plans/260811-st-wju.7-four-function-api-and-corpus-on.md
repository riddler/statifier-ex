# Four-Function API and Corpus Switch-On Implementation Plan

## Overview

Give `Statifier` the four public functions `Statifier.Case` has been waiting on
since ADR-0006 - compile a document, initialize a state chart, send one event
synchronously, read the active leaf states - then wire the harness helpers, flip
the Phase 1 feature set in `Statifier.FeatureDetector`, and seed
`test/passing_tests.json` with the first real conformance baseline so the
regression ratchet goes live. Bead: st-wju.7.

## Current State Analysis

Everything below the boundary exists; nothing above it does.

- `lib/statifier.ex:1-5` is an empty moduledoc stub. There is no public surface
  at all today.
- The pipeline stages are all public and all landed:
  - `Statifier.Parser.parse/1` (`lib/statifier/parser.ex:91-92`) - binary in,
    `{:ok, DOM.Element.t()} | {:error, ParseError.t()}`; a **single** error
    struct, never a list. Documented as never raising.
  - `Statifier.Lowering.lower/1` (`lib/statifier/lowering.ex:69-70`) -
    `{:ok, Document.t()} | {:error, [Lowering.Error.t()]}`.
  - `Statifier.Validator.validate/2` (`lib/statifier/validator.ex:60-62`) -
    takes the document **and the exact source binary it was parsed from**
    (contract 4, `lib/statifier/validator.ex:24-28`); returns
    `{:ok, Document.t()} | {:error, [Validator.Error.t()]}`.
  - `Statifier.Compiler.compile/1` (`lib/statifier/compiler.ex:104-105`) -
    `{:ok, Machine.t()} | {:error, [Compiler.Error.t()]}`.
- The interpreter entry points landed with st-wju.6:
  - `Statifier.Interpreter.initialize/2` (`lib/statifier/interpreter.ex:147-165`)
    - `{MachineState.t(), [Effect.t()]}`, **untagged**, cannot fail; `opts`
    passes straight through to `MachineState.new/2` (`:trace`, `:datamodel`).
  - `Statifier.Interpreter.handle_event/2` (`lib/statifier/interpreter.ex:200-218`)
    - `{:ok, MachineState.t(), [Effect.t()]} | {:error, :not_running}`; the
    only defined error shape.
- `Statifier.MachineState.active_leaf_states/1`
  (`lib/statifier/machine_state.ex:192-195`) returns a `MapSet` of **integer
  indexes** and its own doc says "the string-id translation of this view belongs
  to a future API boundary, not this module's". This bead is that boundary.
- `Statifier.Machine.id/2` (`lib/statifier/machine.ex:250-251`) is the total
  reverse of `index/2` and returns `nil` for the root and for every nameless
  state.
- `Statifier.Event.external/2` (`lib/statifier/event.ex`) builds the external
  event `handle_event/2` wants; `data` defaults to `nil`.
- `test/support/case.ex:114-121` holds the four `not_implemented/1` stubs, and
  `test/statifier/case_test.exs:41-58` asserts the exact stub message
  (`"Statifier.parse/1 does not exist yet"`), so the harness's own test file
  changes with it.
- `test/support/feature_detector.ex:43-79` marks all 33 registry features
  `:unsupported`, which is why every corpus test stops at the feature gate.
- `test/passing_tests.json` has `scion_tests: []` and `w3c_tests: []`;
  `internal_tests` is two globs.
- Corpus size on disk: 118 SCION files under `test/scion_tests/`, 164 W3C files
  under `test/scxml_tests/` (161 mandatory, 3 optional). Both suites are
  excluded by default (`test/test_helper.exs:1`).
- Ratchet mechanics (`lib/mix/tasks/test.baseline.ex`,
  `lib/mix/statifier/regression_registry.ex`): `mix test.baseline` is a dry-run

- Gate guard (`lib/mix/statifier/gate_guard.ex:206-236`): ratchet findings come
  from `base_patterns -- head_patterns`, so **growth produces no finding** and

## Desired End State

`Statifier` exposes exactly four functions; `Statifier.Case`'s four helpers are
one line each on top of them; the Phase 1 features are `:supported`;
`test/passing_tests.json` carries a nonzero, committed conformance baseline; and
`mix test.regression` is green against it, so from that commit on a regression
in ported behavior fails the gate.

Verified by: `mix quality` green; `mix test.regression` exits 0; the two
conformance lists in `test/passing_tests.json` are non-empty and every listed
file passes when run individually.

### Key Discoveries:

- **The harness's stub names are prose, not a contract.** `test/support/case.ex`'s
  moduledoc names `Statifier.parse/1`, `Statifier.initialize/1`,
  `Interpreter.send_event/2`, `Configuration.active_leaf_states/1`, but those
  were written before any engine existed and the bead makes the naming this
  bead's call. What *is* binding is the shape `test_scxml/4` uses at
  `test/support/case.ex:62-77`: `xml |> parse_document() |> initialize()`, then
  `send_event(state_chart, event_map)`, then `active_leaf_states/1` compared
  against a `MapSet` of **strings**. Those are the *private helpers'* shapes -
  the public functions they call may be tuple-returning, because the helper is
  the adapter.
- **String ids only at this boundary** (ADR-0005, `docs/adr/0005-...md:25-28`).
  The translation happens in `Statifier.active_leaf_states/1` and nowhere
  deeper.
- **Effects are returned, never performed** (ADR-0003,
  `docs/architecture.md:19-26`). The four-function API returns them and
  interprets none of them; the corpus harness discards them.
- **Do not fuse the pipeline** (`docs/observability.md` constraint 5). The
  facade composes the four existing public stage functions and must not inline
  or bypass them, so `Document` and `Machine` stay reachable for tooling.
- **No interpreter change is in scope**, so ADR-0002's Appendix D rule has
  nothing to bite on here: this plan adds a facade above
  `Statifier.Interpreter` and changes no ported function. That is stated so the
  implementer does not go looking for a deviation to justify.
- **Growth of `test/passing_tests.json` needs no ledger entry**
  (`lib/mix/statifier/gate_guard.ex:221-236`, ADR-0011). Say so in the PR body
  so the diff reads as intended.
- **`mix test.baseline` alone writes nothing** - `--add` is the flag that
  ratchets (`lib/mix/tasks/test.baseline.ex:140-142`).

## What We're NOT Doing

- Not building `Statifier.Session`, an effect interpreter, an external event
  queue, or any async API. Effects come back as data and the caller ignores
  them (st-cmq).
- Not changing any `Statifier.Interpreter` signature. In particular
  st-wju.6's Open Question 6 (should `initialize/2`'s untagged pair become
  `{:ok, _, _}`) is answered by leaving the interpreter alone: the facade
  mirrors each entry point's own shape rather than normalizing them, because
  normalizing would mean editing a landed, ported function to serve a wrapper.
- Not adding a bang variant (`compile!/1`) or any fifth function. The
  four-function contract is a cap on the coupling surface (ADR-0006), and the
  harness's error path is better served by flunking with the formatted errors
  than by an exception.
- Not touching the corpus generator, the exclusion manifests, or
  `tools/corpus/`. If a corpus test is wrong, that is a corpus bead.
- Not flipping any datamodel-flavored feature (`cond`, `assign`, `script`,
  `data`, `datamodel`, `if`, `foreach`, `send*`, `cancel`, `invoke`,
  `finalize`, `eventexpr`, `targetexpr`, `idlocation`).
- Not editing `docs/quality-gate-changes.md`. Nothing in this plan shrinks the
  registry or touches a guarded config file, so no ledger entry is owed - and
  writing one would be a human's call anyway (ADR-0011).
- Not chasing the last conformance point. The Phase 1 mark is whatever the
  suites report; tests that fail for a missing feature stay failing and are
  simply not ratcheted in.

## Implementation Approach

### The design call: `Statifier.compile/1`

The bead names one real decision - the parse-pipeline entry point's name and
shape. **Decision: `Statifier.compile(source :: binary()) :: {:ok, Machine.t()}
| {:error, [error]}`.**

Rationale:

- The function's product is a `%Statifier.Machine{}` - a compiled artifact,
  interned and valid by construction (`docs/architecture.md:34-37`). "Compile"
  is the ordinary name for source-to-artifact, and it names the *result*, which
  `parse` does not.
- `parse` would name the first of four stages and then return errors from the
  other three. A caller who gets a `%Statifier.Validator.Error{}` back from
  something called `parse/1` has been misled; `Statifier.Parser.parse/1` already
  owns that word for exactly the stage that deserves it.
- `build` is the least committal of the three and says nothing about validity,
  which is the property this function actually guarantees.
- The name collides with `Statifier.Compiler.compile/1` only across modules, and
  that collision is symmetric with `Statifier.Parser.parse/1` under the `parse`
  option, so it is not a tiebreaker. The facade's moduledoc states which stages
  it runs.

Shape details, all decided here:

- **Errors are always a list.** `Statifier.Parser.parse/1` returns a single
  `%ParseError{}`; the facade wraps it in a one-element list so every failure
  from every stage has one shape. The union type is spelled out in the `@spec`;
  no new error-wrapper module is introduced.
- **Fails at the first stage that fails.** Each stage's input is the previous
  stage's output, so there is nothing to collect across stages. Within a stage,
  collect-all still holds (`lib/statifier/validator.ex:11-14`).
- **Arity 1, no opts.** The only options that exist (`:trace`, `:datamodel`)
  belong to `MachineState.new/2` and therefore to `initialize/2`.

### The other three

- `Statifier.initialize(machine, opts \\ []) :: {MachineState.t(), [Effect.t()]}` -
  a straight pass-through to `Interpreter.initialize/2`, mirroring its untagged
  pair. The harness discards the effects; a caller that wants the initialization
  log/trace effects has them.
- `Statifier.send_event(machine_state, event) :: {:ok, MachineState.t(), [Effect.t()]} | {:error, :not_running}`
  where `event` is a `%Statifier.Event{}` **or** a name string (a string clause
  builds `Event.external/2`). The event-map-to-name translation stays in
  `test/support/case.ex`, never in `lib/`.
- `Statifier.active_leaf_states(machine_state) :: MapSet.t(String.t())` -
  `MachineState.active_leaf_states/1` mapped through `Machine.id/2`, with
  `nil` ids dropped. A nameless leaf state cannot be named by any expectation,
  so it cannot be compared either way; dropping it is the only option that does
  not crash on a legal document. This is recorded in Open Questions because it
  is the one choice here that can hide a mismatch.

### Phase shape

Four phases. Phases 1 and 2 are pure `lib/` additions with unit tests. Phase 3
deliberately merges the harness wiring with the feature flips: a harness-only
commit would compile but could not exercise a single call, because with every
feature `:unsupported` every corpus document still stops at the feature gate -
the skill's "combine rather than split when the intermediate has nothing
exercising it" rule. Phase 4 is the conformance baseline, which is naturally its
own commit because it changes one data file and nothing else.

## Phase 1: `Statifier.compile/1` - the pipeline behind one function

### Overview

Turn the empty `Statifier` module into the library's public entry point and give
it the parse pipeline.

### Changes Required:

#### 1. The facade module

**File**: `lib/statifier.ex`
**Changes**: Replace the stub moduledoc with the public-surface moduledoc (four
functions, string ids at this boundary and nowhere deeper per ADR-0005, effects
returned and never interpreted per ADR-0003), and add `compile/1`.

```elixir
@type error ::
        Statifier.Parser.ParseError.t()
        | Statifier.Lowering.Error.t()
        | Statifier.Validator.Error.t()
        | Statifier.Compiler.Error.t()

@spec compile(source :: binary()) :: {:ok, Machine.t()} | {:error, [error()]}
def compile(source) when is_binary(source) do
  with {:ok, root} <- parse(source),
       {:ok, document} <- Lowering.lower(root),
       {:ok, document} <- Validator.validate(document, source) do
    Compiler.compile(document)
  end
end

# Parser.parse/1 is the one stage that reports a single error rather than a
# list; wrapping it here is what gives every failure of this function one
# shape.
defp parse(source) do
  case Parser.parse(source) do
    {:ok, root} -> {:ok, root}
    {:error, error} -> {:error, [error]}
  end
end
```

Note the `source` threaded into `Validator.validate/2` - its contract 4
(`lib/statifier/validator.ex:24-28`) requires the document's own binary.

#### 2. Unit tests

**File**: `test/statifier_test.exs` (new)
**Changes**: Cover the happy path (a small document compiles to a `%Machine{}`
whose `id_to_index` holds the written ids) and one failure per stage, each
asserting the error list is a list and its element's struct type: malformed XML
(`ParseError`), a foreign or unexpected root element (`Lowering.Error`), a
transition to an unknown target (`Validator.Error`), and a compiler-stage
failure (an uncompilable expression - the broken `cond="1 >"` case at
`test/statifier/compiler/acceptance_test.exs:174-186` already runs one through
the whole pipeline; `test/statifier/compiler_test.exs` has no failure case to
borrow).

Every test asserting `lib/` behavior carries its sabotage line (`docs/testing.md`).

#### 3. Changelog fragment

**File**: `changelog.d/st-wju.7.md` (new)

## Phase 2: The runtime three - initialize, send_event, active_leaf_states

### Overview

Add the three functions that wrap `Statifier.Interpreter` and translate the
configuration to string ids at this boundary.

### Changes Required:

#### 1. The runtime facade

**File**: `lib/statifier.ex`
**Changes**: Add the three functions.

```elixir
@spec initialize(machine :: Machine.t(), opts :: keyword()) ::
        {MachineState.t(), [Effect.t()]}
def initialize(%Machine{} = machine, opts \\ []),
  do: Interpreter.initialize(machine, opts)

@spec send_event(machine_state :: MachineState.t(), event :: Event.t() | String.t()) ::
        {:ok, MachineState.t(), [Effect.t()]} | {:error, :not_running}
def send_event(%MachineState{} = machine_state, name) when is_binary(name),
  do: send_event(machine_state, Event.external(name))

def send_event(%MachineState{} = machine_state, %Event{} = event),
  do: Interpreter.handle_event(machine_state, event)

@spec active_leaf_states(machine_state :: MachineState.t()) :: MapSet.t(String.t())
def active_leaf_states(%MachineState{machine: machine} = machine_state) do
  machine_state
  |> MachineState.active_leaf_states()
  |> Enum.map(&Machine.id(machine, &1))
  |> Enum.reject(&is_nil/1)
  |> MapSet.new()
end
```

Documentation each function must carry:

- `initialize/2` - untagged pair, mirroring `Interpreter.initialize/2`'s own
  shape and its "cannot fail" reason; `opts` is `MachineState.new/2`'s
  (`:trace`, `:datamodel`), passed through uninterpreted.
- `send_event/2` - runs one macrostep to quiescence; `{:error, :not_running}` on
  a terminated state chart; effects are returned, never performed (ADR-0003);
  the string clause is a convenience over `Event.external/2` and carries no
  data.
- `active_leaf_states/1` - ADR-0005's boundary: indexes in, string ids out, and
  nameless states (including the root) are absent because they have no id to
  return.

#### 2. Unit tests

**File**: `test/statifier_test.exs`
**Changes**: Add describes for the three. Cover, at minimum:

- initialize returns the initial leaf configuration as string ids, and returns
  an effect list (empty when `trace: false`, non-empty when `trace: true`)
- `send_event/2` with a name string and with an `%Event{}` reach the same
  configuration
- an event that enables nothing leaves the configuration unchanged and still
  returns `{:ok, _, _}`
- a document that terminates on entry (a top-level `<final>`) yields
  `{:error, :not_running}` from a subsequent `send_event/2`
- `active_leaf_states/1` returns leaves only - an active compound ancestor is
  not in the set - and excludes a nameless leaf state

XML fixtures are triple-quoted heredocs at 4-space base indentation.

**File**: `changelog.d/st-wju.7.md`

## Phase 3: Wire `Statifier.Case` and flip the Phase 1 feature set

### Overview

Replace the four `not_implemented/1` stubs with the real calls and turn on
exactly the features Phase 1 of the engine supports, so corpus tests start
running for real. These land together: with every feature `:unsupported`, a
harness-only commit has no document that can reach the four helpers, so nothing
in it would be exercised by its own gate.

### Changes Required:

#### 1. The harness helpers

**File**: `test/support/case.ex`
**Changes**: Replace `parse_document/1`, `initialize/1`, `send_event/2`,
`active_leaf_states/1` and delete `not_implemented/1`. The adapter work -
unwrapping tuples, translating the event map - lives here, per the bead.

```elixir
defp parse_document(xml) do
  case Statifier.compile(xml) do
    {:ok, machine} -> machine
    {:error, errors} -> flunk("Document did not compile:\n#{format_errors(errors)}")
  end
end

defp initialize(machine), do: machine |> Statifier.initialize() |> elem(0)

defp send_event(state_chart, %{"name" => name}) do
  case Statifier.send_event(state_chart, name) do
    {:ok, next, _effects} -> next
    {:error, :not_running} -> flunk("Sent #{inspect(name)} to a state chart that has terminated")
  end
end

defp active_leaf_states(state_chart), do: Statifier.active_leaf_states(state_chart)
```

Two adapter decisions to document in the code:

- The event map's other keys are ignored. Nothing can observe event data until
  the datamodel lands (st-af3), so translating it now would be a field with no
  reader.
- A terminated state chart flunks rather than being treated as an empty
  configuration. The corpus expects a configuration after each event; silently
  returning the terminated one could let a test pass for the wrong reason, and
  flunk-don't-skip is the harness's whole discipline (`docs/testing.md`,
  ADR-0006).

Also update the moduledoc: it currently names `Statifier.parse/1`,
`Statifier.initialize/1`, `Interpreter.send_event/2`,
`Configuration.active_leaf_states/1`. All four calls now live on `Statifier`.

## Corpus/Ratchet Notes

- This is the bead where the ratchet stops being a no-op. Before Phase 4,
  `test/passing_tests.json` guards only the internal globs; after it, every
  baselined conformance file is a gate failure if it regresses.
- The registry tracks **file paths**, not individual tests
  (`lib/mix/statifier/regression_registry.ex:180-186`). A corpus file holds one
  `test` block, so path granularity is per-case in practice.
- `mix test.regression` errors if any registry entry expands to no file, so a
  later corpus regeneration that renames files will fail loudly rather than
  silently shrink the ratchet. That is expected behavior, not a bug to work
  around.
- Corpus files are exempt from the sabotage rule (`docs/testing.md`); harness
  plumbing states its exemption in a `# sabotage: n/a - ...` line rather than
  omitting it.
- Tests failing only for a missing feature are **not** excluded, ratcheted, or
  tagged. They stay red under `--include` and green-by-exclusion under the
  default gate, which is exactly the pre-existing arrangement.
- No exclusion manifest under `tools/corpus/` is edited by this bead.

## Open Questions

Recorded rather than resolved, because each is a judgment call the plan makes a
defensible choice on and a reviewer may want to revisit. None of them blocks
implementation; each names the choice this plan makes.

1. **Nameless leaf states are silently dropped from `active_leaf_states/1`.**
   The plan filters `nil` ids. The alternative - raising, or returning a
   synthetic id - either crashes on a legal document or invents a name no
   expectation can match. The risk this leaves is a corpus test whose expected
   set happens to be empty passing while an anonymous leaf state is active. In
   practice conformance documents give every atomic state an id, so the case is
   theoretical; if a reviewer wants it closed, the fix is a harness-side
   assertion that the configuration's cardinality matches the expectation's,
   which is a `test/support/case.ex` change and not a `lib/` one.
2. **`donedata_elements` is flipped, but `<donedata><content>` still trips
   `send_content_elements`.** The detector has one `<content>` pattern and
   cannot tell `<send>`'s content from `<donedata>`'s. The plan leaves
   `send_content_elements` unsupported, which means a document with static
   donedata expressed as `<content>` flunks even though the engine handles it.
   That is conservative in the safe direction (a false flunk, never a false
   pass), and splitting the detector pattern is a harness bead of its own rather
   than scope here.
3. **The Phase 1 conformance mark is unknown until Phase 4 runs.** The bead
   expects "nonzero but modest". If the mark comes back at or near zero, the
   cause is likelier a wiring or feature-gate mistake in Phase 3 than an
   interpreter gap, and Phase 4 should stop and report rather than baseline a
   near-empty set.

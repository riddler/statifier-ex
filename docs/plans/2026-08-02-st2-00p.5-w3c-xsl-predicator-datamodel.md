# W3C Conformance XSL for the Predicator Datamodel Implementation Plan

## Overview

Rewrite `tools/corpus/scxml_w3/conf_elixir.xsl` so the W3C IRP `.txml` templates
transform into SCXML documents whose `cond`, `expr`, `location`, and array
attributes are **predicator** expressions (ADR-0004), not ECMAScript. Record the
templates that have no predicator equivalent in a committed exclusion manifest
instead of emitting expressions that cannot compile.

Beads issue: `st2-00p.5` (parent `st2-00p`, depends on the completed `st2-00p.4`,
blocks `st2-00p.7`).

## Current State Analysis

`tools/corpus/scxml_w3/conf_elixir.xsl` is the stock W3C ECMAScript stylesheet
with exactly one edit: line 45 emits `datamodel="elixir"` instead of
`ecmascript`. Everything else is ECMAScript, including forms that predicator
cannot parse at all:

- `typeof Var1 === 'undefined'` (`conf_elixir.xsl:487`, `:444`, `:522`)
- `[].concat(Var1, [4])` (`conf_elixir.xsl:605`)
- an inlined JS IIFE for string prefix (`conf_elixir.xsl:465`)
- `var Var1 = 1` inside `<script>` (`conf_elixir.xsl:541`)
- `_event.raw.search(/.../)` and `.match(/.../)[1]` throughout the basichttp
  block (`conf_elixir.xsl:670-744`)
- `'name' in _event && ...` (`conf_elixir.xsl:512`)
- a plainly broken literal, `expr="1, 2, 3]"` (`conf_elixir.xsl:579`)

It also emits `=` where predicator wants `==` in the `analyze-string` condition
templates (`conf_elixir.xsl:378`), and bare `Var1` as a truthiness `cond`
(`conf_elixir.xsl:482`), which predicator rejects because its `and`/`or`/`not`
require actual booleans.

### Template usage

Counted over the 165 mandatory `.txml` files (`~/repos/github/ex_statechart/test/scxml_w3/cases/mandatory`):
**78 distinct `conf:*` templates**. The optional tree (33 files) adds 5 more,
all basichttp regex forms.

### Predicator 3.5 surface (`deps/predicator`)

Verified by reading the lexer/parser/evaluator and by a live `mix run` probe.

Available: `== = != === !== < > <= >=`; `and or not` / `&& || !` (**strict
booleans, no truthiness coercion**); `+ - * / %` where `+` also concatenates
strings; list literals `[1,2,3]` and index/bracket/dot paths; `in` / `contains`
(**list operands only**); functions `len upper lower trim`, `Math.*`, `Date.*`,
`JSON.*`; caller-registered host functions (this is how `In/1` will be provided,
as v1 did at `../statifier/lib/statifier/datamodel.ex:169-178`).

Not available: any undefined/null literal, any boundness or `typeof` predicate,
string prefix or substring, list concatenation, regex, and any statement or
assignment syntax.

Missing paths and unbound identifiers evaluate to the internal atom
`:undefined`. Non-strict comparison against `:undefined` yields `:undefined`
rather than `false`; `===` / `!==` are the only operators that compare it
(`deps/predicator/lib/predicator/evaluator.ex:380-403`).

### Key Discoveries

- **The unbound-probe idiom works today.** Because `===` compares `:undefined`
  and a never-bound identifier evaluates to `:undefined`, boundness is
  expressible with no upstream change and no new host function. Probed live:

  | expression | result |
  | --- | --- |
  | `Var9 === _statifier_unbound` (Var9 absent) | `{:ok, true}` |
  | `Var1 !== _statifier_unbound` (Var1 = 1) | `{:ok, true}` |
  | `_event.sendid === _statifier_unbound` | `{:ok, true}` |
  | `not (Var1 === _statifier_unbound)` | `{:ok, true}` |

  This matters because ~25 mandatory tests hinge on boundness: `conf:isBound`
  (13 tests), `eventFieldHasNoValue` (4), `emptyEventData` (3), `unboundVar`
  (2), `noValue`, `systemVarIsBound`, `eventFieldsAreBound`. Excluding them
  would gut Phase 0's conformance floor.

- **v1's converted corpus is a reference for shape, not for correctness.** It
  gives us `VarN` naming, `datamodel="elixir"`, `In('s1')`, `Var1 + 1`,
  `delayexpr="'1s'"`, `_event.name == 'foo'` - but it still carries raw
  ECMAScript in `test277`, `test280` (`typeof Var2 === 'undefined' `) and
  `test525` (`[].concat(...)`). v1 hid this: a `cond` that failed to compile was
  treated as unconditionally **true**
  (`../statifier/lib/statifier/interpreter/transition_resolver.ex:234`), so
  those tests passed for the wrong reason. v2 cannot do that - errors are events
  (CLAUDE.md, `docs/datamodel.md`).

- **v2 has no parser or datamodel yet.** `lib/` holds `statifier.ex` and the
  ratchet mix tasks only. "Parses under v2's grammar expectations" therefore has
  to be verified against `Predicator.compile/1` and
  `Predicator.context_location/3` directly, which is what Phase 3 builds.

- **`tools/corpus/scratch/` does not exist in this worktree.** Nothing has been
  fetched. A local mirror of the upstream `.txml` exists at
  `~/repos/github/ex_statechart/test/scxml_w3/cases`, and `mise.toml` already
  supports seeding from it via `CORPUS_W3_MIRROR` (`tools/corpus/README.md:31-44`).

- **Dead ends are small.** `conf:varPrefix` (test224, needs string prefix),
  `conf:extendArray` (test525, needs list concat - probed: `Var1 + [4]` raises
  `TypeMismatchError`), `conf:script` (test302/303/304, `<script>` is
  permanently unsupported per ADR-0004), and the optional basichttp regex tree.

## Desired End State

`tools/corpus/scxml_w3/conf_predicator.xsl` replaces `conf_elixir.xsl`. After
`mise run corpus:fetch && mise run corpus:transform`:

1. Every `.scxml` under `tools/corpus/scratch/scxml_w3/cases/mandatory/` declares
   `datamodel="predicator"`.
2. Every `cond` / `expr` / `*expr` attribute in those files either compiles under
   `Predicator.compile/1` or is one of the deliberately-illegal expressions the
   W3C tests require, each of which is named in an allowlist with the test that
   needs it.
3. Every `location` / `item` / `idlocation` attribute either resolves under
   `Predicator.context_location/3` or is a deliberately-illegal location on the
   same allowlist.
4. `tools/corpus/scxml_w3/exclusions.exs` lists every test whose templates have
   no predicator equivalent, with a reason atom and a note naming the upstream
   seam where one exists.
5. `mise run corpus:check` reports zero unexpected failures.

Verify with: `mise run corpus:fetch && mise run corpus:transform && mise run corpus:check`
and a bare `mix quality`.

## What We're NOT Doing

- **Not touching `lib/`.** No parser, no datamodel module, no `In/1` host
  function registration. This issue produces corpus tooling only.
- **Not rewriting the emitters.** `tools/corpus/scxml_w3/cases.exs` keeps
  emitting ex_statechart-shaped modules; that is `st2-00p.7`, which this issue
  blocks. `mise run corpus:emit` stays unsafe to run, as
  `tools/corpus/README.md:73-82` already says.
- **Not committing generated `.scxml` or test modules.** `scratch/` is
  gitignored and `test/scxml_tests/` stays empty until `st2-00p.7`.
- **Not seeding `test/passing_tests.json`.** The ratchet gets its W3C entries
  once the emitted modules compile.
- **Not upstreaming anything to predicator.** The exclusion manifest records the
  seams (`docs/datamodel.md:58-72`); filing the mirrored predicator-ex issues is
  follow-up work, not this issue.
- **Not making the SCION corpus predicator-clean.** `<script>` conversion for
  SCION is the separate follow-on floated in `docs/datamodel.md:53-56`.
- **Not supporting the BasicHTTP Event I/O Processor.** Its templates get
  exclusion entries, not implementations.

## Implementation Approach

Three phases, ordered so each one's output is verifiable before the next starts.
Phase 1 is the stylesheet rewrite, Phase 2 is the exclusion manifest, Phase 3 is
the checker that proves both. Phases 1 and 2 could be done together, but keeping
them separate makes the "which tests did we give up on" diff reviewable on its
own.

The rewrite is deliberately a **rewrite in place of each template body**, not a
restructuring of the stylesheet. Template match patterns stay exactly as
upstream wrote them, so a future upstream diff stays readable and so no `.txml`
silently falls through to the identity template.

#### 2. Stylesheet header

**File**: `tools/corpus/scxml_w3/conf_predicator.xsl`

Add a comment block above the templates recording the two things a reader will
otherwise rediscover the hard way:

```xml
<!-- Emits predicator expressions (ADR-0004), not ECMAScript.

     Boundness: predicator 3.5 has no undefined literal and no typeof/bound
     predicate. `===` is the one operator that compares the internal :undefined
     an unbound identifier evaluates to, so boundness is written as a comparison
     against _statifier_unbound - an identifier no generated document ever
     binds. Revisit if predicator grows a typed undefined (docs/datamodel.md
     seam 3).

     Templates with no predicator equivalent emit nothing useful on purpose;
     their tests are listed in exclusions.exs. Do not "fix" them by emitting
     ECMAScript - v1's corpus did that and the tests passed for the wrong
     reason. -->
```

#### 3. Datamodel and identifiers

| Template | Was | Becomes |
| --- | --- | --- |
| `@conf:datamodel` | `datamodel="elixir"` | `datamodel="predicator"` |
| `@conf:id`, `@conf:name`, `@conf:location` | `Var<n>` | unchanged |
| `@conf:invalidLocation` | `foo.bar.baz ` | unchanged (trailing space is load-bearing; keep it) |
| `@conf:systemVarLocation`, `@conf:systemVarExpr` | passthrough | unchanged |

#### 4. Condition templates: `=` becomes `==`

**Templates**: `@conf:idVal`, `@conf:varIdVal`, `@conf:namelistIdVal`,
`@conf:idQuoteVal`, `@conf:idSystemVarVal`, `@conf:eventvarVal`,
`@conf:compareIDVal`

The shared `analyze-string` skeleton maps the captured operator, and today
`compareIDVal` maps `=` to `=` (`conf_elixir.xsl:378`) while `namelistIdVal`
maps it to `===` (`:325`). Normalize all seven to `==`:

```xml
<xsl:choose>
  <xsl:when test="$op='='">==</xsl:when>
  <xsl:otherwise><xsl:value-of select="$op"/></xsl:otherwise>
</xsl:choose>
```

Use `==` rather than `===` throughout: predicator's `===` is strict type
equality, and the W3C tests mean value equality between operands the document
itself bound. Apply the same change to `@conf:VarEqVar` and
`@conf:VarEqVarStruct`, which currently hardcode `===`. `VarEqVarStruct`
(test326) compares maps; predicator's `==` is deep equality on objects, so it is
the right operator there too.

Also strip the stray whitespace the current templates leak into attribute values
(`conf_elixir.xsl:287-294` puts a newline between the var name and the operator).
Predicator tolerates it, but the emitted documents are read by humans.

#### 5. Boundness: the `_statifier_unbound` probe

| Template | Tests | Emits |
| --- | --- | --- |
| `@conf:isBound` | 13 | `cond="Var<n> !== _statifier_unbound"` |
| `@conf:unboundVar` | test277, test280 | `cond="Var<n> === _statifier_unbound"` |
| `@conf:noValue` | test351 | `cond="Var<n> === _statifier_unbound"` |
| `@conf:emptyEventData` | test343, test488, test528 | `cond="_event.data === _statifier_unbound"` |
| `@conf:eventFieldHasNoValue` | test333, test335, test337, test339 | `cond="_event.<field> === _statifier_unbound"` |
| `@conf:systemVarIsBound` | test319 | `cond="<sysvar> !== _statifier_unbound"` |
| `@conf:eventFieldsAreBound` | test330 | conjunction, below |

`eventFieldsAreBound` replaces the `'name' in _event && ...` chain. `!==` yields
a boolean, so `and` typechecks:

```
_event.name !== _statifier_unbound and _event.type !== _statifier_unbound and
_event.sendid !== _statifier_unbound and _event.origin !== _statifier_unbound and
_event.origintype !== _statifier_unbound and _event.invokeid !== _statifier_unbound and
_event.data !== _statifier_unbound
```

Emit it on one line; the line break above is for this document only.

**Engine contract this creates** (record it, do not solve it here):
`conf:emptyEventData` reads true only if the engine represents *absent* event
data as undefined rather than as an empty map. If the datamodel work later
decides `_event.data` is always `%{}`, test343/488/528 need a different form.
Add this as a `bd note` on the datamodel issue when it is created, and repeat it
in the exclusions file header so it is not lost.

## Phase 2: Exclusion manifest

### Overview

Record every test the stylesheet cannot serve, with a machine-readable reason,
so `st2-00p.7` can skip them and so the conformance ceiling ADR-0004 accepts is
written down rather than implied.

### Changes Required:

#### 1. The manifest

**File**: `tools/corpus/scxml_w3/exclusions.exs` (new)

A plain Elixir term - `mix run`/`Code.eval_file` reads it, no parsing code.

```elixir
# W3C IRP tests the predicator datamodel cannot run, with the reason.
#
# Reasons:
#   :needs_script            - <script>/statements; permanently out (ADR-0004)
#   :needs_predicator_feature - blocked on an upstream predicator capability
#   :needs_basichttp         - BasicHTTP Event I/O Processor, out of scope
#
# NOTE: conf:emptyEventData (test343, test488, test528) is NOT excluded - it is
# emitted as `_event.data === _statifier_unbound`, which holds only if the
# engine represents absent event data as undefined rather than %{}. If the
# datamodel decides otherwise, those three move here.

%{
  "test302" => {:needs_script, "conf:script - predicator has no statement layer"},
  "test303" => {:needs_script, "conf:script"},
  "test304" => {:needs_script, "conf:script"},
  "test224" => {:needs_predicator_feature,
                "conf:varPrefix - no string prefix/substring function"},
  "test525" => {:needs_predicator_feature,
                "conf:extendArray - no list concatenation; `Var1 + [4]` raises TypeMismatchError"}
  # ... plus every optional/BasicHTTPEventProcessor case, :needs_basichttp
}
```

Populate the basichttp entries by listing
`tools/corpus/scratch/scxml_w3/cases/optional/BasicHTTPEventProcessor/`.

## Phase 3: Expression checker

### Overview

Prove the acceptance criterion. Walk every transformed `.scxml`, extract every
datamodel-bearing attribute, and assert it compiles under predicator - except
where the test deliberately requires it not to.

### Changes Required:

#### 1. The checker

**File**: `tools/corpus/scxml_w3/check_exprs.exs` (new)

```
mix run tools/corpus/scxml_w3/check_exprs.exs <cases_root>
```

- Walk `<cases_root>` for `.scxml`, parse with `saxy` (already a dep).
- Collect two attribute families:
  - **expressions**: `cond`, `expr`, `eventexpr`, `targetexpr`, `typeexpr`,
    `delayexpr`, `sendidexpr`, `srcexpr`, `array` - checked with
    `Predicator.compile/1`
  - **locations**: `location`, `item`, `idlocation` - checked with
    `Predicator.context_location/3`
- Skip files whose test id is in `exclusions.exs`.
- Compare each failure against an expected-invalid allowlist keyed by the exact
  attribute value, each entry naming the template and the tests that need it:
  `return` (`conf:illegalExpr`), `'continue'` (`conf:illegalItem`),
  `foo.bar.baz ` (`conf:invalidLocation`), `"foo` (`conf:invalidNamelist`).
- Exit non-zero listing any unexpected failure **and** any allowlist entry that
  no longer fires, so the allowlist cannot rot.
- Print a summary: files checked, expressions checked, expected failures,
  skipped tests.

Keep the allowlist in the script beside the code that uses it; it describes
checker behavior, not corpus policy, so it does not belong in `exclusions.exs`.

#### 2. The task

**File**: `mise.toml`

```toml
[tasks."corpus:check"]
description = "Assert every transformed W3C expression compiles under predicator"
depends = ["corpus:transform"]
dir = "{{config_root}}"
run = 'mix run "$CORPUS_DIR/scxml_w3/check_exprs.exs" "$CORPUS_W3_CASES"'
```

Do not add it to the `corpus` task's `depends`: `corpus` ends in `emit`, which
is still broken until `st2-00p.7`. Mention `corpus:check` in
`tools/corpus/README.md`'s task table instead.

#### 3. Test the checker

**File**: `test/corpus/check_exprs_test.exs` (new)

The checker is `lib/`-adjacent build tooling, so it gets tests. Extract its
logic into a module the script calls (`tools/` files are not compiled, so the
test loads it with `Code.require_file/1`, as `test/mix/statifier/regression_registry_test.exs`
does for its subject). Cover: a valid expr passes, an invalid expr fails, an
allowlisted invalid expr passes, an allowlist entry that never fires is
reported, an excluded test is skipped.

Sabotage each assertion per CLAUDE.md and note the mutation in one line above
the test.

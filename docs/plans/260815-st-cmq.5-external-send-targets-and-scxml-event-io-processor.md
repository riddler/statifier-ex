# External `<send>` Targets and the SCXML Event I/O Processor Implementation Plan

## Overview

Give `<send>` a target vocabulary and a delivery half. Today every non-`nil`
target plans as `{:unroutable, effect}` and is dropped
(`lib/statifier/session/effects.ex:54-65`). After this plan, `#_internal`,
`#_scxml_<sessionid>`, `#_parent` and `#_<invokeid>` are parsed, routed, and
either delivered or turned into the spec's own error events; delivered events
carry spec 5.10.1's `origin`, `origintype` and `sendid`; and
`_ioprocessors[...]['location']` holds an address that works as a `<send>`
target. Bead: st-cmq.5.

**No human was available while this plan was written.** Every question the
research document left open (`docs/research/260815-st-cmq.5-external-send-targets-and-scxml-event-io-processor.md`,
"Open Questions" 1-9) is resolved here as a decision on assumption; each
decision states what it assumed and what would overturn it. Phase 5 is the
one phase an agent may not finish, and it is last for exactly that reason.

**Revised 2026-08-15 after two adversarial reviews, still with no human
available.** The revision read all fifteen conformance test files rather than
trusting the research document's descriptions of them, and the conformance
claims changed substantially as a result - see "Corpus/Ratchet Notes". Two new
decisions on assumption were added (10, self-accessibility; 11, `origintype`);
decision 11 in particular resolves a conflict between the W3C's prose and the
W3C's own test in favor of the test, and a human may want to revisit it.
No phase's scope changed, and Phase 5 remains terminal and human-blocked.

## Current State Analysis

Everything upstream of delivery is finished. `<send>` lowers, validates,
compiles and executes end to end, producing exactly one `{:send, %Effect.Send{}}`
or `{:send_delayed, %Effect.SendDelayed{}}` per execution with the full 6.2.2
attribute surface resolved (`lib/statifier/machine/content/send.ex:104-138`).
What is missing:

- **Routing is one `nil`/not-`nil` branch.** `Session.Effects.plan_one/1`
  (`lib/statifier/session/effects.ex:50-65`) enqueues a `nil`-target send onto
  the session's own external inbox and plans everything else as
  `{:unroutable, effect}`, which `Session.perform_instruction/3`
  (`lib/statifier/session.ex:556-559`) forwards to subscribers and otherwise
  drops. There is no target vocabulary anywhere in `lib/`.
- **`type` is never inspected.** `Effect.Send.type` is carried and never read.
  No short alias `"scxml"` exists.
- **No registry, no supervisor.** ADR-0027 decided the shape and none of it is
  written. `lib/statifier/` has no `supervisor.ex`, and `session.ex:113` still
  reads `use GenServer, restart: :transient`.
- **`error.communication` is raised nowhere in `lib/`**, and `Session` has no
  write path to `%MachineState{}`'s internal queue. Its only inputs into the
  core are `Interpreter.handle_event/2` (external) and `Interpreter.cancel/1`.
- **`Statifier.Event` lacks `origin`, `origintype` and `sendid`**
  (`lib/statifier/event.ex:44-56`), and `SystemVariables.event/1`
  (`lib/statifier/evaluator/system_variables.ex:68-79`) hardcodes all three to
  `nil`.
- **`_ioprocessors[...]['location']` is the bare `sess_` UXID**
  (`lib/statifier/evaluator/system_variables.ex:50-60`), which satisfies
  C.1.1's letter but is not usable as a `<send target>`, which C.1's `origin`
  mapping and 5.10.1 both want.

Fifteen generated conformance tests sit in
`test/scxml_tests/mandatory/scxml_event_processor/`, and
`tools/corpus/scxml_w3/conf_predicator.xsl:239` already emits the
`_ioprocessors` location expression, so the generator side needs nothing.

**None of those fifteen flips in this bead, and one of them already passes.**
This was checked file by file rather than inferred from the research
document's descriptions, and it corrects an earlier draft of this plan that
claimed eleven flips. Three facts, each verified in the tree:

- `test500_test.exs` is *already* in `test/passing_tests.json`. It asserts only
  `Var1 !== undefined` over `_ioprocessors[...].location`, which the
  pre-existing bare `sess_` UXID satisfies. So fourteen, not fifteen, are
  waiting on anything at all.
- The other fourteen all contain `<send>`, and `send_elements` is
  `:unsupported` in `Statifier.FeatureDetector.feature_registry/0`
  (`test/support/feature_detector.ex:106`), alongside `target_expressions`
  (`:81`), `send_delay_expressions`, `send_content_elements` and
  `send_param_elements` (`:107-109`). `Statifier.Case.validate_features!/2`
  (`test/support/case.ex:100-118`) **flunks** on an unsupported atom rather
  than skipping. Confirmed by running the suite: test189 fails with "Test
  depends on unsupported SCXML features: send_elements".
- Even with the atoms flipped, the corpus harness could not observe this
  work. `Statifier.Case` drives the pure four-function API - `Statifier.compile/1`,
  `Statifier.initialize/2`, `Statifier.send_event/2`,
  `Statifier.active_leaf_states/1` (`test/support/case.ex:1-52`) - and never
  starts a `Statifier.Session`. Effects are returned and nobody performs them,
  so no `<send>` is ever routed or delivered under the corpus harness.

Both of those are **st-cmq.9's**, by that bead's own description: it flips the
ten atoms *and* settles "the harness question ... corpus tests with delayed
sends and invoked children need the session (timers, child sessions), not just
bare Interpreter calls - extend `Statifier.Case`/the harness accordingly".
st-cmq.9 depends on st-cmq.5 and st-cmq.7. This plan is therefore verified by
unit tests throughout; its conformance payoff is banked, not collected, and
collecting it is st-cmq.9's job. See "Corpus/Ratchet Notes".

## Desired End State

A `<send>` whose target names a reachable destination is delivered there; a
`<send>` whose target names nothing reachable raises `error.communication` on
the sender's internal queue; a `<send>` whose target or type is unsupported
raises `error.execution` on the sender's internal queue. Neither is ever a
crash. Delivered events carry `origin`, `origintype` and `sendid` per C.1, and
`_ioprocessors` carries a `location` that round-trips as a target.

**Verified by unit tests, not by the corpus.** For the reason given in "Current
State Analysis", `mix test --include scxml_w3 test/scxml_tests/mandatory/scxml_event_processor/`
returns the same result after Phase 5 as before Phase 1: test500 passes, the
other fourteen flunk on `send_elements`. Each phase's Automated Verification
therefore names unit tests and the full gate, and the conformance directory is
run in Phase 4 only as a *regression* check (nothing may go from passing to
failing), never as evidence of progress.

Which conformance tests this work will eventually earn, once st-cmq.9 flips the
feature atoms and puts the corpus harness on a `Session`, is recorded in
"Corpus/Ratchet Notes" so st-cmq.9 inherits the analysis rather than redoing
it. test191, test192 and test347 need a live invoked child session and belong
to st-cmq.7 regardless.

### Key Discoveries:

- `Session.Effects.plan/1` (`lib/statifier/session/effects.ex:44-47`) is the
  session's *pure* half. It is the right home for target parsing and for the
  supported-type check, because both are session-runtime knowledge and neither
  needs a process. This is what keeps the core type-blind (ADR-0003).
- `Session.start_link/2` (`lib/statifier/session.ex:200-204`) already splits
  `:name` out of `opts` and passes it through untouched, so an embedder-owned
  `{:via, Registry, _}` works today with no library code. ADR-0027 decision 2
  keeps that seam open and adds `Statifier.Registry` beside it.
- The session id is read back off `machine_state.datamodel["_sessionid"]` in
  `init/1` (`lib/statifier/session.ex:331`) after `Interpreter.initialize/2`
  has run - so registration can only happen inside `init/1`, exactly as
  ADR-0027 decision 2 says.
- `MachineState.raise_platform/4` (`lib/statifier/machine_state.ex:621-636`)
  and `raise_internal/4` are pure functions on `%MachineState{}`. `Session`
  holds the `%MachineState{}`. What it lacks is a way to *run* the machine
  after enqueuing, which is what Phase 4's new `Interpreter` seam supplies.
- `Effect.Send.send_id` is always non-`nil` (ADR-0035,
  `lib/statifier/machine/content/send.ex:243-249`), but C.1 requires the
  *delivered* event's `sendid` to be empty when the author wrote neither `id`
  nor `idlocation`. The effect does not record which case it was.
- `Mix.Statifier.AdrGuard` checks only paths under `lib/statifier/`
  (`lib/mix/statifier/adr_guard.ex:265`) against `@effect_call_pattern`
  (`:93-98`), whose alternatives are `use GenServer`, `GenServer.`,
  `Process.(send|send_after|exit|monitor)(`, `:timer.`, `Logger.`, `IO.`,
  `File.`, `System.cmd(`, `Node.`, `:ets.`, `Agent.`, `Task.(start|async)(`,
  `spawn`, and `receive do`. A module-based `use Supervisor` matches none of
  them. See Phase 5 for why the exemption list is widened anyway.
- `Mix.Statifier.GateGuard`'s guarded set is `.quality.exs`, `.credo.exs`,
  `coveralls.json`, `.sobelow-conf`, `.doctor.exs`
  (`lib/mix/statifier/gate_guard.ex:36`), gate-relevant `mix.exs` lines
  (`:43`), `@tag :skip`/`:pending` (`:52`), and shrinking
  `test/passing_tests.json`. `lib/mix/statifier/adr_guard.ex` is **not** in it.
- ADR-0029 and `docs/observability.md` constraint 6 require every session-side
  input into the core to be recordable. Phase 4's new seam is such an input and
  gains a `Recording` entry alongside `put_event`, `put_cancel`, `put_timer`
  and `put_interpret` (`lib/statifier/session/recording.ex:118-144`).
- **`Recording.entry/0` and `Replay.apply_entry/2` are a closed pair.**
  `entry/0` (`lib/statifier/session/recording.ex:76-80`) has exactly four
  variants and `Replay.apply_entry/2` (`lib/statifier/replay.ex:173-193`) has
  exactly four clauses and **no catch-all**. A fifth producer without a fifth
  clause is a `FunctionClauseError` in `Statifier.Replay.run/1`, and no gate
  stage would catch it: the conformance run does not record or replay. Phase 4
  adds both halves together.
- **`Statifier.Replay` is a second consumer of the whole planning surface, and
  it too has no catch-alls.** `Effects.plan/1` has two call sites, not one:
  `lib/statifier/session.ex:507` (inside `perform/3`) and
  `lib/statifier/replay.ex:266` (inside `Replay`'s own performing half, which
  records instead of acting). `Replay.perform_instruction/3`
  (`lib/statifier/replay.ex:275-309`) has one clause per instruction and no
  fallback, including `{:schedule, send_id, _delay_ms, _event}` at `:288` -
  which stops matching the moment Phase 4 gives `{:schedule, ...}` a route. So
  every instruction-vocabulary change in this plan is a `Replay` change as
  well. `Replay` can read the session id the same way `Session.init/1` does,
  off `state.machine_state.datamodel["_sessionid"]`.

## What We're NOT Doing

- **Full `#_parent` and `#_invokeid` delivery.** `docs/architecture.md:125-139`
  assigns `#_parent`/`#_invokeid` *routing and delivery* to st-cmq.7. This plan
  reserves their shape only: both parse to a route, both plan to a `{:deliver,
  route, ...}` instruction, and both resolve through an invocation table that
  st-cmq.7 populates. With no invocation table they resolve to nothing, which
  C.1 already answers ("a session that does not exist or is inaccessible" ->
  `error.communication`). No arm is left to guess or crash. Whoever implements
  st-cmq.7 fills `Session.State`'s parent/invocation slots and the routes start
  resolving; no instruction, parser or planner clause changes.
- **`#_invokeid` as a first-class named target.** C.1 makes it a MUST and
  test192 exercises it, and it is named in neither this bead's description nor
  its acceptance criteria, nor in st-cmq.7's. It is filed as follow-up rather
  than silently absorbed here or dropped: the parser in Phase 4 gives every
  `#_`-prefixed target that is not `#_internal`, `#_parent` or `#_scxml_*` the
  `{:invoke, invokeid}` route, so nothing has to be re-parsed later, but no
  bead in the tracker today owns making that route deliver. See "Follow-up
  work".
- **Reopening 6.2.3's three-way "exactly one of `event`, `eventexpr` and
  `<content>`" constraint.** Deliberately unenforced with its reasoning in
  `lib/statifier/validator/checks/send.ex:31-71` and its own commit (`5889e3b`).
  Two W3C mandatory tests violate the letter. Nothing here touches it.
- **The BasicHTTP Event I/O processor.** Eleven tests are excluded as
  `:needs_basichttp` in `tools/corpus/scxml_w3/exclusions.exs:15-31`, "out of
  scope". This plan implements only the SCXML Event I/O processor; an
  unsupported `type` raises `error.execution`, which is what 6.2.5 asks a
  processor that does not support a type to do.
- **Multiple named runtime instances.** ADR-0027's deferred open question,
  excluded there as mechanism without a caller. Unchanged here.
- **A `Statifier.Application` callback.** ADR-0027 decision 1: the library
  ships none, and the embedder places `Statifier.Supervisor`.
- **Replay of cross-session delivery ordering.** Phase 4 makes the injected
  internal event recordable so a single session replays faithfully, and adds
  the `Replay` clauses that keeps `Statifier.Replay.run/1` from crashing on the
  new entry and the new instructions. Replaying *two* sessions' interleaving is
  not in ADR-0029's tuple and is not attempted.
- **Flipping the corpus feature atoms, or putting the corpus harness on a
  `Session`.** Both are st-cmq.9's by that bead's own description, and st-cmq.9
  depends on this bead and st-cmq.7. Consequently **no conformance test flips
  in this plan**; "Corpus/Ratchet Notes" records the per-test analysis so
  st-cmq.9 inherits it. Flipping an atom here would let a test that this bead
  cannot actually satisfy end-to-end into the ratchet, and would take st-cmq.9's
  harness decision on its behalf.

## Implementation Approach

Five phases, ordered so that the four an agent can finish alone come first and
the one that needs a human comes last.

**The strategy for the human-blocked work.** ADR-0027 requires the implementing
branch to widen `Mix.Statifier.AdrGuard.@effect_interpreter_paths` by
`lib/statifier/supervisor.ex` *and* to carry a `docs/quality-gate-changes.md`
entry with an `Approved-by:` line naming the human who made the call, stating
in as many words that "writing that entry is the human's call at implementation
time, per ADR-0011; this record specifies its contents and does not write it."
Phase 5 is therefore the only phase an agent may not complete. Everything that
does not need a registry is pulled ahead of it.

**What makes that pull-ahead possible** is that a session can resolve
`#_scxml_<its own session id>` without any registry at all: it already knows
`state.session_id` (`lib/statifier/session.ex:331`). Eleven of the fifteen
conformance tests in `test/scxml_tests/mandatory/scxml_event_processor/` target
either `#_internal`, no target, or their own `_sessionid` - test189, test190,
test348, test349, test350, test351, test352, test354, test495, test496 and
test501 (test500 is the twelfth and already passes; note this membership is
*not* the earlier draft's list, which included test500 and omitted test349) -
so Phases 1-4 are the complete engine-side answer for all eleven with no
process infrastructure -
even though, per "Current State Analysis", the corpus cannot observe that until
st-cmq.9. Phase 5 adds *cross*-session reachability, which no conformance test
exercises without `<invoke>`, and which is therefore worth nothing in the
ratchet and everything to st-cmq.7.

**The Appendix D rule** (ADR-0002). This plan adds one function to
`Statifier.Interpreter` that Appendix D does not name:
`deliver_internal/5` (Phase 4). The deviation is mechanical, not semantic.
Appendix D has a single `mainEventLoop` that blocks on `externalQueue.dequeue()`
and never returns; this engine already split that loop across the pure core and
`Session`'s `handle_continue(:drain, ...)` (`lib/statifier/session.ex:358-374`),
per ADR-0003. In the pseudocode's world a routing failure is discovered inside
the loop and `raise(error.communication)` writes the internal queue in place;
here it is discovered in the effect interpreter, which is outside the loop by
construction. `deliver_internal/5` is the re-entry that restores the
pseudocode's ordering: enqueue on the internal queue, then run to quiescence,
exactly as an in-loop `raise` would have. No selection, exit-set or entry-set
procedure changes.

### Decisions taken on assumption

Each answers a numbered open question from the research document. Any of them
is cheap to reverse inside its own phase.

1. **(Q1) `error.communication` reaches the internal queue through a new pure
   core seam, not by `Session` mutating `%MachineState{}` behind the core's
   back.** `Statifier.Interpreter.deliver_internal(machine_state, kind, name,
   origin, opts)` calls the existing `MachineState.raise_internal/4` or
   `raise_platform/4` and then `main_event_loop/1`, returning
   `{:ok, machine_state, effects}` in exactly `handle_event/2`'s shape.
   *Assumed*: that ADR-0003's ban is on side effects in the core, not on the
   session calling pure core functions - which is what `Interpreter.cancel/1`
   already is. Overturned if a reviewer wants routing itself moved into the
   core (research option (c)), which would mean the core knowing about live
   sessions and is a bigger ADR than this one.
2. **(Q2) The error event's `Cause.origin` is the originating `<send>`'s
   `{:content, c_index, owner}`**, which `Effect.Send` and `Effect.SendDelayed`
   already carry. No new `Cause.origin/0` arm
   (`lib/statifier/event/cause.ex:133-141`) and no `Cause` change at all. The
   counters `Cause.new/4` stamps are the *current* ones, which for a delayed
   send are later than the ones on the effect. *Assumed*: that a cause answers
   "when did this happen" for the counters and "what code is responsible" for
   the origin, and those are legitimately different moments for a delayed send.
   The effect's own stored `macrostep`/`microstep` remain visible to a
   subscriber on the `{:notify, effect}` that preceded it.
3. **(Q3) `sendid` on the error event is the triggering `<send>`'s send id,
   unconditionally.** 5.10.1: "in the case of error events triggered by a
   failed attempt to send an event, the Processor MUST set this field to the
   send id of the triggering `<send>` element." That sentence carries no
   "if the author specified id", unlike C.1's rule for delivered events.
   `Event.platform/3` and `raise_platform/4` gain a `sendid:` opt.
4. **(Q4) The delivered event's `sendid` is empty when the author wrote
   neither `id` nor `idlocation`, and the effect gains one boolean to say
   so.** `Effect.Send` and `Effect.SendDelayed` gain `id_from_author?`, set by
   `build_effect/6` from `node.id != nil or node.idlocation != nil`. The
   alternatives were both worse: populating unconditionally is a knowing C.1
   violation, and not minting a send id would break `<cancel>`-by-generated-id
   and ADR-0035's counter. The field has a reader in the same phase that adds
   it, so the no-dead-field rule holds.
5. **(Q5) `_ioprocessors[URI]['location']` becomes `"#_scxml_" <> session_id`.**
   It is simultaneously C.1.1's "address that external entities can use to
   communicate with this SCXML session", C.1's delivered `origin`, and
   5.10.1's "a value which, when used as the value of 'target', will allow the
   receiver ... to `<send>` a response back". Only the prefixed form satisfies
   all three. test501 (`targetexpr` over the location) and test349 (`<send>` to
   the received `_event.origin`) are the corpus tests that will distinguish the
   two forms; test500 asserts only `Var1 !== undefined` and passes either way,
   which is why it passes today. `_sessionid` stays the bare `sess_` UXID; only
   `location` changes.
6. **(Q6) The router accepts both `#_internal` and `_internal`.** 6.2.2's
   attribute table says `"_internal"`; C.1 says `'#_internal'`; the two clauses
   of the spec disagree and the corpus (test189, test495) writes `#_internal`.
   Accepting both is a strict superset that fails no test. `Checks.Send`'s
   `delay_and_internal_target/2` (`lib/statifier/validator/checks/send.ex:210-216`)
   widens to both spellings for the same reason.
7. **(Q7) `#_parent` is reserved here, delivered by st-cmq.7; `#_invokeid` is
   parsed here and owned by neither bead.** See "What We're NOT Doing" and
   "Follow-up work". This plan follows the bead's own description over
   `docs/architecture.md:125-139`, which the bead post-dates, and Phase 4 fixes
   the architecture doc's sentence to say so.
8. **(Q8) The unsupported-`type` check lives in `Session.Effects.plan/1`, not
   in `Machine.Content.Send.execute/2`.** The set of supported Event I/O
   processors is a property of the effect interpreter, and the core has no
   access to it (and under ADR-0003 should not). The core stays type-blind and
   carries `type` through as it does today.
9. **(Q9) Yes - and it blocks Phase 5 only.** See the Phase 5 header.
10. **A session is always accessible to itself, registry or not.** Phase 4
    resolves `{:session, sid}` with `sid == state.session_id` to the session's
    own inbox before any lookup, and Phase 5 leaves that branch alone: it adds
    `Registry.lookup/2` to the *other* branch only. This is a real, permanent
    narrowing of ADR-0027 decision 2, which states the mechanism for
    `#_scxml_<sessionid>` uniformly as `Registry.lookup(Statifier.Registry,
    sessionid)` and ties accessibility to registration ("an unregistered
    session is an inaccessible one"). Read strictly, a bare
    `Session.start_link/2` session addressing itself would get
    `error.communication`. It is declared here rather than left implicit.
    *Assumed*: that C.1's "a session that does not exist or is inaccessible"
    cannot describe the sending session itself - it demonstrably exists, and
    the Processor demonstrably reaches it, since it is the one doing the
    sending. Registration is how *other* sessions find it, and ADR-0027's
    sentence is about that. Overturned if a reviewer wants `#_scxml_<self>` to
    fail on an unregistered session, which would make the ratchet depend on how
    a session was started and would break test190, test349, test350 and test501
    under any harness that does not register.
11. **`origintype` is the SCXML Event I/O Processor's type URI, not the string
    `"scxml"`.** An earlier draft of this plan said the opposite and cited
    test352 as asserting it; test352 asserts the URI. Read the file: it assigns
    `Var1` from `_event.origintype` and then takes
    `cond="Var1=='http://www.w3.org/TR/scxml/#SCXMLEventProcessor'"` to `pass`
    (`test/scxml_tests/mandatory/scxml_event_processor/test352_test.exs:35-40`).
    The W3C's own prose disagrees with the W3C's own test here: C.1 says the
    field "MUST have the value \"scxml\"" (`scxml-rec.html:5159-5161`), while
    5.10.1 says `origintype` "is equivalent to the 'type' field on the `<send>`
    element" and must be usable *as* a `type` value (`:3457-3466`) - and the
    document under test wrote the URI in `type`. *Assumed*: that the executable
    test is the better evidence of intent than the prose bullet it contradicts,
    and that 5.10.1's "equivalent to the 'type' field" is the reading that
    makes both clauses true at once. `Target.supported_type?/1` accepts both
    spellings, so a response addressed with either round-trips. Cheap to
    reverse: it is one literal in `Session.Effects`. Nothing in *this* bead
    tests it either way - test352 cannot run until st-cmq.9 - so record the
    choice loudly and let st-cmq.9 be the first to run the judgment.

## Phase 1: Record the internal re-entry seam as ADR-0037

### Overview

Write the architecture decision that Phases 4 and 5 implement, so the seam is
argued once in the record rather than four times in code review. Documentation
only; no Elixir changes, so per this repo's authority table there is no gate to
run and the phase commits on review of the diff.

### Changes Required:

#### 1. New ADR

**File**: `docs/adr/0037-session-detected-send-failures-re-enter-the-core.md`
**Changes**: New record. The highest ADR on disk is 0036, so 0037 is the next
free number.

Content, in the repo's ADR shape (Status / Context / Decision / Consequences):

- **Context.** Spec 6.2.4 and C.1 put both send failures on the *internal*
  queue of the *sending* session. Under ADR-0003 the failure is discovered in
  `Statifier.Session` (a registry lookup miss, or a target string the router
  does not accept), and `Session` has no write path to `%MachineState{}`'s
  internal queue: its only inputs are `Interpreter.handle_event/2` and
  `Interpreter.cancel/1`, and `handle_event/2` hardcodes `from: :external`
  (`lib/statifier/interpreter.ex:430-453`). Appendix D has no such split
  because its `mainEventLoop` never returns.
- **Decision.** One new pure entry point,
  `Statifier.Interpreter.deliver_internal/5`, taking `(machine_state, kind,
  name, origin, opts)` with `kind :: :internal | :platform`. It delegates to
  `MachineState.raise_internal/4` or `raise_platform/4` - the existing, unique
  internal-queue writers - and then runs `main_event_loop/1` to quiescence,
  returning `handle_event/2`'s exact `{:ok, machine_state, effects} |
  {:error, :not_running}` shape. `Session` never touches `%MachineState{}`'s
  queues directly. Record the two alternatives rejected: `Session` calling
  `MachineState.raise_platform/4` itself and re-driving the loop (leaves the
  queue write outside any core entry point, so a future core invariant on
  enqueue has no chokepoint), and moving target routing into the core (makes
  the core aware of live sessions, which ADR-0003 forbids outright).
- **Consequences.** It is a recordable session-side input, so `Recording` gains
  an entry per ADR-0029 and `docs/observability.md` constraint 6. It is the
  path for `<send target="#_internal">` too, not only for errors, so `:internal`

## Phase 4: The target vocabulary, the router, and both error events

### Overview

The bead's centre of gravity, and the last phase an agent can finish alone.
Parse the target vocabulary, plan every route, deliver what is reachable
without a registry (self and `#_internal`), and turn everything else into
`error.communication` or `error.execution` on the sender's internal queue via
ADR-0037's seam. After this phase the engine is the complete answer for eleven
of the fifteen `scxml_event_processor` conformance tests - which none of them
can demonstrate until st-cmq.9 flips the feature atoms and puts the corpus
harness on a `Session`, so this phase's evidence is unit tests.

### Changes Required:

#### 1. The target parser

**File**: `lib/statifier/session/target.ex` (new)
**Changes**: one pure module, no process, no effect calls - so
`Mix.Statifier.AdrGuard` has nothing to say about it and no exemption is
needed.

```elixir
@type route ::
        :self
        | :internal
        | {:session, String.t()}
        | :parent
        | {:invoke, String.t()}
        | {:invalid, String.t()}

@spec parse(target :: String.t() | nil) :: route()
def parse(nil), do: :self
def parse("#_internal"), do: :internal
# 6.2.2's attribute table spells it `_internal`, C.1 spells it `#_internal`,
# and the two clauses disagree with each other. Accepting both is a superset
# that fails no test; the corpus writes the `#_` form.
def parse("_internal"), do: :internal
def parse("#_parent"), do: :parent
def parse("#_scxml_" <> session_id) when session_id != "", do: {:session, session_id}
# C.1's `#_invokeid`. An id naming no live invocation is "a session that does
# not exist or is inaccessible" (C.1) - error.communication, not
# error.execution. Resolution is the session's job, not the parser's.
def parse("#_" <> invokeid) when invokeid != "", do: {:invoke, invokeid}
# Anything else is 6.2.4's "not supported or invalid" -> error.execution.
def parse(other), do: {:invalid, other}
```

Also the supported-type predicate, since it is the same kind of knowledge:

```elixir
@spec supported_type?(type :: String.t() | nil) :: boolean()
def supported_type?(nil), do: true
def supported_type?("scxml"), do: true
def supported_type?(type), do: type == SystemVariables.scxml_event_processor()
```

`"scxml"` is 6.2.5's explicitly-permitted short form ("Processors MAY define
short form notations"), which this bead's description commits to. Note the
modality in the `@doc`: the alias is a MAY we chose, not a MUST.

#### 2. The instruction vocabulary

**File**: `lib/statifier/session/effects.ex`
**Changes**: replace the two `{:unroutable, effect}` send clauses with routing.
Two new instructions, and `{:schedule, ...}` gains a route so a *delayed*
cross-session send resolves at fire time rather than being silently
self-delivered:

```elixir
@type instruction ::
        {:notify, Effect.t()}
        | {:enqueue_event, Event.t()}
        | {:deliver, Target.route(), Event.t(), Effect.t()}
        | {:raise, kind, name :: String.t(), Cause.origin(), keyword()}
        | {:schedule, send_id, delay_ms, Target.route(), Event.t(), Effect.t()}
        | {:cancel_timers, send_id :: String.t()}
        | {:unroutable, Effect.t()}
        | {:halt, :done | :budget_exhausted}
```

`{:unroutable, _}` stays for `:invoke`, `:cancel_invoke` and `:autoforward`,
which are st-cmq.7's, so this phase narrows it rather than removing it.

Planning, per send effect, in order:

1. `Target.supported_type?(send.type) == false` ->
   `{:raise, :platform, "error.execution", {:content, send.c_index, send.owner},
   [sendid: send.send_id]}` (6.2.5). No delivery, no timer.
2. `Target.parse(send.target)` is `{:invalid, _}` -> the same `error.execution`
   (6.2.4's "not supported or invalid").
3. `:self` -> `{:enqueue_event, event}`, unchanged from today.
4. `:internal` -> `{:deliver, :internal, event, effect}` where `event` is built
   by `Event.internal/3` with blank `origin`/`origintype` (5.10.1) and
   `sendid: if(send.id_from_author?, do: send.send_id)` per Phase 3's rule.
   This is the caller Phase 3's `:sendid` opt on `internal/3` exists for.
5. `{:session, sid}`, `:parent`, `{:invoke, id}` ->
   `{:deliver, route, event, effect}` with the external event of Phase 3.
6. Delayed sends take the same route through `{:schedule, ...}` instead, and
   the type/target errors above fire at *execution* time, not at fire time -

   `<send>` element is evaluated, and not when the message is actually
   dispatched."

#### 3. The core re-entry seam

**File**: `lib/statifier/interpreter.ex`
**Changes**: add `deliver_internal/5` as decided in ADR-0037, with an inline

```elixir
# Appendix D discovers a routing failure inside `mainEventLoop` and writes the
# internal queue in place. ADR-0003 puts routing in the effect interpreter,
# which is outside that loop by construction, so ADR-0037 gives the session one
# way back in: enqueue on the internal queue exactly as an in-loop `raise`

@spec deliver_internal(
        MachineState.t(),
        :internal | :platform,
        String.t(),
        Cause.origin(),
        keyword()

  do: {:error, :not_running}

def deliver_internal(%MachineState{} = machine_state, kind, name, origin, opts) do

    case kind do
      :internal -> MachineState.raise_internal(machine_state, name, origin, opts)
      :platform -> MachineState.raise_platform(machine_state, name, origin, opts)
    end

  {machine_state, effects} = main_event_loop(machine_state)

end
```

## Phase 5: The ADR-0027 session runtime (BLOCKS ON A HUMAN)

### Overview

`Statifier.Supervisor`, `Statifier.Registry`, `Statifier.SessionSupervisor`,
registration in `Session.init/1`, `restart: :temporary`, the public
start-through-the-runtime helper, and real cross-session `#_scxml_<sessionid>`
delivery.

**This phase cannot be completed or committed unattended.** ADR-0027 requires
the implementing branch to widen
`Mix.Statifier.AdrGuard.@effect_interpreter_paths` by exactly one path and to
carry a `docs/quality-gate-changes.md` entry with an `Approved-by:` line naming
the human who made the call, and states in as many words that "writing that
entry is the human's call at implementation time, per ADR-0011; this record
does not write it." No agent may write an `Approved-by:` line for itself.

Two things about the mechanics, so nobody is surprised:

- **The gate does not mechanically stop this phase.** `Mix.Statifier.GateGuard`
  guards `.quality.exs`, `.credo.exs`, `coveralls.json`, `.sobelow-conf`,
  `.doctor.exs`, gate-relevant `mix.exs` lines, `@tag :skip`, and a shrinking
  `test/passing_tests.json` (`lib/mix/statifier/gate_guard.ex:36-52`).
  `lib/mix/statifier/adr_guard.ex` is not among them, and a module-based
  `use Supervisor` matches none of `@effect_call_pattern`'s alternatives
  (`lib/mix/statifier/adr_guard.ex:93-98`). So this phase's code would go green
  with no ledger entry at all.
- **That is precisely the hole ADR-0027 forbids riding.** It says the exemption
  list "is the design statement, and riding a pattern gap instead of amending
  it would be the hole the guard's own comment disclaims." Committing this
  phase without the amendment would be an agent quietly choosing the cheaper
  reading of an accepted ADR. The block here is a policy block, not a red gate,
  and it is the stronger of the two.

An implementing agent that reaches this phase should stop, report that Phases
1-4 are complete and committed, and hand the human the ledger text below to
approve. Phases 1-4 are a coherent, shippable increment on their own: they are
the engine-side answer for eleven conformance tests, banked against st-cmq.9,
and they leave `#_parent`, `#_invokeid` and cross-session sends taking C.1's
mandated `error.communication` path, which is correct behavior rather than a
stub.

### Changes Required:

#### 1. The supervisor

**File**: `lib/statifier/supervisor.ex` (new)
**Changes**: ADR-0027 decision 1, verbatim - a module-based supervisor whose
children are, in order, `{Registry, keys: :unique, name: Statifier.Registry}`
then `{DynamicSupervisor, name: Statifier.SessionSupervisor}`, strategy
`:rest_for_one`. One default-named instance; no `:name` option (ADR-0027's
deferred open question). The moduledoc states that the embedder places it and
that the library ships no application callback.

#### 2. Registration and restart

**File**: `lib/statifier/session.ex`
**Changes**: `use GenServer, restart: :temporary` at `:113` (ADR-0027 decision
4, which also says to keep writing the option explicitly). In `init/1`, after
`session_id` is read off the datamodel at `:331`, register with
`Registry.register(Statifier.Registry, session_id, nil)` - and only when the
registry is running, so a bare `Session.start_link/2` stays legal and
unregistered, which ADR-0027 decision 2 and C.1's "accessible ... is
platform-dependent" both sanction. A registration failure is never fatal to the
session.

#### 3. The public start helper

**File**: `lib/statifier.ex`
**Changes**: ADR-0027 leaves this name and signature explicitly to this bead.
Add `Statifier.start_session(machine, opts \\ [])`, wrapping
`DynamicSupervisor.start_child(Statifier.SessionSupervisor, {Statifier.Session,
{machine, opts}})`, returning `{:ok, pid} | {:error, term}`. Note in the `@doc`
that a session started this way is registered and therefore reachable by
`#_scxml_<sessionid>`, and one started by bare `Session.start_link/2` is not.
`lib/statifier.ex` is outside `@core_prefix` ("lib/statifier/"), so this adds no
exempt path.

#### 4. Real resolution

**File**: `lib/statifier/session.ex`
**Changes**: the `{:session, sid}` resolver from Phase 4 gains its registry
lookup ahead of the failure path: `Registry.lookup(Statifier.Registry, sid)`,
`[{pid, _}]` -> `Session.send_event(pid, event)`; `[]` -> the existing
`communication_error/3`, unchanged. An empty lookup covers all three cases
ADR-0027 names (never existed, named a bare session, named a dead one) and is
never a crash. No planner, parser or instruction change.

#### 5. The guard amendment

**File**: `lib/mix/statifier/adr_guard.ex`
**Changes**: `@effect_interpreter_paths` widens from `["lib/statifier/session.ex"]`
to `["lib/statifier/session.ex", "lib/statifier/supervisor.ex"]`. ADR-0027:
"a second new path is a smell to be argued, not defaulted." Extend the comment
above it to name the session runtime rather than only `Statifier.Session`.

#### 6. The ledger entry - THE HUMAN'S, NOT AN AGENT'S

**File**: `docs/quality-gate-changes.md`
**Changes**: an entry a human writes and signs. ADR-0027 specifies its contents
exactly; this is the text to hand them for approval, not text to commit
unsigned. Quoted rather than fenced, so its own `##` heading line does not read
as a section boundary of this plan; strip the `> ` prefix when using it:

> ## 2026-08-15 - st-cmq.5
>
> Approved-by: \<human\>

>
> - lib/mix/statifier/adr_guard.ex: widens @effect_interpreter_paths from
>   ["lib/statifier/session.ex"] to the named session-runtime set, adding
>   lib/statifier/supervisor.ex

  route showing the instruction list in order, including that `{:notify, _}`

- `test/statifier/session_test.exs`: the performing half. Self-delivery by
  `#_scxml_<own id>`; `#_internal` landing on the internal queue with blank
  `origin`/`origintype`; `error.communication` carrying the failing send's

  `test/statifier/evaluator/system_variables_test.exs`: the three new fields on
  the struct and their appearance on `_event`, including the C.1 empty-`sendid`

  including `{:error, :not_running}`.
- `test/statifier/replay_test.exs`: a recorded run containing an `#_internal`
  send, a failed `#_scxml_<unknown>` send and a delayed send, replayed to the
  same final configuration. This is the only place the fifth `apply_entry/2`
  clause, the two new `perform_instruction/3` clauses and the widened
  `{:schedule, ...}` clause are exercised - the gate does not record or replay
  anywhere else.
- **Stand-ins for the eleven conformance tests this bead answers but cannot
  run** (Phase 4's criteria list the four): each is a hand-written unit test

  rather than at st-cmq.9. Name the corpus test in a comment on each so
  st-cmq.9 can retire the stand-in if it becomes redundant.
- Registry tests (Phase 5) `start_supervised!(Statifier.Supervisor)` per
  ADR-0027 decision 1, never a globally started tree.

Every test asserting `lib/` behavior gets its sabotage note per CLAUDE.md:

### Manual Testing Steps

1. Compile a two-session document by hand in IEx, start both through
   `Statifier.start_session/2`, and send between them by `#_scxml_<id>`;
   confirm the receiving session's `_event.origin` is the *sender's*
   `_ioprocessors` location and `_event.origintype` is the SCXML Event I/O
   Processor URI (decision 11), and that sending back to that `origin` reaches
   the original sender - which is test349's round trip, done by hand.
2. Send to `#_scxml_totally_made_up` and confirm `error.communication` arrives
   on the sender with `_event.sendid` equal to the failing `<send>`'s id, and
   that neither process crashed.
3. Send with `type="http://www.w3.org/TR/scxml/#BasicHTTPEventProcessor"` and
   confirm `error.execution`, no delivery, and no timer.
4. Kill a receiving session, then send to its id, and confirm the sender gets
   `error.communication` rather than a crash or a hang.
5. Read `deliver_internal/5` beside Appendix D's `mainEventLoop` and confirm
   the only difference is the re-entry, not the ordering.

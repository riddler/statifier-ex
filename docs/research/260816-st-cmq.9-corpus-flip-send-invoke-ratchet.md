# Research: the Phase 4 corpus closer (st-cmq.9)

**Date**: 2026-08-16T12:46:30-0600
**Git Commit**: d3c9226778125ac1a08a7d28ab8655451fe5e5a5
**Branch**: st-cmq.9-corpus-send-invoke-ratchet
**Bead**: st-cmq.9

## Research Question

st-cmq.9 is the Phase 4 corpus closer. It flips ten feature atoms to
`:supported` in the feature registry, requires conformance corpus tests that
need real delivery, timers, and child sessions to run through the Session layer
rather than bare `Interpreter` calls, and ratchets newly passing files into
`test/passing_tests.json` in the same PR.

What exists today across: the feature registry and detector, the corpus harness
(`Statifier.Case` and its four-function contract), how the Session layer is
exercised in existing tests, how the ratchet tasks work, and what Phase 3's
analogous bead (st-af3.8) did as the precedent to follow.

## Summary

The bead sits on a codebase where every piece of engine work it depends on has
already landed. All eleven Phase 4 sub-beads except two P3 extensions
(`st-cmq.2` OpenTelemetry design, `st-cmq.8` handler-registry invoke) are
closed, and `st-xcgr` (`#_invokeid` delivery, the last known corpus blocker in
`lib/`) merged to `main` via PR #157. What is left is harness work plus a
registry flip plus a `mix test.baseline --add` run.

Four findings shape the work:

1. **The flip is the last feature gate the corpus has.** Of 281 generated
   corpus files on disk, 174 are in the ratchet and 107 are not. **106 of those
   107 are blocked on exactly these ten atoms**; the one remaining file is
   `test/scxml_tests/mandatory/data/test552_test.exs`, already feature-clean and
   failing on behavior (ADR-0024, bead `st-bnr`). After the flip,
   `feature_registry/0` contains **zero** `:unsupported` entries - every atom
   becomes `:supported` except `script_elements`, which stays `:partial`. The
   feature gate in `Statifier.Case` becomes a no-op for the corpus.

2. **The harness has no Session path at all today.** `test/support/case.ex`
   drives charts synchronously through `Statifier.compile/1`,
   `Statifier.initialize/2`, `Statifier.send_event/2`,
   `Statifier.active_leaf_states/1`. No corpus test has ever started a process.
   Meanwhile every existing Session test lives in `test/statifier/session*`, is
   hand-written, reimplements a `wait_for_status/3` poller per file, and the
   `<invoke>` files are `async: false` because `Statifier.Supervisor` uses fixed
   module-qualified names. Generated corpus tests are all `use Statifier.Case,
   async: true`.

3. **Timers are real wall-clock, with no injection seam.** There is no fake
   clock anywhere in the repo; `Statifier.Session` calls
   `Process.send_after/3` directly. 73 of the untracked files carry a `delay=`
   or `delayexpr=` attribute, with values from `1ms` to `20s`. Most of the
   second-scale ones are W3C `timeout` guards that must *not* fire, but at
   least one SCION file (`delayed_send/send1_test.exs`) asserts a configuration
   *before* a 10ms delayed send arrives and a later one *after* it - so
   "quiescence" for the harness cannot mean "no pending timers".

4. **Growing the ratchet is unguarded; only shrinking it is a finding.**
   `test/passing_tests.json` is absent from `GateGuard`'s `@guarded_paths`, and
   `ratchet_findings/1` fires only on a set-difference removal. No
   `docs/quality-gate-changes.md` entry is needed for the ratchet growth, and
   st-af3.8's plan says so explicitly.

### The harness today: `Statifier.Case` and the four-function contract

`test/support/case.ex` is the entire coupling surface between the corpus and
the library (ADR-0006). `test_scxml/4` ([`test/support/case.ex:83-98`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/test/support/case.ex#L83-L98)) does four
things in order: `validate_features!/2` flunks with the feature named if any
detected atom is not `:supported`/`:partial`; `parse_document/1` wraps
`Statifier.compile/1`; `initialize/1` wraps `Statifier.initialize/2`; then a
`reduce` over the event list calling `send_event/2` (over
`Statifier.send_event/2`) and asserting after each.

Two assertion-side reads sit alongside the four driving functions and are
documented as *not* a fifth driving function
([`test/support/case.ex:26-40`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/test/support/case.ex#L26-L40)): `observed_state_chart/2`
([`test/support/case.ex:139-144`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/test/support/case.ex#L139-L144)) restores a terminated chart's configuration
from the `{:done, _}` effect's `configuration` field, and
`assert_every_leaf_named/2` ([`test/support/case.ex:151-157`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/test/support/case.ex#L151-L157)) compares the raw
index-keyed leaf count against the id-translated set to catch an anonymous
active leaf.

`test_scxml/4` takes only `(xml, description, expected_initial_config, events)`
- it has no ExUnit context, so the emitted `@tag required_features:` list is not
visible to it. It does, however, already compute the detected feature set
itself, at [`test/support/case.ex:101`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/test/support/case.ex#L101), which is the routing signal available
with no generator change.

The harness's own coverage is `test/statifier/case_test.exs`; note that the
existing "flunks naming every unsupported feature" test there uses a `<send>`
document and asserts the message contains `"send_elements"` - it breaks on the
flip and needs a different example.

### The Session layer as a driving surface

`Statifier.Session` (`lib/statifier/session.ex`) is the GenServer effect
interpreter and the only ADR-0003 exempt path that may do I/O. The client API
relevant to a harness:

- `Session.start_link(machine, opts)` ([`lib/statifier/session.ex:364`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/session.ex#L364)) - runs
  `Interpreter.initialize/2` to quiescence *before returning*, so a session can
  come up already `:running`, `:done`, or `:budget_exhausted`. Options include
  `:subscribers` (pids monitored from start), `:trace`, `:datamodel`,
  `:invoke_source`, `:record`.
- `Statifier.start_session(machine, opts)` ([`lib/statifier.ex:176-196`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier.ex#L176-L196)) - the
  registered variant, `DynamicSupervisor.start_child/2` onto
  `Statifier.SessionSupervisor`. Required for cross-session
  `#_scxml_<sessionid>` delivery and for `<invoke>` children, and it requires
  `Statifier.Supervisor` already placed.
- `Session.send_event(server, event | name)` ([`lib/statifier/session.ex:394`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/session.ex#L394)) -
  a `GenServer.cast`, asynchronous; `:ok` returns before processing.
- `Session.snapshot(server)` ([`lib/statifier/session.ex:464`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/session.ex#L464)) - the whole
  `%MachineState{}`, which `Statifier.active_leaf_states/1` accepts directly.
- `Session.status(server)` ([`lib/statifier/session.ex:475`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/session.ex#L475)) - the cheap
  projection: `session_id`, `status`, `configuration` (translated to string
  ids - the **full** configuration, not the leaf view), `macrostep`,
  `microstep`, `round`, `queued_events`, `pending_timers`. Type at
  [`lib/statifier/session.ex:315-324`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/session.ex#L315-L324); built by `build_status/1` at
  [`lib/statifier/session.ex:1367-1382`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/session.ex#L1367-L1382), whose
  `status_and_configuration/1` performs the same done-effect restore
  `Statifier.Case` does, citing [`test/support/case.ex:23-32`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/test/support/case.ex#L23-L32) in its comment.
- `Session.cancel/1`, `Session.stop/2`, `Session.subscribe/2`.

Because `active_leaf_states/1` still does the index-to-id translation and
`Statifier.compile/1` still does the parse, a session-driven path replaces two
of the four functions (`initialize`, `send_event`) with `start_link`/`send_event`
on `Statifier.Session` while keeping the other two intact.

**Supervision.** `Statifier.Supervisor` (`lib/statifier/supervisor.ex`) is
module-based, `:rest_for_one`, holding `{Registry, keys: :unique, name:
Statifier.Registry}` then `{DynamicSupervisor, name:
Statifier.SessionSupervisor}` - fixed names, no `:name` option, never started
automatically (ADR-0027 decision 1, no `mod:` in `mix.exs`).

**Child sessions.** `{:invoke, _}` is performed at
[`lib/statifier/session.ex:963-968`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/session.ex#L963-L968): resolve through
`Statifier.Invoke.Source.resolve/2` ([`lib/statifier/invoke/source.ex:64`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/invoke/source.ex#L64)),
seed the child datamodel per 6.4.3 ([`lib/statifier/session/invocations.ex:146-150`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/session/invocations.ex#L146-L150)),
then `Statifier.start_session(machine, invoked_by: {self(), invoke_id}, ...)`.
The child monitors the parent ([`lib/statifier/session.ex:564-570`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/session.ex#L564-L570)); a dead
parent stops it. `done.invoke.<id>` is built by `return_done_event/2`
([`lib/statifier/session.ex:1044-1058`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/session.ex#L1044-L1058)) only on a `:done` halt. `<finalize>`
runs inside the pure core, not the session. `#_<invokeid>` resolves through the
parent's `Invocations` table ([`lib/statifier/session.ex:1228-1237`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/session.ex#L1228-L1237)).
`{:cancel_invoke, _}` ([`lib/statifier/session.ex:1001-1011`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/session.ex#L1001-L1011)) calls
`Session.cancel/1` on the child, not `stop/2`, so its `<onexit>` handlers run.

**Timers.** `{:schedule, ...}` is performed at
[`lib/statifier/session.ex:932-947`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/session.ex#L932-L947) with a real `Process.send_after/3`; firing
arrives as `handle_info({:statifier_delayed_send, ...})` at
[`lib/statifier/session.ex:723-735`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/session.ex#L723-L735), which resolves the route only at fire time
(spec 6.2.3). `Statifier.Session.Timers`
([`lib/statifier/session/timers.ex:15-17`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/session/timers.ex#L15-L17)) deliberately calls neither
`Process.send_after/3` nor `Process.cancel_timer/1` - only `Session` does.
There is no clock-injection seam, no test mode, and no flush/advance helper
anywhere in the repo.

**Telemetry.** `Statifier.Session.Telemetry`
(`lib/statifier/session/telemetry.ex`) is the sole emission surface, with
`events/0` at [`lib/statifier/session/telemetry.ex:252-257`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/lib/statifier/session/telemetry.ex#L252-L257) enumerating the 7
lifecycle/span, 9 effect and 9 trace event names (ADR-0040). Nothing in the
test suite currently attaches to it as a synchronization primitive; it is
available via `:telemetry.attach_many/4` if a harness wanted a specific event
name or `span_ref` instead of polling.

   [`test/statifier/session/invoke_cancel_test.exs:69-81`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/test/statifier/session/invoke_cancel_test.exs#L69-L81),
   [`test/statifier/session/invoke_integration_test.exs:35-47`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/test/statifier/session/invoke_integration_test.exs#L35-L47),
   [`test/statifier/session/send_cancel_test.exs:33-46`](https://github.com/riddler/statifier-ex/blob/d3c9226778125ac1a08a7d28ab8655451fe5e5a5/test/statifier/session/send_cancel_test.exs#L33-L46),

### The delay semantics the corpus actually asserts

`test/scion_tests/delayed_send/send1_test.exs` is the sharpest case. Its
document sends `s` with `delay="10ms"` on the `t1` transition, and the emitted
expectations are `["a"]` initially, `["b"]` after `t1`, `["d"]` after `t2`. So
the harness must assert `["b"]` *before* the 10ms send lands, and `t2` must
arrive *after* it (the chart has to have moved a -> b -> c for `t2` to reach
`d`). A quiescence rule of "wait until `pending_timers == 0`" makes the first
assertion fail; a rule of "assert as soon as `queued_events == 0`" makes the
second depend on the wall clock between two assertions.

Delay values across the whole corpus: literal `delay=` is `1s` x22, `2s` x17,
`5s` x11, `3s` x8, `10ms` x3, `2ms` x1, `20s` x1, `1ms` x1; `delayexpr=` is
`'1s'` x13, `'2s'` x4, `'1.5s'` x4, `'.5s'` x3, `'10ms'` x2, and `Var1` x1.
The second-scale values are overwhelmingly W3C `timeout` guards - a
`<send event="timeout" delay="5s"/>` that a passing run must never let fire -
rather than delays a test waits on.

## Architecture Documentation

- **ADR-0006** - reuse the conformance corpus and the regression ratchet; the
  corpus touches no library internals, everything goes through `Statifier.Case`.
- **ADR-0011** - gate config is not agent-editable; remaining reds are bugs to
  file, never `@tag :skip` and never a corpus exclusion. Mechanically enforced
  by `mix gate.check`'s skip-tag scan and the ratchet-shrink check.
- **ADR-0003** - pure core with effects; `lib/statifier/session.ex`,
  `supervisor.ex` and `session/telemetry.ex` are the only exempt paths.
- **ADR-0027** - embedder-placed session runtime with a named registry;
  `Statifier.Supervisor` is never started automatically, its child names are
  fixed, sessions are `restart: :temporary`, and parent/child lifetime is an
  ownership protocol via monitors rather than supervision nesting.
- **ADR-0029** - `Session.interpret/2` stays public; replay records four inputs.
- **ADR-0031** - a failed `<invoke>` argument evaluation aborts that invocation
  and raises `error.execution`, leaving siblings alone.
- **ADR-0032** - the macrostep round budget spans the invoke re-entry, and
  terminal effects are emitted exactly once per `main_event_loop/1` call.
- **ADR-0034** - replay re-drives the pure core, not a live session.
- **ADR-0035 / ADR-0036** - the send id is a `%MachineState{}` counter; a failed
  `<send>` argument evaluation discards the message.
- **ADR-0038** - `<invoke>`'s source resolves at the session boundary; the
  library never fetches `src`.
- **ADR-0039** - session-detected send failures re-enter the core through
  `Interpreter.deliver_internal/5`.
- **ADR-0040** - the session telemetry event contract.
- **ADR-0041** - `<content>` markup lowers to a source slice, compiled at invoke
  time; this is what st-53ys landed and what leaves 25 documents waiting on the
  `invoke_elements` flip.
- **ADR-0024** - `<data src>` is never fetched, which is why `test552` is the one
  untracked file the flip does not explain.

Repo conventions the work inherits: provenance comments (`# st-cmq.9`) above
each flipped registry row and each `@supported_features` addition; sabotage
notes on every test asserting `lib/` behavior, with generated corpus files
exempt and harness plumbing stating `# sabotage: n/a - ...`; a
`changelog.d/st-cmq.9.md` fragment only if the change is user-facing; commit
titles under 50 chars in simple present tense with a `Refs:` trailer.

   `test/scion_tests/delayed_send/send1_test.exs` asserts a configuration that

   correct *after* it. A single quiescence predicate cannot satisfy both;
   nothing in the repo settles what the harness should do here.
3. **How do 27 `async: true` invoke corpus files coexist with a globally-named
   `Statifier.Supervisor`?** Every existing invoke test is `async: false` for

   harness starts the supervisor differently, or the async claim changes.
4. **What does the ~2 minutes of wall-clock delay cost the gate?** The
   `Regression ratchet` stage and the built-in `Tests` stage both run the corpus
   once green. The second-scale `timeout` guards should never fire in a passing
   run, but the sub-second delays are load-bearing and real.

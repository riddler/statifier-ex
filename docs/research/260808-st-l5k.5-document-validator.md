# Research: st-l5k.5 - Validates the Document

**Date**: 2026-08-08T10:20:58-0600
**Git Commit**: aad8c639414829f0ce11f2a5c5c21c68d0e54c4d
**Branch**: st-l5k.5-document-validator
**Beads Issue**: st-l5k.5

## Research Question

What does the current codebase provide for, and demand of, a `Document`
validator implementing st-l5k.5's ten numbered checks? Specifically: the
`%Statifier.Document{}` shape and every nested struct; how source locations
and `attribute_locations` survive lowering and what span shape an error would
report; the existing error struct and error-code conventions; the v1
reference validator at `../statifier`; what W3C SCXML 3.2.1 / 3.3 / 3.6 / 3.7
/ 3.10 / 3.14 actually require; and the test conventions a validator test file
would follow. Every place where a stated check conflicts with what the
`Document` can express, or needs information lowering discards, is flagged
explicitly.

## Summary

The substrate is in place and was designed for this bead. Lowering deliberately
builds every malformed shape the ten checks exist to report - that is stated in
as many words in [`lib/statifier/document/state.ex:43-62`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document/state.ex#L43-L62) (a per-field table
naming the st-l5k.5 check that catches each misuse) and in the st-l5k.4 plan's
"lowering must not reject malformed shapes". No `Statifier.Validator` module
exists in `lib/`; the layer is empty.

Eight of the ten checks are directly expressible against `%Statifier.Document{}`
as it stands. Two are not, and both gaps are in information lowering discards
rather than in the tree shape:

1. **Check 5's "type is shallow or deep" is unimplementable from a `%Document{}`
   alone.** `Statifier.Lowering.Attributes.atom/4` maps an unrecognised value to
   the default ([`lib/statifier/lowering/attributes.ex:67-73`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/lowering/attributes.ex#L67-L73)), so `type="sideways"`
   and `type="shallow"` both arrive as `history_type: :shallow`. The span
   survives in `attribute_locations[:type]`, but the offending string does not,
   and the validator has no source binary to slice it back out of.
2. **Check 9's "the root element declares `xmlns=...`" false-positives on a
   prefix-declared root.** `Document.xmlns` is the literal `xmlns` attribute
   string ([`lib/statifier/lowering/builders.ex:65`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/lowering/builders.ex#L65)). `<s:scxml
   xmlns:s="http://www.w3.org/2005/07/scxml">` is spec-conformant and lowers to
   `xmlns: nil`. Lowering *computes* the resolved namespace URI
   (`Statifier.Lowering.Namespace.resolve/2`, called at [`lib/statifier/lowering.ex:72`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/lowering.ex#L72))
   and then discards it - it is never stored on `%Document{}`.

Beyond those, the spec says slightly more than the bead does in two places
(a `<history>`'s transition is required and must have a non-null target; an
`initial` attribute MUST NOT occur on an atomic state), and there is a cluster
of representable-but-invalid shapes with no check assigned to them at all -
the st-l5k.4 plan's two Residual Notes plus three more found here.

The v1 reference implements 5 of the 10 checks and gets one of them wrong: its
initial-target check tests **direct-child** membership, not descendancy
(`../statifier/lib/statifier/validator/initial_state_validator.ex:154-155`),
which is a narrower rule than spec 3.3 states. v1 has no `<final>`-children
check, no `donedata`-placement check, and no `xmlns`/`version` check at all -
it silently *rewrites the source* to insert both
(`../statifier/lib/statifier/parser/scxml.ex:76-103`), which is exactly the
behaviour st-700 rejected for v2. v1's errors are bare `String.t()` with no
codes and, outside the history validator, no source locations.

## Detailed Findings

### 1. The `%Statifier.Document{}` tree

Eight structs under `lib/statifier/document/` plus the root. All carry a
`location` (`@enforce_keys`'d); all attribute-bearing nodes carry
`attribute_locations`.

**Root** - [`lib/statifier/document.ex:98-121`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document.ex#L98-L121)

```
%Statifier.Document{
  location,                      # the <scxml> element span
  name, version, xmlns, datamodel :: String.t() | nil,
  binding :: :early | :late,     # default :early
  initial :: [String.t()],       # whitespace-split
  states :: [State.t()],
  attribute_locations :: %{optional(atom()) => Location.t()}
}
```

Keys lowering can put into the root's `attribute_locations`: `:initial`,
`:name`, `:datamodel`, `:binding`, `:version`, `:xmlns`
([`lib/statifier/lowering/builders.ex:49-56`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/lowering/builders.ex#L49-L56)). `<scxml>` is deliberately *not* a
`State` with `kind: :scxml`; the reasoning is in the moduledoc at
[`lib/statifier/document.ex:46-75`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document.ex#L46-L75) and is settled, not open.

**State** - [`lib/statifier/document/state.ex:84-113`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document/state.ex#L84-L113)

```
%Statifier.Document.State{
  kind :: :state | :parallel | :final | :history,   # equals the element name
  location, id :: String.t() | nil,
  initial :: [String.t()],
  initial_element :: Initial.t() | nil,
  states :: [State.t()],
  transitions :: [Transition.t()],
  onentry :: [Block.t()], onexit :: [Block.t()],
  history_type :: :shallow | :deep | nil,
  donedata :: Donedata.t() | nil,
  attribute_locations
}
```

One struct with a `kind` atom, not four per-kind structs. The decisive argument
for that shape was the validator itself: per-kind structs would make checks 4,
6 and 8 *unrepresentable*, relocating the rejection into lowering and deleting
checks whose acceptance criteria demand a code and a fixture apiece
([`docs/research/260807-st-l5k.2-typed-document-structs.md:67-77`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/docs/research/260807-st-l5k.2-typed-document-structs.md#L67-L77), `:872-905`).

`attribute_locations` keys lowering can put on a state: `:id`, `:initial`
([`lib/statifier/lowering/builders.ex:353-356`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/lowering/builders.ex#L353-L356)), plus `:type` for `:history`
(`:110-113`).

[`lib/statifier/document/state.ex:43-62`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document/state.ex#L43-L62) is a per-field table mapping each
representable misuse to the st-l5k.5 check that catches it. It is the closest
thing to a spec for this bead that exists in `lib/`, and it names two rows that
**no** check covers: `history_type` on a non-history kind (unbuildable from
lowering, so a hand-built-fixture-only shape), and `transitions` on a `:final`
(buildable from lowering - "Residual Note 1 for st-l5k.5 to pick up - either
check 6 widens its scope or a ninth check appears").

**Transition** - [`lib/statifier/document/transition.ex:43-62`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document/transition.ex#L43-L62)

```
%Transition{location, cond :: String.t() | nil, event :: [String.t()],
            target :: [String.t()], type :: :internal | :external,
            content :: [content_node()], attribute_locations}
```

`event` and `target` are already whitespace-split. An empty list means either
"absent" or `event=""`; the two are told apart only by `attribute_locations`
([`lib/statifier/lowering/attributes.ex:34-46`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/lowering/attributes.ex#L34-L46), Decision 6). Keys: `:event`,
`:target`, `:cond`, `:type`.

**Initial** - [`lib/statifier/document/initial.ex:34-40`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document/initial.ex#L34-L40).
`%Initial{location, transitions :: [Transition.t()]}`. No `id`, no
`attribute_locations` (the element has no attributes, spec 3.6). `transitions`
is a **list precisely so the zero and two-or-more cases survive lowering long
enough for check 4 to name them** (moduledoc `:16-25`;
[`lib/statifier/lowering/builders.ex:118-136`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/lowering/builders.ex#L118-L136)). This also avoids v1's synthetic
`__initial_N__` ids, which v1 then had to exclude by hand from its own
unique-id check.

**Donedata** - [`lib/statifier/document/donedata.ex:20-26`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document/donedata.ex#L20-L26).
`%Donedata{location, content :: Content.t() | nil}`. Its moduledoc states
outright that `donedata` on a non-`:final` kind "is a shape the validator
(st-l5k.5 check 8) exists to report, not one this layer refuses to build".
`<param>` is a Phase 3 element and is rejected by lowering as
`{:unsupported_element, "param"}`, so Phase 1 `<donedata>` has only the
`<content>` arm.

**Content** - [`lib/statifier/document/content.ex:32-40`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document/content.ex#L32-L40).
`%Content{location, expr, text, attribute_locations}`. Its moduledoc names
another unassigned check: "`expr` and `text` are both nilable and both
representable at the same time, even though spec 5.6 says a document MUST NOT
specify both. That mutual exclusion is a validator concern, not this layer's".

**Block** (`<onentry>`/`<onexit>`) - [`lib/statifier/document/block.ex:32-38`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document/block.ex#L32-L38).
**Raise**, **Log** - `lib/statifier/document/raise.ex`, `.../log.ex`.

**Nesting.** A plain tree, no parent pointers and no ids-to-nodes index. Every
state kind, including `:history`, lives in its parent's `states` list; the
root's `states` list accepts the same ([`lib/statifier/lowering/builders.ex:429-431`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/lowering/builders.ex#L429-L431)),
which is what makes check 5's "history at the root" case representable. There
is **no** `document_order` integer and no interning - both belong to the
compiler (st-wju.1). Descendancy (checks 3 and 5) therefore has to come from an
ancestry-threading walk or a validator-local parent map;
[`docs/research/260807-st-l5k.2-typed-document-structs.md:460`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/docs/research/260807-st-l5k.2-typed-document-structs.md#L460) already says "the
validator builds a throwaway id-to-path index and explicitly must not share it
with the compiler."

**Transitions do not all live in one place.** A generic transition walk must
visit `State.transitions` (ordinary, history-default) *and*
`State.initial_element.transitions`. Check 2 (target resolution) has to decide
whether it covers the latter two or leaves them to checks 4 and 5.

### 2. Source locations and `attribute_locations`

`Statifier.Parser.Location` ([`lib/statifier/parser/location.ex:13-37`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/parser/location.ex#L13-L37)) is a
span: 1-based `start_line`/`start_column`, 0-based `start_offset`, exclusive
`end_*`. This is the shape ADR-0014 fixed for expression spans so XML locations
and expression spans compose by plain arithmetic
(`value_location.start_offset + span.start`). `Location.slice/2` (`:69-72`)
slices raw source bytes back out - the primitive every location test in the
repo is built on.

**The `attribute_locations` contract** ([`lib/statifier/document.ex:22-44`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document.ex#L22-L44),
implemented at [`lib/statifier/lowering/attributes.ex:75-98`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/lowering/attributes.ex#L75-L98)):

- The map is keyed by an attribute-name atom from a fixed per-element set,
  valued by that attribute's **value span** - the text inside the quotes, not
  the whole `name="value"` run.
- **A key exists only for an attribute actually written in the source.** This
  is the "was it written" oracle, and it is the only one, because lowering
  applies defaults (`:external`, `:early`, `:shallow`) so a field's runtime
  value cannot answer the question.
- Inherited from the DOM: the stored *string* is entity-expanded while the
  *span* covers raw source, so an offset inside a value containing an entity
  does not map 1:1 ([`lib/statifier/document.ex:41-44`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document.ex#L41-L44)).

**A caveat the bead does not mention.** `put_location/4` also skips the key when
a written attribute's `value_location` is `nil` - the handler's short-scan
tolerance ([`lib/statifier/lowering/attributes.ex:92-93`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/lowering/attributes.ex#L92-L93), referencing
[`lib/statifier/parser/handler.ex:162-175`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/parser/handler.ex#L162-L175)). So `Map.has_key?/2` is precisely
"written **and** has a span", not "written". Any check that leans on it as a
written/absent oracle inherits that narrowing.

**What a validator error's location would be.** Three tiers, all already
available:

1. The offending attribute's value span - `node.attribute_locations[:target]`,
   `[:initial]`, `[:id]`, `[:xmlns]`, `[:version]`, `[:type]`.
2. The offending node's own element span - `state.location`,
   `transition.location`, `initial.location`, `donedata.location`.
3. The root's `<scxml>` start-tag span - `document.location` - the bead's named
   fallback for checks 9 and 10 when the attribute was not written.

`test/statifier/lowering/relaxed_input_test.exs` pins all three for the
boilerplate case and is the substrate checks 9 and 10 report from:

- `:140-154` - absent `xmlns`/`version` leave `%Document{xmlns: nil, version:
  nil}` with **no** `attribute_locations` keys, and `document.location` slices
  the `<scxml>` start tag.
- `:161-182` - written `xmlns`/`version` produce keys whose spans slice back to
  exactly `"http://www.w3.org/2005/07/scxml"` and `"1.0"`.
- `:54-86` - every span from a boilerplate-free parse slices out of the
  **original** binary; no `xmlns` insertion, no prepended XML declaration
  (contrast v1, below).
- `:117-133` - a `cond` span lands on the bare expression, not the quoted
  attribute.

### 3. The existing error struct and code conventions

`Statifier.Lowering.Error` (`lib/statifier/lowering/error.ex`) is
`%{reason, message, location}`, all three `@enforce_keys`'d. Never raised,
always collected. `reason` is a tagged tuple over a closed union
(`:14-27`): `{:unsupported_element, name}`, `{:misplaced_element, name,
parent}`, `{:stray_text, text}`, `{:unexpected_root, name}`,
`{:missing_attribute, element, attribute}`, `{:foreign_element, name, uri}`.
Messages are built by a named constructor per reason and read as prose with
`inspect/1`-quoted identifiers, e.g.:

- `"unsupported element \"send\""`
- `"element \"state\" is not allowed inside \"content\""`
- `"expected the document root to be <scxml>, got \"foo\""`
- `"element \"raise\" is missing required attribute \"event\""`

Conventions this establishes, which the validator's errors would be read
against:

- **A tagged-tuple `reason`, not a bare atom code.** The tuple carries the
  offending name(s) as data, so a test asserts
  `%Error{reason: {:unsupported_element, "send"}}` rather than parsing a
  message. The bead says "code"; `reason` is what the repo calls the same
  field.
- **`message` is asserted with `=~`, never for exact text**
  ([`test/statifier/lowering/error_test.exs:22-28`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/test/statifier/lowering/error_test.exs#L22-L28)), so message wording stays
  editable.
- **Errors are sorted by `location.start_offset` before returning**
  ([`lib/statifier/lowering.ex:140`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/lowering.ex#L140)), so a report reads in document order.
- **`{:ok, x} | {:error, [error]}`, with the partial result never returned**
  ([`lib/statifier/lowering.ex:20-24`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/lowering.ex#L20-L24), `:137-141`).

Three facts argue the validator introduces its own struct rather than reusing
this one. `Error`'s moduledoc calls its union "the finished set for the whole
bead" (`:11-17`); its reasons are all *lowering's* vocabulary (dispatch and
placement failures); and `lower/1` never hands back a document when its list is
non-empty, so the two error lists can never be observed together. The st-l5k.4
plan's Decision 2 nonetheless chose the list shape deliberately "so the two
layers can share the shape later". Whether that means one struct, two structs
with the same field names, or a shared behaviour is a plan-stage decision, not
one anything in `lib/` has made.

### 4. The v1 reference validator (`../statifier`, read-only)

`Statifier.Validator.validate/1` (`../statifier/lib/statifier/validator.ex:40`)
returns `{:ok, optimized_document, warnings}` or `{:error, errors, warnings}`,
both lists of bare `String.t()`. It threads a `%Validator{errors: [], warnings: []}`
accumulator through five sub-validators, then a `finalize/2` that runs two more
checks and (only when `errors == []`) compiles expressions, builds lookup maps
and a hierarchy cache, and sets `document.validated = true`. That `validated`
boolean is the "validate if not already validated" fallback ADR-0012-adjacent
principle 4 exists to make unrepresentable in v2
([`docs/research/260807-st-l5k.2-typed-document-structs.md:195-198`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/docs/research/260807-st-l5k.2-typed-document-structs.md#L195-L198)).

**Collection strategy**: collect-all, never fail-fast; later sub-validators run
even after earlier ones added errors. Errors and warnings are two independent
lists and the classification is a per-call-site choice
(`Utils.add_error/2` vs `Utils.add_warning/2`,
`../statifier/lib/statifier/validator/utils.ex:12-25`). Both are built by
prepending and **never reversed**, so v1's output is in reverse discovery
order - v2's offset sort is a straight improvement.

**Traversal**: no shared index. `Utils.collect_all_states/1` re-flattens the
whole tree, and `Utils.state_exists?/2` linear-scans it, once per target - each
of five sub-validators calling both independently.

### 5. What the W3C spec actually requires

From https://www.w3.org/TR/scxml/ (anchors `#scxml`, `#state`, `#initial`,
`#final`, `#donedata`, `#history`, `#IDs`).

- **3.2.1 `<scxml>`** - `xmlns`: Required = true, "The value MUST be
  'http://www.w3.org/2005/07/scxml'." `version`: Required = true, type decimal,
  "The value MUST be '1.0'."
- **3.3 `<state>` `initial`** - optional, type IDREFS. "MUST NOT be specified in
  conjunction with the `<initial>` element. **MUST NOT occur in atomic
  states.**" Value must be a legal state specification "consisting solely of
  descendants of the containing state". "A compound state MAY specify either an
  'initial' attribute or an `<initial>` element, but not both." Default when
  neither is present: "the state's first child state in document order".
- **3.6 `<initial>`** - must contain **exactly one** `<transition>`, which
  "MUST specify a non-null 'target' whose value is a valid state specification
  consisting solely of descendants of the containing state" and "MUST NOT
  contain 'cond' or 'event' attributes". It MAY contain executable content
  (which `Transition.content` already holds).
- **3.7 `<final>`** - legal children are `<onentry>` (0+), `<onexit>` (0+),
  `<donedata>` (optional). State-type children are not in the content model.
- **5.5 `<donedata>`** - specified in 5.5, not 3.7; 3.7 only lists it as a legal
  child of `<final>`, and 5.5 grants it no other parent. Its own content model
  says "either a single `<content>` element or one or more `<param>` elements
  ... but not both".
- **3.10 `<history>`** - a child of a compound `<state>` or of `<parallel>`.
  `type` is `"shallow"` or `"deep"`, default `"shallow"`. **Exactly one
  `<transition>` is required**, it "MUST specify a non-null 'target'" among
  descendants of the history node's parent, and "MUST NOT contain 'cond' or
  'event' attributes".
- **3.14 IDs** - "In a conformant SCXML document, the values of all attributes
  of type 'id' MUST be unique **within the session**." Typed as an XML Schema
  `ID`, not NMTOKEN. When an optional id is omitted, "the SCXML processor MUST
  generate a unique id automatically" for elements other than `<send>` and
  `<invoke>`.

**A caveat the research agent flagged and I am recording rather than resolving:**
across all six sections the spec phrases these as *document*-conformance
obligations on the author ("a conformant SCXML document MUST ..."), not as
processor obligations to reject. No normative "the processor MUST reject"
sentence was found for any of them. So all ten checks are this project's own
strictness policy - defensible under `docs/architecture.md` principle 4 ("make
invalid states unrepresentable"), but not spec-compelled. Section A.2
("Conforming SCXML Processors") was not fetched directly and is the place to
check if that distinction turns out to matter.

### 6. Test conventions a validator test file would follow

- **Module/file naming**: path-mirroring. `test/statifier/lowering/error_test.exs`
  -> `Statifier.Lowering.ErrorTest`. `use ExUnit.Case, async: true` - **not**
  `Statifier.Case`, which is reserved for the conformance corpus
  ([`test/support/case.ex:1-30`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/test/support/case.ex#L1-L30), and its `parse_document/1` still
  `flunk`s with "Statifier.parse/1 does not exist yet" at `:112`).
- **Local `parse!/1` / `lower!/1` helpers per file**, not a shared one
  ([`test/statifier/lowering/lowering_test.exs:10-18`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/test/statifier/lowering/lowering_test.exs#L10-L18),
  `.../relaxed_input_test.exs:12-20`, `.../location_test.exs:52-56`). There is
  no shared XML-to-`%Document{}` helper anywhere.
- **`describe` names are `"<function>/<arity> - <scenario>"`**; `test` names are
  full sentences.
- **Pattern-match asserts dominate**; `assert %Error{reason: {:tag, "name"}} = e`
  over a stack of equality asserts. Ordered multi-error lists are matched as
  list patterns, and ordering is asserted separately via
  `offsets == Enum.sort(offsets)` ([`test/statifier/lowering/lowering_test.exs:109-116`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/test/statifier/lowering/lowering_test.exs#L109-L116)).
- **XML style**: `~s(...)` for one-liners; triple-quoted heredocs with 4-space
  base indent for multi-line, either inline in the test or as a `@source`
  module attribute ([`test/statifier/lowering/location_test.exs:16-35`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/test/statifier/lowering/location_test.exs#L16-L35)).
- **Location assertions** come in three shapes: regex-anchored slice
  (`assert Location.slice(loc, src) =~ ~r/\A<#{Regex.escape(tag)}[\s\/>]/`),
  exact-equality slice for attribute values
  (`assert Location.slice(loc, src) == "late"`), and struct pattern match on
  `%Location{start_line: 3, start_column: 9}`. There is also a hardcode-free
  round-trip helper pattern at
  [`test/statifier/parser/location_accuracy_test.exs:60-69`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/test/statifier/parser/location_accuracy_test.exs#L60-L69).
- **`# sabotage:` convention** ([`docs/testing.md:78-134`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/docs/testing.md#L78-L134)): format
  `# sabotage: <what was broken> -> red`, one line (wrapped where long), above
  the `test` line and above any `@tag`. Every real example follows a three-part
  shape - name the function, name the mutation, name which assertion reddens.
  Verbatim:

  ```elixir
  # sabotage: `finalize/2` drops `Enum.sort_by(errors, ...)` and returns the
  # accumulated list unsorted -> the ordered names assertion below reddens
  ```

  ```elixir
  # sabotage: `unsupported/2` builds `{:unsupported_element, "?"}` instead
  # of tagging the reason with the given `name` -> the reason assertion
  # below reddens
  ```

  Harness plumbing states its exemption instead:
  `# sabotage: n/a - asserts the sample table matches the registry, no lib/ behavior`.
- **No fixture-file corpus for XML.** `test/fixtures/` holds only
  `adr_judge/*.diff` + `manifest.exs` for an unrelated harness. Every lowering
  and parser test embeds its XML inline. The bead's "red-test fixture" per check
  therefore means an inline heredoc, not a file on disk, unless this bead
  chooses to start a new pattern.
- **`layer_test.exs` precedent**: both `test/statifier/document/layer_test.exs`
  and `test/statifier/lowering/layer_test.exs` turn an acceptance criterion into
  a mechanical AST-walk guard over the layer's own sources. A "every check has a
  distinct code" or "every reason in the union has a constructor" guard would
  have precedent here.

## Conflicts between the stated checks and what the Document can express

Flagged explicitly, as the research brief requires. Ordered by how much they
change the shape of the work.

### C1. Check 5's "type is shallow or deep" cannot be evaluated (blocking)

`Attributes.atom/4` ([`lib/statifier/lowering/attributes.ex:67-73`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/lowering/attributes.ex#L67-L73)) returns the
default for any value not in the mapping, and `build_history/2` uses `:shallow`
as that default. So:

| source | `history_type` | `attribute_locations[:type]` |
|---|---|---|
| no `type` | `:shallow` | absent |
| `type="shallow"` | `:shallow` | present |
| `type="deep"` | `:deep` | present |
| `type="sideways"` | `:shallow` | present |

Rows 2 and 4 are indistinguishable. The validator receives a `%Document{}` and
nothing else - it has no source binary to `Location.slice/2` the offending text
back out of. The check is unimplementable as worded. Three ways out, all
plan-stage calls: (a) `validate/2` takes the source binary as a second argument
and slices the span (cheap, and it would also let *every* error message quote
the offending text); (b) lowering keeps the raw string alongside the atom (a
new field, and it reopens a settled layer); (c) the check is dropped or
narrowed to what is expressible. Note that (a) generalizes: the same collapse
affects `<transition type="...">` and `<scxml binding="...">`, which are the
st-l5k.4 Residual Note 2 cases.

### C2. Check 9's wording false-positives on a prefix-declared root

`Document.xmlns` is `Attributes.value(element, "xmlns")` - the literal attribute
named `xmlns`. A document rooted at `<s:scxml xmlns:s="http://www.w3.org/2005/07/scxml">`
satisfies spec 3.2.1 and lowers to `xmlns: nil` with no `:xmlns` key. Check 9
as written ("The root element declares `xmlns="http://www.w3.org/2005/07/scxml"`.
Report from `Document.xmlns`") would report it as an error.

Lowering knows the right answer: `Lowering.lower/1` builds a scope with
`Namespace.push/2` and computes `{uri, local_name}` with `Namespace.resolve/2`
([`lib/statifier/lowering.ex:71-72`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/lowering.ex#L71-L72)), then throws `uri` away. Storing the
resolved root namespace URI on `%Document{}` is a one-field change to lowering
that would make check 9 correct for both spellings. Recorded as a conflict, not
resolved.

### C3. `Map.has_key?` is "written and spanned", not "written"

Checks 4 and 5 need "carries no `event` and no `cond`". `cond` is safe: `nil`
when absent, `""` when written empty. `event` is not: `Attributes.list/2`
returns `[]` for both absent and `event=""`, so the only oracle is the
`attribute_locations` key - which is also absent when a written attribute has a
`nil` `value_location` ([`lib/statifier/lowering/attributes.ex:92-93`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/lowering/attributes.ex#L92-L93)). A
document that trips the handler's short-scan tolerance *and* writes `event=""`
on an `<initial>` transition would slip past. Narrow, but it is the difference
between the check being exact and being approximate, and it should be a stated
choice rather than an accident.

### C4. The spec requires more than checks 4 and 5 state

- **`<history>`'s transition is required and must have a non-null target**
  (3.10). The bead says "its default transition, **when present**". Check 4
  imposes the exactly-one-transition and non-null-target rules on `<initial>`
  but check 5 imposes neither on `<history>`. `Initial.transitions` and a
  history state's `transitions` have the *same* list shape
  ([`lib/statifier/document/initial.ex:20-25`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document/initial.ex#L20-L25) says so explicitly), so the same
  sub-check is reusable if the scope is widened.
- **`initial` MUST NOT occur on an atomic state** (3.3). Check 3 covers
  resolution and descendancy only; an `initial` on a childless `<state>` fails
  descendancy trivially, but an `initial` on a `<parallel>` or `<final>` (also
  illegal) may not. [`lib/statifier/document/state.ex:48`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document/state.ex#L48) lists this row as
  "caught by st-l5k.5 check 3 (target resolution and descendancy)", so the
  intent exists even if the wording does not reach it.
- **`<history>`'s parent must be compound or parallel** - check 5 says this, and
  the spec agrees, but "compound" has no predicate at this layer (ADR-0002 puts
  them on the Machine). The validator will have to define it locally as "has at
  least one `:state`/`:parallel`/`:final` child", which is a definition worth
  stating once rather than inlining.

### C5. Check 7's "enterable" is undefined at this layer

"the check that the first child exists and is enterable belongs here". `states`
holds all four kinds, so "first child" is unambiguous, but "enterable" is not: a
`:history` first child is not a legal default entry, and neither, arguably, is a
first child with no `id` that nothing can name. No Appendix D predicate is
available here by ADR-0002. This needs a definition written into the plan, not
inferred at implementation time.

### C6. Representable-but-invalid shapes with no check assigned

Each of these is buildable by lowering today and named by nothing in the bead's
list of ten:

1. **A `:final` with `transitions`** - st-l5k.4 Residual Note 1, restated at
   [`lib/statifier/document/state.ex:50`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document/state.ex#L50), `:58-62`: "either check 6 widens its
   scope or a ninth check appears".
2. **Duplicate attributes** on one element - st-l5k.4 Residual Note 1
   (plan `:959-963`); the DOM preserves them and lowering passes them through.
3. **Out-of-range enumerated values** for `transition type` and `scxml binding`
   - st-l5k.4 Residual Note 2, same root cause as C1.
4. **`<content>` with both `expr` and `text`** - spec 5.6 MUST NOT;
   [`lib/statifier/document/content.ex:22-26`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document/content.ex#L22-L26) explicitly leaves it to "a future
   check".
5. **`<donedata>` with both `<content>` and `<param>`** - spec 5.5 MUST NOT.
   Moot in Phase 1 (`<param>` is rejected by lowering as unsupported) but it
   becomes live in Phase 3.
6. **An explicitly empty `id=""`** - v1 errored on this
   ([`state_validator.ex:46-54`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/state_validator.ex#L46-L54)); [`lib/statifier/document/state.ex:51`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document/state.ex#L51) says a
   `nil` id is "not an error; the spec makes `id` optional", which is a
   different case.

### C7. Check 1's scope wording

Spec 3.14 says ids are unique "within the **session**"; the bead says "across
the document". These coincide for a single document and diverge once `<invoke>`
spawns child sessions (Phase 3+). Also: `nil` ids must be excluded from the
uniqueness set, and there are no synthetic `<initial>` ids to exclude - v2
avoided v1's problem structurally
([`lib/statifier/document/initial.ex:11-14`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/lib/statifier/document/initial.ex#L11-L14)).

## Open Questions

Recorded here rather than blocking. No human was available during this research;
each of these is a plan-stage decision.

1. **How does the validator recover an out-of-range enum's raw text (C1)?** The
   most likely answer is that `validate/2` takes the source binary alongside the
   document, which would also let every error message quote the offending text
   via `Location.slice/2`. That is a public-API shape decision for the whole
   validator, not a detail of check 5, so it should be settled first.
2. **Does check 9 test the literal `xmlns` attribute or the resolved namespace
   (C2)?** If the latter, lowering gains a field for the resolved root URI. If
   the former, a spec-conformant prefixed document is rejected, and that should
   be a stated, accepted cost the way st-700's was.
3. **Its own error struct, or `Statifier.Lowering.Error` extended?** The
   `reason` union calls itself finished; the st-l5k.4 plan says the list shape
   was chosen so "the two layers can share the shape later". Also: the bead says
   "code", the repo says `reason` - one name should win.
4. **Errors only, or errors and warnings?** v1 classified four rules as warnings
   (unreachable states, non-top-level document initial, unreachable history,
   uncompilable expressions). The bead's return type is
   `{:ok, document} | {:error, errors}` with no warning channel, but st-700
   assigns `:strict` (warnings-as-errors) to this bead
   ([`docs/plans/260808-st-700-relaxed-parsing-options.md:29`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/docs/plans/260808-st-700-relaxed-parsing-options.md#L29)), which presupposes
   warnings exist. Reachability analysis in particular is a v1 feature with no
   home in the ten checks.
5. **Does check 2 cover `<initial>` and `<history>` transitions, or do checks 4
   and 5 own their own target resolution?** Affects whether the transition walk
   descends into `State.initial_element`.
6. **What does "top-level-reachable" mean for the `<scxml>` `initial` (check
   3)?** v1 made "not a top-level state" a warning, not an error. The bead's
   phrasing is looser than v1's rule and stricter than nothing.
7. **Do any of C6's six unassigned shapes join this bead?** Residual Note 1
   (a `:final` with transitions) is the one `lib/` already anticipates by name;
   the rest are open. Widening the bead is a human's call, the same way st-700's
   own Open Question 1 was.
8. **Is there a "valid corpus-shaped document" to pass clean?** The acceptance
   criteria require one (compound + parallel + history + final/donedata), but no
   XML fixture-file pattern exists in `test/` - every test embeds its XML inline.
   Whether that document is an inline heredoc or the first entry in a new
   fixture directory is a convention decision.
9. **Is `Statifier.parse/1` this bead's job?** [`test/support/case.ex:112`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/test/support/case.ex#L112) still
   `flunk`s with "Statifier.parse/1 does not exist yet", and v1's
   `Statifier.parse/1` was parse+validate composed. Nothing in this bead's
   description mentions the public entry point, and the four-function coupling
   surface in [`docs/testing.md:19-21`](https://github.com/riddler/statifier-ex/blob/aad8c639414829f0ce11f2a5c5c21c68d0e54c4d/docs/testing.md#L19-L21) is waiting on it.

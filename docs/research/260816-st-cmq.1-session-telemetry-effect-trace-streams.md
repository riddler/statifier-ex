# Research: Session telemetry for the effect and trace streams (st-cmq.1)

**Date**: 2026-08-16T06:47:16-0600
**Git Commit**: 50e347f82da41d194392a0b3dd39b8290d95593c
**Branch**: st-cmq.1-session-telemetry
**Bead**: st-cmq.1

## Research Question

`Statifier.Session` must forward its effect and trace streams as `:telemetry`
events, per `docs/observability.md` constraint 6, with the pure core never
calling `:telemetry` (ADR-0003). This document maps the codebase as it exists
today: the session's effect-interpretation loop and every seam an event could
be emitted from, the full effect vocabulary and what each effect carries, the
step counters and constraint-3 identities available at emission time, what the
project's documents have already settled, what it takes to add `:telemetry` as
a dependency, and what the gate and the test conventions require.

This is a map, not a design. Nothing below proposes event names, shapes, or
changes.

## Summary

Nine facts do most of the work for whoever plans this bead.

1. **The bridge point already exists and is a single function.** Every effect
   the session interprets passes through `notify/2`
   ([`lib/statifier/session.ex:1250-1255`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session.ex#L1250-L1255)), which sends
   `{:statifier, session_id, {:effect, effect}}` to each subscriber. The
   session's plan/perform split guarantees a `{:notify, effect}` instruction
   is emitted first for every effect ([`lib/statifier/session/effects.ex:111-114`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session/effects.ex#L111-L114)),
   so the notify pass is ordered, total, and already carries the session id.
   Two more envelopes ride the same function: `{:halted, reason}` and
   `{:unroutable, effect}`.

2. **Nothing in the repo calls `:telemetry` today.** There is no dependency in
   `mix.exs` or `mix.lock`, nothing in `deps/`, no call site in `lib/`, and no
   test that attaches a handler. The only occurrences are prose: one moduledoc
   line ([`lib/statifier/machine.ex:101`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/machine.ex#L101)) and two lines in
   `docs/observability.md` (`:151`, `:196`).

3. **Every effect - core and trace alike - already carries the step counters.**
   All nine core effect structs and all nine trace effect structs carry
   `macrostep` and `microstep`; the nine trace structs plus
   `Effect.BudgetExhausted` also carry `round` (ADR-0020).

4. **Every effect already carries constraint-3 identities as bare integers.**
   State indexes, `t_index`, `c_index`, `owner` tuples, `invoke_id`,
   `invoke_index` - never a compiled struct. Source locations are *not* on the
   effects; they are reached by resolving the index through `Machine.at/2`,
   `Machine.transition/2`, or `Machine.content/2` and reading `.location`.

5. **The session holds the `Machine` at effect-dispatch time**, via
   `state.machine_state.machine`, so resolving a location at emission needs no
   new plumbing.

6. **The trace gate is a macro on `MachineState.trace`.** `Effect.trace/3`
   ([`lib/statifier/effect.ex:163-173`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/effect.ex#L163-L173)) is a `defmacro` that expands to a
   one-or-zero element list, evaluating its field list lazily. When `trace` is
   false the core produces no trace effect at all, so the session cannot emit a
   microstep-grained telemetry event under `trace: false` - the data does not
   exist. Macrostep-grained data does: `Effect.Done`,
   `Effect.BudgetExhausted`, and the counters on `machine_state` survive with
   trace off.

7. **The documents have already settled that telemetry is a bridge, not a
   replacement.** [`docs/observability.md:145-153`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/docs/observability.md#L145-L153) says the `:telemetry` bridge
   "attaches at that same boundary once it exists"; the st-cmq.4 plan and
   research both say in as many words that st-cmq.1 builds the bridge on the
   subscriber stream, that the stream's shape was cmq.4's commitment and the
   telemetry event names are not. No document anywhere proposes a name, a
   measurement, or a metadata key.

8. **`Mix.Statifier.AdrGuard` is the cheap enforcement mechanism the acceptance
   criterion asks for.** Its ADR-0003 check applies `@effect_call_pattern`
   ([`lib/mix/statifier/adr_guard.ex:97-102`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/mix/statifier/adr_guard.ex#L97-L102)) to added diff lines under
   `lib/statifier/`, exempting only `@effect_interpreter_paths`
   (`:78`, today `session.ex` and `supervisor.ex`). Adding `:telemetry\.` as
   one more alternation in that regex is a one-line change and reuses the
   existing gate stage (`.quality.exs:94-101`).

9. **Adding the dependency is mechanically unguarded, but amending the guard is
   ledger territory by policy.** `{:telemetry, "~> 1.x"}` matches none of
   `@mix_exs_pattern`'s alternatives ([`lib/mix/statifier/gate_guard.ex:40-43`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/mix/statifier/gate_guard.ex#L40-L43)),
   so `mix gate.check` stays green. `lib/mix/statifier/adr_guard.ex` is not a
   guarded path either - yet every previous amendment to it took a *voluntary*
   ledger entry ([`docs/quality-gate-changes.md:16-46`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/docs/quality-gate-changes.md#L16-L46), `:73-112`), and
   ADR-0027 states outright that riding a pattern gap instead of amending the
   guard "would be the hole the guard's own comment disclaims." Writing that
   entry is a human's call per ADR-0011.

## Detailed Findings

### The session's effect-interpretation loop

`Statifier.Session` is a `GenServer` with `restart: :temporary`
([`lib/statifier/session.ex:245`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session.ex#L245)). Its `%State{}` struct
([`lib/statifier/session.ex:264-297`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session.ex#L264-L297), `@enforce_keys [:machine_state,
:session_id, :inbox, :timers]`) holds `machine_state`, `session_id`,
`done_effect`, `inbox`, `timers`, `timer_refs`, `subscribers`, `halted`,
`recording`, `invocations`, `invoke_source`, `invoked_by`.

There is **no trace flag on the session**. Trace is `MachineState.trace`
([`lib/statifier/machine_state.ex:355`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/machine_state.ex#L355), `:369-374`, `:404`), set once from the
`:trace` option at `MachineState.new/2` ([`lib/statifier/machine_state.ex:454`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/machine_state.ex#L454)),
passed through by `init/1`'s `Keyword.take` ([`lib/statifier/session.ex:331`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session.ex#L331),
`:491`). The session can read `state.machine_state.trace` at any point.

Four callbacks drive the pure core, each returning
`{:ok, machine_state, effects}`:

- `init/1` -> `Interpreter.initialize/2` ([`lib/statifier/session.ex:492`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session.ex#L492))
- `drain_event/2` -> `Interpreter.handle_event/2` ([`lib/statifier/session.ex:776`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session.ex#L776))
- `drain_cancel/1` -> `Interpreter.cancel/1` ([`lib/statifier/session.ex:762`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session.ex#L762))
- `deliver_internal/6` -> `Interpreter.deliver_internal/5`
  ([`lib/statifier/session.ex:1216`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session.ex#L1216)), the ADR-0039 re-entry seam

A fifth path skips the core entirely: `handle_cast({:interpret, effects}, ...)`
([`lib/statifier/session.ex:673-676`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session.ex#L673-L676)) hands a caller-supplied effect list
straight to `perform/3` (ADR-0029).

`perform/3` ([`lib/statifier/session.ex:787-794`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session.ex#L787-L794)) is the whole loop:

```
effects |> Effects.plan(state.session_id) |> Enum.reduce(state, &perform_instruction/2)
```

`Statifier.Session.Effects.plan/2` ([`lib/statifier/session/effects.ex:111-114`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session/effects.ex#L111-L114))
is a pure `flat_map`; each effect yields `{:notify, effect}` **first**, then
zero or more actionable instructions (`{:enqueue_event, _}`, `{:deliver, ...}`,
`{:raise, ...}`, `{:schedule, ...}`, `{:cancel_timers, _}`, `{:start_child, ...}`,
`{:forward, ...}`, `{:stop_child, _}`, `{:halt, _}`). `perform_instruction/3`
([`lib/statifier/session.ex:796-931`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session.ex#L796-L931)) is a multi-clause pattern match on the
instruction head.

The macrostep boundary is **not** signalled to the session: `initialize/2` and
`handle_event/2` each run a whole macrostep internally and return once. What
the session sees afterwards are `state.machine_state.macrostep` /
`.microstep` / `.round` (read in `build_status/1`,
[`lib/statifier/session.ex:1279-1281`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session.ex#L1279-L1281)) and, under trace, the
`Trace.MacrostepStable` effect at the tail of the returned list.

### Subscriber notification, the existing observation channel

```elixir
defp notify(state, message) do
  payload = {:statifier, state.session_id, message}
  Enum.each(state.subscribers, fn {pid, _ref} -> send(pid, payload) end)
  :ok
end
```
([`lib/statifier/session.ex:1250-1255`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session.ex#L1250-L1255))

Call sites: `{:notify, {:done, %Done{}}}` (`:802`), the generic
`{:notify, effect}` (`:807`), `{:unroutable, effect}` (`:921`), and
`{:halt, reason}` -> `{:halted, reason}` (`:929`). Because the planner puts
`{:notify, effect}` at the head of each effect's instruction list, a
subscriber sees an effect *before* the session acts on it, and effects arrive
in the core's own list order.

### No timing instrumentation exists

`session.ex` contains no `System.monotonic_time/0` and no duration measurement
of any kind. The only wall-clock read in the whole library is
`MachineState.generate_session_id/0`'s `System.os_time(:millisecond)`
([`lib/statifier/machine_state.ex:481`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/machine_state.ex#L481)). `Statifier.Session.Recording`'s
moduledoc states explicitly that it calls no `Process.*` or `System.*` time
function and that ordering is ordinal, never wall-clock
([`lib/statifier/session/recording.ex:56-65`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session/recording.ex#L56-L65), ADR-0034). A span-style
`macrostep stop` event with a duration measurement would introduce the first
monotonic-clock read in the library.

### The effect vocabulary

`Statifier.Effect` (`lib/statifier/effect.ex`) is a type-union module plus one
macro. It provides:

- `@type core` (`:114-123`), `@type trace` (`:126-135`), `@type t` (`:138`)
- `trace?/1` (`:146-148`) - `{:trace, _} -> true`, else `false`. This is the
  single predicate that splits the stream.
- `trace/3` (`:163-173`) - a `defmacro`, `require`d as
  `require Statifier.Effect, as: Effect`. Expands to
  `if machine_state.trace, do: [{:trace, Mod.new(machine_state, fields)}], else: []`,
  binding `machine_state` once and splicing the field list only inside the
  `do` branch, so an untraced run allocates nothing and evaluates nothing.

Every trace payload module defines `new/2`, which pattern-matches
`%MachineState{macrostep:, microstep:, round:}` and stamps all three counters
via `struct!/2` - no call site can forget or duplicate them.

### Step counters and constraint-3 identities

`Statifier.MachineState` ([`lib/statifier/machine_state.ex:337-357`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/machine_state.ex#L337-L357)) carries

#### Sabotage convention

The comment block sits immediately above the `test "..."` line, names the exact
function or clause mutated in backticked Elixir, states the mutation as prose,
says which assertion reddens and why, and ends "Reverted and confirmed green."


## Architecture Documentation

The design this bead lands into is settled by three accepted ADRs and one
document that ADR-0012 makes binding.

ADR-0003 puts every side effect on one side of a line: the core returns effect
data, and `Statifier.Session` is the only production interpreter of it.
ADR-0012 makes `docs/observability.md` binding and states that "debuggers and
visualizers are effect interpreters, not core hooks" - which is exactly the
shape a telemetry bridge has. Constraint 6 then names the session as the
boundary and the pid-subscriber stream as the mechanism, with the telemetry
bridge attaching at the same point.

Two structural properties of the existing code make the bridge cheap. First,
`Effects.plan/2` guarantees a `{:notify, effect}` instruction per effect, in
core order, ahead of the session's own action - so a single fan-out point sees
everything. Second, every effect struct is already stamped with the counters
(ADR-0020) and carries constraint-3 identities as bare integers, so metadata
assembly is a field read, and location resolution is one `Machine.at/2` or
`Machine.content/2` call against a `Machine` the session already holds.

Two properties limit it. ADR-0029 records that core-derived and
`interpret/2`-injected effects are indistinguishable on the stream - which is
why the recorder could not be a subscriber, and a telemetry bridge attached the
same way inherits the same blindness unless it adds a discriminator itself.
ADR-0034 keeps `Statifier.Replay` a pure fold with no session, so replay
structurally cannot fire telemetry.

Finally, ADR-0011 and ADR-0027 together set the process cost: amending
`Mix.Statifier.AdrGuard` is a policy-level act that has taken a voluntary
ledger entry twice, and writing that entry is a human's call.

## Open Questions

No human was available during this research, so the questions below are
recorded rather than asked. Each is a decision the plan must make; none blocks
mapping the codebase.

1. **Duration for a span-style macrostep event.** The bead proposes a macrostep
   stop event with "duration from event acceptance to quiescence". The library
   reads no monotonic clock anywhere today, and
   [`lib/statifier/session/recording.ex:56-65`](https://github.com/riddler/statifier-ex/blob/50e347f82da41d194392a0b3dd39b8290d95593c/lib/statifier/session/recording.ex#L56-L65) documents its clock-freedom as
   deliberate (ADR-0034). Adding `System.monotonic_time/0` to the session would
   be the first such read. Whether that is in scope, and whether it needs its
   own note against ADR-0034's reasoning, is a plan decision.

2. **Where the macrostep boundary is observed.** The session has no
   per-macrostep hook: `Interpreter.initialize/2` and `handle_event/2` each run
   a whole macrostep and return once. A macrostep event can be emitted from
   the return of those calls (available with `trace: false`, using the counters
   on the returned `machine_state`) or from `Trace.MacrostepStable` (available
   only under `trace: true`). The bead's own trace-off policy recommendation
   implies the former, but the two do not fire on the same set of runs -
   `Trace.MacrostepStable` is suppressed when the round budget is exhausted, in
   favor of `Effect.BudgetExhausted`.

3. **The four non-`handle_event` core-driving paths.** `initialize/2`,
   `cancel/1`, `deliver_internal/5` (ADR-0039), and the `interpret/2` bypass
   all produce effect lists that reach `perform/3`. Whether each counts as its
   own "macrostep" for telemetry purposes, and whether `interpret/2`-injected
   effects should be distinguishable in metadata (ADR-0029 says the stream does
   not distinguish them), is unsettled.

4. **Location resolution cost and depth.** Resolving a location at emission is
   cheap per effect but is a per-event `Machine` tuple read. Which events carry
   locations (all of them, or only those with a `c_index` / `t_index` / state
   index), and whether a location is rendered as a struct or flattened into
   metadata keys, is undecided. `Machine.Transition` additionally has a
   `cond_location` distinct from `location`.

5. **Whether `{:halted, _}` and `{:unroutable, _}` get telemetry events.**
   Both ride `notify/2` alongside `{:effect, _}` but are lifecycle messages
   rather than effects. The bead names session lifecycle events but not the
   unroutable case.

6. **Whether the AdrGuard amendment happens on this branch.** Adding
   `:telemetry\.` to `@effect_call_pattern` is the cheap enforcement the
   acceptance criterion asks for, and `session.ex` is already exempt so no new
   exempt path is needed. The amendment does not mechanically fail
   `mix gate.check`, but ADR-0027's reasoning and the two prior voluntary
   entries in `docs/quality-gate-changes.md` point at recording it. Per
   ADR-0011 and the ledger's own preamble, writing that entry is a human's
   call - an agent may not write itself one.

7. **The `:telemetry` version constraint.** The dependency is new to the lock,
   and nothing in the repo constrains which major line to take. Elixir is
   1.18.3-otp-27, Erlang 27.3.

8. **Whether `docs/observability.md` constraint 6 gets rewritten here.**
   `docs/plans/260815-st-dtm-...:909-912` identifies "once it exists" as the
   last forward-looking phrase in that document. Discharging it is this bead's
   natural moment, but the bead's acceptance criteria say "module doc or
   docs/" without choosing.

9. **Doc-coverage cost.** `.doctor.exs` requires 100% on every axis, so any new
   module needs a `@moduledoc` and every public function a `@doc` and a
   `@spec`. If the bridge is a new module rather than private functions in
   `session.ex`, that is the bar it meets.

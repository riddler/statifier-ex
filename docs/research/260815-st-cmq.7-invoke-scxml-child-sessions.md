# Research: Invoke type=scxml child sessions (st-cmq.7)

**Date**: 2026-08-15T16:47:49-0600
**Git Commit**: c9d8783870d79065c892938a4b74952be79cb37f
**Branch**: st-cmq.7-invoke-scxml-child-sessions
**Bead**: st-cmq.7

## Research Question

st-cmq.7 is the session-side half of `<invoke type="scxml">`: starting child
`Statifier.Session` processes from `src` or inline `<content>`, seeding the
child datamodel from namelist/`<param>`, `_ioprocessors`/`#_parent` wiring,
`done.invoke.<invokeid>` delivery with donedata, autoforward delivery,
`<finalize>` sequencing, and the cancel-invoke effect (stopping the child and
discarding its already-queued events per spec 6.4).

What exists today for each of those, where the seams are, what the spec
requires verbatim, and what prior records have already settled or explicitly
deferred to this bead.

## Summary

The pure core is finished. st-cmq.6 landed lowering, validation, compilation,
the Appendix D `statesToInvoke` and cancel-invoke passes, and the
finalize/autoforward selection pass, and it emits `{:invoke, _}`,
`{:cancel_invoke, _}` and `{:autoforward, _}`. `<finalize>` already *executes*
inside the core. st-cmq.5 landed the send target vocabulary, the registry, and
`Statifier.Supervisor`. ADR-0027 decision 3 already specifies the protocol this
bead implements.

What is missing is exactly one layer: the parent session has no invocation
table, so all three invoke effects terminate at
`Statifier.Session.Effects.plan/2`'s `{:unroutable, effect}`
([`lib/statifier/session/effects.ex:98-108`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/session/effects.ex#L98-L108)), and `#_parent` / `#_<invokeid>`
resolve unconditionally to `error.communication`
([`lib/statifier/session.ex:703-709`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/session.ex#L703-L709)). No process is spawned, no
`done.invoke.<id>` string exists anywhere in `lib/`, and no mechanism discards
queued events by invokeid.

Three findings go beyond "wire up the missing layer", and each is load-bearing
for planning:

1. **Inline `<content><scxml>...</scxml></content>` does not compile today.**
   `Statifier.Lowering.Builders.build_content/2` reports every element child of
   `<content>` as `{:misplaced_element, name, "content"}`
   ([`lib/statifier/lowering/builders.ex:356-373`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/lowering/builders.ex#L356-L373)), and any lowering error is
   fatal ([`lib/statifier/lowering.ex:164-168`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/lowering.ex#L164-L168)). The decision is deliberate and
   documented ([`lib/statifier/document/content.ex:1-16`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/document/content.ex#L1-L16)) on the stated ground
   that "nothing in the conformance corpus needs it" - which the invoke corpus
   contradicts ([`test/scxml_tests/mandatory/invoke/test220_test.exs:26-31`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/test/scxml_tests/mandatory/invoke/test220_test.exs#L26-L31)).
   The bead's "inline `<content>`" acceptance criterion cannot be met without
   revisiting that.
2. **`src` has no fetcher and the corpus has no fixtures.** ADR-0031 routed the
   `src` dereference decision to this bead explicitly. The W3C invoke tests
   reference sub-documents by URI (`'file:test216sub1.scxml'`,
   [`test/scxml_tests/mandatory/invoke/test216_test.exs:29`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/test/scxml_tests/mandatory/invoke/test216_test.exs#L29)), and those
   sub-documents are deliberately filtered out of corpus emission
   (`tools/corpus/scxml_w3/sub_documents.exs`) and exist nowhere in the tree.
3. **The parent's inbox has no discard-by-key mechanism.** 6.4.3's "MUST NOT
   not insert them into the external event queue" needs one, and
   `Statifier.Session.Inbox` is FIFO-only (`lib/statifier/session/inbox.ex`);
   the only existing keyed discard is `Timers.take/2` by send id
   ([`lib/statifier/session/timers.ex:52-60`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/session/timers.ex#L52-L60)).

## Detailed Findings

### The pure core: what st-cmq.6 already produces

`%Statifier.Effect.Invoke{}` ([`lib/statifier/effect/invoke.ex:36-45`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/effect/invoke.ex#L36-L45)) carries
`invoke_id`, `type`, `src`, `params`, `content`, `autoforward`, `state_index`,
`macrostep`, `microstep`. Built in `invoke_one/6`
([`lib/statifier/interpreter.ex:1336-1348`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/interpreter.ex#L1336-L1348)).

- `src` is the **resolved URI string**, never dereferenced; `content` is an
  already-resolved value or text. The moduledoc explains why they stay two
  fields ([`lib/statifier/effect/invoke.ex:19-34`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/effect/invoke.ex#L19-L34)).
- `params` is `EventData.coerce({:params, _})` over `namelist ++ params`, with
  the first failure halting the whole fold, per 6.4's terminate-the-element
  MUST ([`lib/statifier/interpreter.ex:1375-1388`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/interpreter.ex#L1375-L1388)).
- ADR-0031's abort is the `with` chain in `invoke_one/6`; a failure raises
  `error.execution` with origin `{:invoke, state_index, invoke_index}` and
  yields no effect for that invocation, siblings unaffected
  ([`lib/statifier/interpreter.ex:1325-1359`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/interpreter.ex#L1325-L1359), `1494-1501`).

`%Effect.CancelInvoke{}` ([`lib/statifier/effect/cancel_invoke.ex:36-44`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/effect/cancel_invoke.ex#L36-L44)) is
emitted from one shared function,
`ExitEntry.cancel_invocations_for_state/2` ([`lib/statifier/interpreter/exit_entry.ex:279-291`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/interpreter/exit_entry.ex#L279-L291)),
called from both Appendix D sites: `depart/2`
([`lib/statifier/interpreter/exit_entry.ex:224-235`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/interpreter/exit_entry.ex#L224-L235)) and
`Statifier.Interpreter.exit_interpreter/1` ([`lib/statifier/interpreter.ex:1577`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/interpreter.ex#L1577)),
in each case after `<onexit>` and before removal from the configuration.

`%Effect.Autoforward{}` ([`lib/statifier/effect/autoforward.ex:41-42`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/effect/autoforward.ex#L41-L42)) carries
the external event **verbatim** rather than rebuilding it through
`Effect.Send`, because 6.4 requires an exact copy of every 5.10.1 field
([`lib/statifier/effect/autoforward.ex:11-22`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/effect/autoforward.ex#L11-L22)).

The invoke pass runs at [`lib/statifier/interpreter.ex:1193-1241`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/interpreter.ex#L1193-L1241), walking
`Machine.document_order(machine, machine_state.states_to_invoke)`, clearing
`states_to_invoke` last (`:1276`), and re-entering on a non-empty internal
queue with the budget threaded across the re-entry per ADR-0032
([`lib/statifier/interpreter.ex:1177-1241`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/interpreter.ex#L1177-L1241)).

The invoke id is minted inside the core, deterministically, per ADR-0008 as
amended: `state.id <> "." <> "inv_" <> counter`, or bare `inv_<counter>` for an
anonymous state, off `MachineState.invoke_counter`
([`lib/statifier/interpreter.ex:1435-1451`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/interpreter.ex#L1435-L1451), [`lib/statifier/machine_state.ex:339`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/machine_state.ex#L339)).
An author-written `id` is used verbatim and does not advance the counter.

`MachineState.active_invocations` is `%{{state_index, invoke_index} => invoke_id}`
([`lib/statifier/machine_state.ex:60-92`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/machine_state.ex#L60-L92)). Its own moduledoc states that
ADR-0027 decision 3's parent-held session table "is built on top of this one,
not in place of it" ([`lib/statifier/machine_state.ex:82-87`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/machine_state.ex#L82-L87)).

### `<finalize>` already runs in the core

This is the finding most likely to be mis-scoped. `apply_invoke_passes/2`
([`lib/statifier/interpreter.ex:527-579`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/interpreter.ex#L527-L579)) runs inside `handle_event/2` at
[`lib/statifier/interpreter.ex:447`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/interpreter.ex#L447), after `_event` is assigned and before
`Selection.select_transitions/2` - Appendix D's own position.

Per invocation ([`lib/statifier/interpreter.ex:620-638`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/interpreter.ex#L620-L638)), when
`invoke_id == event.invokeid` it runs `apply_finalize/5`, and *independently*
(sibling `if`, never nested) emits `{:autoforward, _}` when the invocation
autoforwards. `apply_finalize/5` ([`lib/statifier/interpreter.ex:693-715`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/interpreter.ex#L693-L715)) is a
three-way split matching 6.5: absent finalize is a no-op, an empty `<finalize>`
triggers the namelist/`<param location>` auto-assign
([`lib/statifier/interpreter.ex:732-750`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/interpreter.ex#L732-L750)), and a populated block re-enters the
ordinary block runner `Content.execute_block/3` under owner
`{:finalize, state_index, invoke_index}`.

**So st-cmq.7 does not implement finalize.** It has to deliver an event from a
child carrying the right `invokeid`, and `Statifier.Event` already has that
field (`lib/statifier/event.ex:49,63`), documented as being for exactly this
caller ([`lib/statifier/event.ex:72-74`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/event.ex#L72-L74)).

### The session runtime: what exists, and where it stops

`Statifier.Session` is a `GenServer` with `restart: :temporary`. Its state
struct ([`lib/statifier/session.ex:158-185`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/session.ex#L158-L185)) holds `machine_state`,
`session_id`, `done_effect`, `inbox`, `timers`, `timer_refs`, `subscribers`,
`halted`, `recording`. **There is no field mapping an invokeid to a child.**

`init/1` ([`lib/statifier/session.ex:354-381`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/session.ex#L354-L381)) runs `Interpreter.initialize/2`,
reads `session_id` back from `machine_state.datamodel["_sessionid"]` (`:363`),
and registers in `Statifier.Registry` (`:400-408`). The drain loop is
`handle_continue(:drain, state)` (`:417-434`), standing in for Appendix D's
blocking `externalQueue.dequeue()`.

`Session.Effects.plan/2` names every effect explicitly with no catch-all. The
three invoke effects all plan to `{:notify, effect}, {:unroutable, effect}`
([`lib/statifier/session/effects.ex:98-108`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/session/effects.ex#L98-L108)), which
`Session.perform_instruction/3` turns into a subscriber message and nothing
else ([`lib/statifier/session.ex:642-645`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/session.ex#L642-L645)).

`Session.Target.parse/1` ([`lib/statifier/session/target.ex:47-62`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/session/target.ex#L47-L62)) already
parses the full vocabulary: `nil -> :self`, `#_internal`/`_internal ->
:internal`, `#_parent -> :parent`, `#_scxml_<sid> -> {:session, sid}`, any
other `#_<x> -> {:invoke, x}`, anything else `{:invalid, _}`. Resolution is in
`Session.deliver/5` ([`lib/statifier/session.ex:670-709`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/session.ex#L670-L709)): `:parent` and
`{:invoke, _}` both fall to `communication_error/4` unconditionally, with the
comment "no invocation table yet" ([`lib/statifier/session.ex:663-669`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/session.ex#L663-L669)).
`communication_error/4` (`:750-765`) routes through
`Interpreter.deliver_internal/5`, the ADR-0037 seam.

`Session.Inbox` (`lib/statifier/session/inbox.ex`) is a `:queue` of
`{:event, Event.t()} | :cancel`, FIFO, with no removal by any key. The
`:cancel` marker is structural rather than a reserved event name
([`lib/statifier/session/inbox.ex:12-16`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/session/inbox.ex#L12-L16)), and `cancel/1` enqueues it rather
than racing ahead of the queue ([`lib/statifier/session.ex:477-480`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/session.ex#L477-L480)) - which is
already the shape a parent needs to stop a child.

`_ioprocessors` is seeded once by
`Statifier.Evaluator.SystemVariables.initial/2`
([`lib/statifier/evaluator/system_variables.ex:67-77`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/evaluator/system_variables.ex#L67-L77)) as
`%{"http://www.w3.org/TR/scxml/#SCXMLEventProcessor" => %{"location" => "#_scxml_" <> session_id}}`,
merged over the author's `:datamodel` option by `MachineState.new/2`
([`lib/statifier/machine_state.ex:436`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/machine_state.ex#L436)) so a system variable is never shadowed.

The runtime is `Statifier.Supervisor` holding `Statifier.Registry` and
`Statifier.SessionSupervisor` under `:rest_for_one`, placed by the embedder;
`Statifier.start_session/2` ([`lib/statifier.ex:176-196`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier.ex#L176-L196)) is the registered
start path. `Statifier.compile/1` ([`lib/statifier.ex:68-79`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier.ex#L68-L79)) is the runtime
XML-to-`Machine` pipeline, an ordinary pure function callable from inside a
session process.

### What the spec requires

6.4.2, on starting the invocation and the invokeid:

> the Processor MUST start a new logical instance of the external service
> specified in 'type' or 'typeexpr', passing it the URL specified by 'src' or
> the data specified by `<content>`, "namelist" or `<param>`.

> In addition to the explicit arguments, the Processor MUST keep track of the
> unique invokeid and ensure that it is included in all events that the invoked
> service returns to the invoking session.

6.4.2, on autoforward - note it is the point of *removal from the queue*, not
the point of receipt, and note the exact-copy requirement:

> When the 'autoforward' attribute is set to true, the SCXML Processor MUST
> send an exact copy of every external event it receives to the invoked
> process. All the fields specified in 5.10.1 The Internal Structure of Events
> MUST have the same values in the forwarded copy of the event. The SCXML
> Processor MUST forward the event at the point at which it removes it from the
> external event queue of the invoking session for processing.

6.4.2, on finalize timing and on cancellation:

> If there is a `<finalize>` handler in the instance of `<invoke>` that created
> the service that generated the event, the SCXML Processor MUST execute the
> code in that `<finalize>` handler right before it removes the event from the
> event queue for processing. It MUST NOT execute the `<finalize>` handler in
> any other instance of `<invoke>`.

> If the invoking session takes a transition out of the state containing the
> `<invoke>` before it receives the 'done.invoke.id' event, the SCXML Processor
> MUST automatically cancel the invoked component and stop its processing. The
> cancel operation MUST act as if it were the final `<onexit>` handler in the
> invoking state.

6.4.3 is the clause that governs an SCXML child specifically. Datamodel
seeding is **name-matched against the child's top-level `<data>` ids, and
non-matching values MUST NOT be added**:

> If the 'name' of a `<param>` element in the `<invoke>` matches the 'id' of a
> `<data>` element in the top-level data declarations of the invoked session,
> the SCXML Processor MUST use the value of the `<param>` element as the initial
> value of the corresponding `<data>` element.

> If the names do not match, the Processor MUST NOT add the value of the
> `<param>` element or namelist key/value pair to the invoked session's data
> model. However the Processor MAY make the values available by some other
> platform-specific means.

done.invoke on normal termination, and the cancellation rules:

> When the invoked state machine reaches a top-level final state, the Processor
> MUST place the event `done.invoke.id` on the external event queue of the
> invoking machine, where `id` is the invokeid for this invocation.

> when it is cancelled, the invoked session MUST exit at the end of the next
> microstep. The Processor MUST execute the `<onexit>` handlers for all active
> states in the invoked session, but it MUST NOT generate the `done.invoke.id`
> event. Once it cancels the invoked session, the Processor MUST ignore any
> events it receives from that session. In particular it MUST NOT not insert
> them into the external event queue of the invoking session.

(The doubled "MUST NOT not" is verbatim in the REC.)

And the transport is mandated:

> The SCXML Processor MUST support the use of SCXML Event/IO processor (C.1
> SCXML Event I/O Processor) to communicate between the invoking and the
> invoked sessions.

6.4.2 on the `type` value, which is a **different URI** from the send
processor's:

> Platforms MUST support `http://www.w3.org/TR/scxml/` as a value for the
> 'type' attribute.

C.1 defines the two targets this bead resolves:

> `#_parent`. If the target is the special term '#_parent', the Processor MUST
> add the event to the external event queue of the SCXML session that invoked
> the sending session, if there is one.

> `#_invokeid`. If the target is the special term '#_invokeid', where
> `invokeid` is the invokeid of an SCXML session that the sending session has
> created by `<invoke>`, the Processor MUST add the event to the external queue
> of that session.

5.10.1 on the field the parent must stamp on child-originated events:

> invokeid. If this event is generated from an invoked child process, the SCXML
> Processor MUST set this field to the invoke id of the invocation that
> triggered the child process. Otherwise it MUST leave it blank.

5.5, on donedata riding the done event:

> In cases where the SCXML Processor generates a 'done' event upon entry into
> the final state, it MUST evaluate the `<donedata>` elements `<param>` or
> `<content>` children and place the resulting data in the `_event.data` field.

**Appendix D defines no pseudocode for `invoke`, `cancelInvoke`,
`applyFinalize`, `returnDoneEvent` or `isCancelEvent`.** They exist only as
call sites; the REC declares each implementation platform-specific. The call
sites are `mainEventLoop` (`appendix-d.txt:138-158`), `exitInterpreter`
(`:175`), `exitStates` (`:260,273`) and `enterStates` (`:310`), all four of
which this core already ports. Two details in `mainEventLoop` are worth
carrying forward:

```
        for state in configuration:
            for inv in state.invoke:
                if inv.invokeid == externalEvent.invokeid:
                    applyFinalize(inv, externalEvent)
                if inv.autoforward:
                    send(inv.id, externalEvent)
```

The two `if`s are siblings, and the autoforward line is `send(inv.id, ...)` -
Appendix D routes autoforward through the same `#_<invokeid>` mechanism C.1
defines, which is the bead-boundary question below.

`exitInterpreter`'s prose is where `done.invoke` originates:

> The implementation of returnDoneEvent is platform-dependent, but if this
> session is the result of an `<invoke>` in another SCXML session,
> returnDoneEvent will cause the event done.invoke.`<id>` to be placed in the
> external event queue of that session, where `<id>` is the id generated in that
> session when the `<invoke>` was executed.

Note "external", contrasting with ADR-0037's internal-queue seam, which is for
routing failures only.

### The inline-`<content>` blocker

[`test/scxml_tests/mandatory/invoke/test220_test.exs:26-31`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/test/scxml_tests/mandatory/invoke/test220_test.exs#L26-L31) is the shape:

```xml
<invoke type="http://www.w3.org/TR/scxml/">
    <content>
        <scxml initial="subFinal" version="1.0" datamodel="predicator">
            <final id="subFinal" />
        </scxml>
    </content>
</invoke>
```

`build_content/2` ([`lib/statifier/lowering/builders.ex:356-373`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/lowering/builders.ex#L356-L373)) maps every
element child to `Error.misplaced(name, "content", location)`, and
`Statifier.Lowering.finalize/2` ([`lib/statifier/lowering.ex:164-168`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/lowering.ex#L164-L168)) turns any
error into `{:error, [...]}`, so `Statifier.compile/1` rejects the whole
document. `Statifier.Document.Content`'s moduledoc records the reasoning
([`lib/statifier/document/content.ex:1-16`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/document/content.ex#L1-L16)): preserving markup "would mean
holding a DOM subtree inside a Document struct, crossing the layer boundary
this rewrite is organized around, and nothing in the conformance corpus needs
it". That last clause was true when written and is not true for the invoke
corpus. 5.6 itself allows "text, XML from any namespace, or a mixture of both",
and 6.4.2 requires SCXML-typed services to "interpret values specified by the
`<content>` element or 'src' attribute as markup to be executed".

Twenty-five of the twenty-seven files under `test/scxml_tests/mandatory/invoke/`
contain a `<content>` element.

### Replay is a closed fold with no catch-all

`Statifier.Replay` (`lib/statifier/replay.ex`) folds recorded entries with no
catch-all clause, per ADR-0034. `Recording` entry shapes are
`{:event, _}`, `:cancel`, `{:timer, send_id, event}`, `{:interpret, effects}`,
`{:internal, kind, name, origin, opts}`
([`lib/statifier/session/recording.ex:77-84`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/session/recording.ex#L77-L84)). `perform_instruction/3` already
carries a deliberate no-op for `:internal`, `:parent` and `{:invoke, _}`
deliver routes ([`lib/statifier/replay.ex:360-365`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/replay.ex#L360-L365)). Any new instruction or
recording-entry variant st-cmq.7 adds needs its own `Replay` clause, and
nothing in the corpus or the gate would catch its absence.

## Architecture Documentation

- **ADR-0003** names `Statifier.Session` as the production effect interpreter
  owning "timers, invoke lifecycles, and parent/child session routing".
- **ADR-0027 decision 3** is the protocol: children on the flat
  `Statifier.SessionSupervisor`, a parent-held
  `invokeid -> {child_session_id, pid, monitor_ref}` table, monitors both ways
  (the child monitors its parent so a brutally killed parent still takes
  children down), cancellation sequenced by the parent's own code because 6.4
  places it in the parent's execution order, and queued-event discard by
  invokeid at the parent's inbox. Links and a supervisor-per-parent were
  considered and rejected in the record. Decision 4 makes sessions
  `restart: :temporary`, already in force.
- **ADR-0031** settles that an argument failure aborts one invocation, and
  routes the `src` dereference question to this bead: "whether anything
  downstream fetches the resolved URI, and under what security posture, is
  st-cmq.7's call."
- **ADR-0032** keeps the round budget spanning the invoke re-entry, so
  livelock-by-invoke is already handled inside the core.
- **ADR-0008 as amended (2026-08-15)** fixes the invoke id as a MachineState
  counter, not a UXID - the core/non-core split.
- **ADR-0029** keeps `Session.interpret/2` public and requires every session
  input to be a recordable, serialized entry.
- **ADR-0034** makes replay a catch-all-free fold, so new instructions owe new
  clauses.
- **ADR-0037** makes `Interpreter.deliver_internal/5` the sole door for writing
  to a session's own internal queue from outside the core - the right seam for
  an `error.communication` from a failed parent/child resolution, and the wrong
  one for `done.invoke`, which 6.4.3 puts on the **external** queue.
- **ADR-0011** governs the gate: if child-session code needs a third
  `@effect_interpreter_paths` entry beyond `session.ex` and `supervisor.ex`,
  that is a guarded change needing a `docs/quality-gate-changes.md` entry with a
  human `Approved-by:` line. ADR-0027 says a second new path "is a smell to be
  argued, not defaulted".

## Open Questions

No human was available while this was written; each of these is recorded rather
than resolved.

1. **How does an inline `<content>` child document become a Machine?**
   Lowering rejects element children of `<content>` today, on a recorded
   rationale whose stated premise (no corpus need) the invoke corpus falsifies.
   The options visible from here are: preserve a DOM subtree on
   `Document.Content`, keep the raw source span and re-parse at invoke time, or
   re-serialize the subtree to XML at lowering. Each crosses a layer boundary
   the rewrite was organized to keep, so it looks like ADR territory rather
   than a plan detail.
2. **Is `src` fetched, and under what posture?** ADR-0031 routed this here
   explicitly, and ADR-0024's precedent for `<data src>` is "never fetched, at
   any binding time", with resolution handed to the embedder. If `src` is not
   fetched by the library, the twenty-seven-file invoke corpus needs some other
   resolution seam; if it is, this is the first network/filesystem read in
   `lib/`.
3. **Where do the `<dep>` sub-documents come from?** They are filtered out of
   emission by design (st-rbp) and absent from the tree, so no `src`-based
   corpus test can resolve its child document however question 2 is answered.
4. **Does autoforward deliver through `{:invoke, invokeid}` or straight to the
   child?** Appendix D writes it as `send(inv.id, externalEvent)`, i.e. through
   the same route C.1 defines for `#_invokeid` - which st-cmq.5 filed as
   **st-xcgr**, blocked on this bead. If autoforward resolves the route itself,
   st-xcgr may be reduced to the `<send target="#_invokeid">` author-facing case
   only; if it reuses one resolver, the ordering between the two beads matters.
   Worth a fresh `bd show st-xcgr` before scoping.
5. **Which bead flips `invoke_elements` and `finalize_elements`?** st-cmq.6's
   plan says st-cmq.7 flips them and runs `mix test.baseline add`; st-cmq.5's
   plan assigns the harness-on-Session change to st-cmq.9. Since
   `Statifier.Case` never starts a Session, flipping the atoms here admits
   thirty-five files that would fail on assertions rather than on the feature
   gate, which st-cmq.6 itself called "a worse signal for the same red".
6. **Does child-session code fit inside `session.ex`?** `@effect_interpreter_paths`
   is exactly `["lib/statifier/session.ex", "lib/statifier/supervisor.ex"]`
   ([`lib/mix/statifier/adr_guard.ex:78`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/mix/statifier/adr_guard.ex#L78)). A third path is an ADR-0011 ledger
   entry with a human `Approved-by:`, which ADR-0027 pre-argued as a smell.
   Whether the invocation table, monitors, and child-start belong in
   `session.ex` or in a new module is a shape question with a gate cost.
7. **How does a cancelled invocation's queued event get discarded?**
   `Session.Inbox` is FIFO with no key-based removal. Options are a filter at
   drain time against a set of cancelled invokeids (ADR-0027 says "the parent
   drops, at drain time, every queued entry originating from a cancelled
   invokeid"), or a rebuild of the queue at cancel time. The set of cancelled
   invokeids also has no obvious retirement point.
8. **What does 6.4.3's name-matching seeding mean for `MachineState.new/2`?**
   The spec requires `<param>`/namelist values to seed only where the name
   matches a top-level `<data>` id, and MUST NOT add the rest. Today `:datamodel`
   is merged wholesale ([`lib/statifier/machine_state.ex:436`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/machine_state.ex#L436)). Filtering needs
   the child `Machine`'s top-level data ids, which are available only after the
   child document is compiled.
9. **Can a bare, unregistered parent session start children?** ADR-0027
   decision 2 registers only sessions started through the runtime, and decision
   10 exempts self-addressing from the registry. A `#_parent` send from a child
   to an unregistered parent has a pid but no registry entry; whether the
   parent/child protocol uses the table's pid directly or a registry lookup
   decides whether bare `Session.start_link/2` parents can invoke at all. ADR-0027
   also leaves "what error an `<invoke>` raises when the runtime supervisor is
   not running" explicitly to this bead.
10. **Does the invoke `type` URI get its own constant?** 6.4 mandates
    `http://www.w3.org/TR/scxml/` (with `"scxml"` a permitted short form), which
    is a different string from `Session.Target.supported_type?/1`'s
    `http://www.w3.org/TR/scxml/#SCXMLEventProcessor`
    ([`lib/statifier/session/target.ex:74-77`](https://github.com/riddler/statifier-ex/blob/c9d8783870d79065c892938a4b74952be79cb37f/lib/statifier/session/target.ex#L74-L77)). Nothing in `lib/` currently holds
    the invoke type URI, and an unsupported invoke `type` has no specified error
    path in the code today.
11. **What is recorded, and what does replay do with a child?** ADR-0034's fold
    has no catch-all, so child-start, autoforward delivery, `done.invoke`
    delivery and cancel each need a `Replay` clause. A child pid is not
    replayable, so the recording probably has to capture the child's
    contribution as delivered events rather than as a spawn - which is what the
    existing `{:internal, ...}` and no-op deliver clauses already model, but
    nothing in the corpus or gate would catch getting it wrong.
12. **Does `origintype` on a `#_parent` delivery follow decision 11?** st-cmq.5
    chose the processor URI over C.1's literal `"scxml"` on the strength of
    test352. Child-to-parent events go through the same delivery path, so the
    same choice applies by construction; test224 and test347 are where it gets
    judged.

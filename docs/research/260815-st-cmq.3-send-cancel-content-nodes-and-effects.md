# Research: `<send>` / `<cancel>` as pure-core content nodes producing the send effects

**Date**: 2026-08-15T11:16:27-0600
**Git Commit**: 02eb756ae022f1ccd30b385ec791a12c140ae18e
**Branch**: st-cmq.3-send-cancel-effects
**Bead**: st-cmq.3

## Research Question

What does the codebase look like today, in every layer `<send>` and `<cancel>`
must pass through, so that a plan for st-cmq.3 can be written without
re-discovering the pipeline: the `Machine.Content` contract, the end-to-end
path for an existing executable-content element, the Phase 3 evaluator and its
single payload-coercion function, how `<param>` / `<content>` are already
modeled and consumed, the existing `Effect.Send` / `Effect.SendDelayed` /
`Effect.Cancel` shapes, the `<assign>` datamodel write path, id generation, the
duration path available today, the governing spec clauses, and the governing
ADRs.

## Summary

Almost every seam this bead needs already exists and is documented as waiting
for `<send>`. The work is additive at nine named sites and edits nothing in the
parser, the block runner, or the protocol definition.

The consumer end is already built: `Statifier.Session.Effects.plan/1` already
has clauses for `{:send, _}`, `{:send_delayed, _}`, and `{:cancel, _}`
([`lib/statifier/session/effects.ex:50-69`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/session/effects.ex#L50-L69)), so the moment the core produces
them they route. The `Effect.Send` / `Effect.SendDelayed` / `Effect.Cancel`
structs are structurally complete and carry the spec's own attribute names.
`Statifier.EventData.coerce/1` is the single payload-coercion function and its
own moduledoc names `<send>` as an expected caller. `<invoke>` (st-cmq.6,
landed) implemented the near-identical attribute surface -
`type`/`typeexpr`, `src`/`srcexpr`, `id`/`idlocation`, `namelist`, `<param>`,
`<content>` - and is the file-for-file mirror to follow.

Three findings are decisions the plan must make rather than inherit:

1. **The bead's "`send_` UXID" is superseded.** ADR-0008 as amended
   2026-08-15 forbids a UXID for any id minted inside the pure core, and names
   `<send idlocation>` explicitly as governed by that rule. The format is left
   to whichever record implements it.
2. **ADR-0021's scope limit forces an explicit call** on what a failed
   `<content expr>` under `<send>` yields, and states the default expectation
   is the *opposite* of the `<donedata>` answer.
3. **ADR-0031 does not extend to `<send>`.** Whether a failed `<send>` argument
   aborts the send is st-cmq.3's own question, though spec 6.2 answers it
   plainly (quoted below).

The delay path is unblocked: st-59d has landed ([`mix.exs:41`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/mix.exs#L41) pins
`{:predicator, "~> 8.0"}`, [`mix.lock:21`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/mix.lock#L21) resolves 8.0.0), so
`Predicator.Duration.parse/1` + `to_milliseconds/1` are available and unused in
`lib/` today. st-rsl's leading-dot finding is confirmed empirically:
`parse(".5s")` is `:error`, `parse("1.5s")` is `{:ok, %{seconds: 1,
milliseconds: 500}}`.

The bead's JSON-`<content>` note is verified below, and the answer is split:
`EventData.coerce/1` preserves present-and-null, but `Statifier.Evaluator`'s own
`undefine_nils/1` re-collapses it on bind.

## Detailed Findings

### 1. The `Machine.Content` contract (st-wju.5)

`Statifier.ExecutableContent` is a `defprotocol`, not a behaviour
([`lib/statifier/executable_content.ex:1-83`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/executable_content.ex#L1-L83)). The contract:

- `execute(node, context) :: {:ok, Context.t(), [Effect.t()]} | {:error, term()}
  | {:error, Context.t(), term()}` ([`lib/statifier/executable_content.ex:69-73`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/executable_content.ex#L69-L73)).
- A leaf node returns the two-element error form; only a *composite* node (one
  that runs child content) returns the three-element form
  ([`lib/statifier/executable_content.ex:40-45`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/executable_content.ex#L40-L45)). `<send>` and `<cancel>` are
  leaves - `<param>`/`<content>` are not executable content - so both return
  the two-element form.
- "an implementation never constructs a `Statifier.Event` and never raises"
  ([`lib/statifier/executable_content.ex:34-39`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/executable_content.ex#L34-L39)).
- No `@fallback_to_any`, deliberately
  ([`lib/statifier/executable_content.ex:56-63`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/executable_content.ex#L56-L63)).

`Statifier.Machine.Content` ([`lib/statifier/machine/content.ex:1-69`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/machine/content.ex#L1-L69)) is a
namespace module owning only `owner/0` ([`lib/statifier/machine/content.ex:61-65`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/machine/content.ex#L61-L65))
and the `t()` union ([`lib/statifier/machine/content.ex:68`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/machine/content.ex#L68)). Its moduledoc says
outright that each future node - naming `<send>` and `<cancel>` - "gets its own
struct here too, and its own `Statifier.ExecutableContent` implementation, never
a clause added to this module" ([`lib/statifier/machine/content.ex:14-17`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/machine/content.ex#L14-L17)).

`owner/0` is the shape the bead asks the new effects to carry:

```
{:onentry, state_index, ordinal} | {:onexit, state_index, ordinal}
  | {:transition, t_index} | {:finalize, state_index, invoke_index}
```

Reference implementations, struct + `defimpl` in one file:
[`lib/statifier/machine/content/log.ex:49-68`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/machine/content/log.ex#L49-L68) (evaluate an expr, emit one
effect, touch nothing else), [`lib/statifier/machine/content/raise.ex:34-43`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/machine/content/raise.ex#L34-L43)

whole write to `Interpreter.Datamodel.write_location/4`).

**The block runner** is `Statifier.Interpreter.Content.execute_block/3`
([`lib/statifier/interpreter/content.ex:127-159`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/interpreter/content.ex#L127-L159)). It builds one
`ExecutableContent.Context` per block ([`lib/statifier/interpreter/content.ex:138-142`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/interpreter/content.ex#L138-L142)),

([`lib/statifier/interpreter/content.ex:199-209`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/interpreter/content.ex#L199-L209)). Nothing here changes for a new
element.

`ExecutableContent.Context` ([`lib/statifier/executable_content/context.ex:1-72`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/executable_content/context.ex#L1-L72))
carries `machine_state`, `owner`, `datamodel_context`, and `pending_errors`.
ADR-0028 governs: one context per block, threaded, `Predicator.Context.bind/3`
for a write rather than a rebuild.

`<invoke>`'s id generation is at [`lib/statifier/interpreter.ex:1384-1405`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/interpreter.ex#L1384-L1405). It

> with `UXID.generate!`: UXID reads the wall clock and a CSPRNG, which would
> make this function `(state, event, clock, entropy) -> ...` instead of
> ADR-0003's `(state, event) -> {state, [effect]}`, observably so because
> `<invoke idlocation>` writes the generated id into the datamodel. A pure

### 7. Delay / delayexpr: what is available today

[`mix.exs:41`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/mix.exs#L41) pins `{:predicator, "~> 8.0"}` and [`mix.lock:21`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/mix.lock#L21) resolves 8.0.0,
so **st-59d has landed on this branch's base** and st-rsl's full scope is
implementable in one pass.

`Predicator.Duration` exists at `deps/predicator/lib/predicator/duration.ex`:
`parse/1` at `:462` (`@spec parse(binary()) :: {:ok, Types.duration()} |
:error`, whole-string, no partial consumption) and `to_milliseconds/1` at
`:154` (`@spec to_milliseconds(Types.duration()) :: integer()`). **Nothing in
`lib/` calls either today.**

Verified empirically in this worktree (`mix run`, scratch script, not committed):

```
Predicator.Duration.parse("2s")   -> {:ok, %{seconds: 2, ...}}
Predicator.Duration.parse("1.5s") -> {:ok, %{seconds: 1, milliseconds: 500, ...}}
Predicator.Duration.parse(".5s")  -> :error
```

This confirms st-rsl's leading-dot finding exactly: the SCXML schema pattern
`\d*(\.\d+)?(ms|s|m|h|d)` admits `.5s` and predicator 8.0 rejects it, so a
one-line `.` -> `0.` pre-normalization on both the static `delay` and a string
`delayexpr` result is owed here.

st-rsl folds into this bead: it is `[open]` and its own description says "if
st-cmq.3 is implemented after this is read, fold it in there and close this
bead against it."

### 8. Spec clauses, quoted from the local cache

Read from `$(git rev-parse --path-format=absolute --git-common-dir)/spec-cache/scxml-rec.html`.

**6.2.2, `idlocation`:**

> If 'idlocation' is present, the SCXML Processor MUST generate an id when
> the parent `<send>` element is evaluated and store it in this location.

**6.2.2, delay and evaluation timing (the whole MUST that shapes `execute/2`):**

> If a delay is specified via 'delay' or 'delayexpr', the SCXML Processor MUST
> interpret the character string as a time interval. It MUST dispatch the
> message only when the delay interval elapses. (Note that the evaluation of
> the send tag will return immediately.) The Processor MUST evaluate all
> arguments to `<send>` when the `<send>` element is evaluated, and not when
> the message is actually dispatched. If the evaluation of `<send>`'s
> arguments produces an error, the Processor MUST discard the message without
> attempting to deliver it. If the SCXML session terminates before the delay
> interval has elapsed, the SCXML Processor MUST discard the message without
> attempting to deliver it.

That third sentence is the direct answer to the ADR-0031-shaped question: an
argument-evaluation failure means **no effect is produced at all** for that
`<send>`. (The session already discards on termination -
`docs/plans/260814-st-cmq.4-...` and `lib/statifier/session.ex`.)

**6.2.2, mutual exclusions and children** (the validator check's contents):
`event` "Must not occur with 'eventexpr'"; `target` / `targetexpr`; `type` /
`typeexpr`; `id` "Must not occur with 'idlocation'"; `delay` "Must not occur
with 'delayexpr' or when the attribute 'target' has the value `_internal`";
`namelist` "Must not be specified in conjunction with `<content>` element". And:

> A conformant SCXML document MUST specify exactly one of 'event', 'eventexpr'
> and `<content>`. A conformant document MUST NOT specify "namelist" or
> `<param>` with `<content>`.
> The SCXML Processor MUST include all attributes and values provided by
> `<param>` or 'namelist' even if duplicates occur.

**6.2.4, target - the error.execution / error.communication split:**

> If the value of the 'target' or 'targetexpr' attribute is not supported or
> invalid, the Processor MUST place the error error.execution on the internal
> event queue. If it is unable to dispatch the message, the Processor MUST
> place the error error.communication on the internal event queue.

**6.2.5, type:**

> If neither the 'type' nor the 'typeexpr' is defined, the SCXML Processor
> MUST assume the default value of
> http://www.w3.org/TR/scxml/#SCXMLEventProcessor. If the SCXML Processor does
> not support the type that is specified, it MUST place the event
> error.execution on the internal event queue.

**3.12.2, the general split** (this is the line that puts unreachable targets
outside this bead):

> 'error.communication' and 'error.execution'. The former cover errors
> occurring while trying to communicate with external entities, such as those
> arising from `<send>` and `<invoke>`, while the latter category consists of
> errors internal to the execution of the document, such as those arising from
> expression evaluation.

**3.14 IDs, on when a `<send>` id is generated:**

> The ids for `<send>` and `<invoke>` are subtly different. In a conformant
> SCXML document, they MUST be unique within the session, but in the case
> where the author does not provide them, the processor MUST generate a new
> unique ID not at load time but each time the element is executed.
> Furthermore the attribute 'idlocation' can be used to capture this
> automatically generated id.

and, on format freedom:

> Finally note that the automatically generated id for `<invoke>` has a
> special format. ... The SCXML processor MAY generate all other ids in any
> format, as long as they are unique.

**6.3, `<cancel>`:**

> The `<cancel>` element is used to cancel a delayed `<send>` event. The SCXML
> Processor MUST NOT allow `<cancel>` to affect events that were not raised in
> the same session. The Processor SHOULD make its best attempt to cancel all
> delayed events with the specified id.

> A conformant SCXML document MUST specify exactly one of sendid or
> sendidexpr.

**5.6.2, `<content expr>` failure** (the clause ADR-0021's scope limit points at):

> If the evaluation of 'expr' produces an error, the Processor MUST place
> error.execution in the internal event queue and use the empty string as the
> value of the `<content>` element.

**5.7, `<param>` failure:**

> If the 'location' attribute does not refer to a valid location in the data
> model, or if the evaluation of the 'expr' produces an error, the SCXML
> Processor MUST place the error 'error.execution' on the internal event queue
> and MUST ignore the name and value.

Note the tension between 5.7's "MUST ignore the name and value" (per-param,
what `<donedata>` implements) and 6.2's "MUST discard the message" (whole
element). `<invoke>` resolved the same tension in favor of the element-level
MUST ([`lib/statifier/interpreter.ex:1323-1328`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/interpreter.ex#L1323-L1328), ADR-0031); 6.2's text is the
same shape.

**5.9.2, location expressions:**

> If a location expression cannot be evaluated to yield a valid location, the
> SCXML processor MUST place the error 'error.execution' in the internal event
> queue.

**B.2.1, the JSON clause behind the bead note:**

> Otherwise if the content (whether fetched or provided in-line) is JSON (and
> the Processor supports JSON), the SCXML Processor MUST create the
> corresponding ECMAScript object.

### 10. The JSON `<content>` present-and-null note - verified

The bead's inherited note from st-7ft asks whether a JSON event payload
preserves a present-and-null field distinctly from an absent one. Verified in
this worktree with `mix run` (scratch script, not committed):

```
Statifier.EventData.coerce({:text, ~s({"foo": null, "bar": 1})})
  -> %{"bar" => 1, "foo" => nil}
```

So **the coercion boundary preserves it**: px-o9v's upstream removal of the
recursive `nil` collapse holds, and predicator's literal parser reads `null` as
`nil` inside a map literal. There is no JSON parser involved -
`EventData`'s moduledoc records that the predicator literal-parse rung
substitutes for B.2.1's JSON rung
([`lib/statifier/event_data.ex:22-27`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/event_data.ex#L22-L27), `:57-64`).

But the collapse is reintroduced one layer later, by this repo's own code.
`Statifier.Evaluator.undefine_nils/1`
([`lib/statifier/evaluator.ex:220-228`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/evaluator.ex#L220-L228)) recursively rewrites `nil` to
`:undefined` and is applied by `bind/3` ([`lib/statifier/evaluator.ex:254-258`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/evaluator.ex#L254-L258))
on every root bound into a `Predicator.Context`, `_event` included. Verified:

```
Statifier.Evaluator.bind(ctx, "_event", %{"data" => %{"foo" => nil, "bar" => 1}})
  -> %{"_event" => %{"data" => %{"bar" => 1, "foo" => :undefined}}}
```

So a `<send>` whose `<content>` is `{"foo": null}` produces an
`Effect.Send.data` that correctly holds `%{"foo" => nil}`, and the receiving
session's expression evaluation of `_event.data.foo` sees `:undefined` -
indistinguishable from absent. Whether that is a defect or the intended
"declared but no value yet" convention (the reason `undefine_nils/1` exists -
[`lib/statifier/evaluator.ex:200-219`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/evaluator.ex#L200-L219), `:230-252`) is not settled anywhere in
`docs/`. Recorded as an open question below rather than judged here.

- **Delivery.** `Statifier.Session` owns routing, timers, and the external

  communication failure in the session's half; 6.2.4's `error.execution` arm
  (unsupported or invalid target/type) is the only error-tier detection that
  belongs here, and only to the extent the spec puts it at execute time.
- **Flipping corpus feature atoms.** The Phase 4 corpus bead.
- **`<invoke>`.** Landed under st-cmq.6; `{:invoke, _}` already plans as
  `{:unroutable, _}` and this bead does not touch that row.
- **External send targets and child sessions.** st-cmq.5 / st-cmq.7.

## Architecture Documentation

- **ADR-0003** - pure core, effects describe rather than perform. The reason a
  `send_` id cannot be a UXID.
- **ADR-0004** - predicator as the datamodel; the value space `EventData`
  substitutes for JSON.
- **ADR-0008 as amended 2026-08-15** - core/non-core id split; supersedes the
  bead's "`send_` UXID".
- **ADR-0012** - observability; `c_index` is constraint 3, the step counters are
  constraint 4, and `owner` is the correlation seam constraint 3 alone does not
  provide.
- **ADR-0021** - `<donedata>` content failure, with an explicit scope limit
  excluding `<send>`.
- **ADR-0028** - one threaded context per executable-content block.
- **ADR-0031** - invoke argument failure aborts the element.
- **ADR-0033** - the validator warning tier, scoped at `<send>`-in-`<finalize>`.

Two house patterns this bead should follow rather than re-argue: mutually
exclusive attributes are lowered *without* enforcement so the validator can
report the pair ([`lib/statifier/document/invoke.ex:6-19`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/document/invoke.ex#L6-L19),
[`lib/statifier/document/content.ex:23-29`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/document/content.ex#L23-L29)); and every new element adds a struct
plus a `defimpl` and never a clause in a central dispatcher
([`lib/statifier/executable_content.ex:1-13`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/executable_content.ex#L1-L13)).

## Historical Context

- st-wju.2 defined the effect vocabulary and left `{:send, _}`,
  `{:send_delayed, _}`, `{:cancel, _}`, `{:invoke, _}` producer-less on purpose,
  with the instruction "extend rather than rename".
- st-wju.5 built the protocol and block runner, and named `<send>` as a Phase 3
  node that would implement it "without touching the interpreter".
- st-af3.7 built `Statifier.EventData` and named `<send>` as a future caller.
- st-cmq.4 built `Statifier.Session` and its effect planner, already handling
  all three send/cancel tags, testable through `Session.interpret/2` (ADR-0029)
  because no document could produce them yet.
- st-cmq.6 landed `<invoke>` and, post-loop, triggered ADR-0008's amendment
  after direction review found that a UXID invoke id "breaks ADR-0003's
  `(state, event) -> {state, [effect]}` contract observably, since `<invoke
  idlocation>` writes the id into the datamodel and replay then diverges."
- st-jzc landed the warning tier (ADR-0033) and left the `<send>`-in-`<finalize>`
  clause explicitly for this bead.
- st-59d landed the predicator 8.0 pin, unblocking st-rsl.

## Open Questions

1. **The `send_` id format.** The bead says "a `send_` UXID generated at
   execute time"; ADR-0008 as amended forbids a UXID for any id minted inside
   the pure core and names `<send idlocation>` as governed by that rule, while
   leaving the format "to the record that implements it". So the plan must
   choose: reuse `machine_state.invoke_counter`, or add a sibling
   `send_counter` field to `%MachineState{}`. Spec 3.14 requires only
   session-uniqueness and imposes no shape (unlike 6.4.1's `stateid.platformid`
   for `<invoke>`). This looks like it needs its own short ADR, the way the
   invoke format did. A secondary reading exists and should be closed
   explicitly: if the id were minted by the *session* rather than the core, the
   UXID bucket would reopen - but the effect must carry a resolved `send_id`
   (the planner "evaluates nothing"), and `idlocation` must write it into the
   datamodel from inside `execute/2`, so core-minting is forced.

2. **What a failed `<content expr>` under `<send>` yields.** ADR-0021's scope
   limit demands an explicit decision, and states the default expectation is
   5.6's literal empty string - the opposite of the `<donedata>` answer.
   Deciding "no data" instead is an amendment to ADR-0021, not a silent
   extension.

3. **Per-param versus per-element failure.** 5.7 says a bad `<param>` means
   "MUST ignore the name and value" (per-param, what `<donedata>` does at
   [`lib/statifier/interpreter/exit_entry.ex:1074`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/interpreter/exit_entry.ex#L1074)); 6.2 says an argument error
   means "discard the message" (per-element, what `<invoke>` does under
   ADR-0031). 6.2's text is element-level and appears controlling, but ADR-0031
   does not extend to `<send>`, so this needs stating rather than inheriting.

4. **`_event.data` present-and-null collapses at bind time.** Verified above:
   `EventData.coerce/1` preserves `nil`, but `Evaluator.undefine_nils/1`
   rewrites it to `:undefined` when `_event` is bound, so `_event.data.foo`
   cannot tell present-and-null from absent at expression-evaluation time. This
   is the substrate concern st-7ft handed forward, and the answer is "half
   correct". No corpus file is known to depend on the distinction, so it may be
   out of scope for this bead - but it should be recorded (a follow-up bead, or
   a note on the plan) rather than quietly assumed fixed by px-o9v.

5. **`<cancel>` with no `sendid` match.** 6.3 says the Processor "SHOULD make
   its best attempt" and cannot guarantee success. The session already treats a
   `send_id` that never existed as a no-op
   ([`lib/statifier/session.ex:550`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/session.ex#L550)). Presumed nothing to do in the core, but
   worth one line in the plan.

6. **`delay` with `target="_internal"`.** 6.2.2 says `delay` "Must not occur
   ... when the attribute 'target' has the value `_internal`". Whether that is
   a validator error, an ADR-0033 warning, or unenforced is undecided; note
   that `_internal` currently plans as `{:unroutable, _}` anyway
   ([`lib/statifier/session/effects.ex:14-19`](https://github.com/riddler/statifier-ex/blob/02eb756ae022f1ccd30b385ec791a12c140ae18e/lib/statifier/session/effects.ex#L14-L19)).

7. **Does `<cancel>` need its own validator check module,** or does it fold
   into `Checks.Send`? 6.3.1 has exactly one constraint ("MUST specify exactly
   one of sendid or sendidexpr"). The house pattern is one file per element
   (`Checks.Invoke`, `Checks.Assign`), which argues for a separate file, but
   this is a plan-level judgment call.

8. **Whether `Effect.Send`/`SendDelayed`/`Cancel` gaining `owner` needs any
   downstream change** in `lib/statifier/session/recording.ex` or
   `lib/statifier/replay.ex`. The field is additive and nilable, so probably
   not, but the replay recorder's send/cancel handling was noted as
   hand-waved in `docs/research/260815-st-dtm-replay-recorder-session-boundary.md`
   and should be checked.
